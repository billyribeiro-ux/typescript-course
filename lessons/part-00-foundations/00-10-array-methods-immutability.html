Iteration, Array Methods & Immutability

🎯 Core · high-value ⏱️ ~32 min ⭐ Used in every React app

If there is one lesson in Part 0 to truly absorb, it's this one. The array methods map, filter, and reduce are how professionals transform data — and map is literally how React renders lists. We pair them with the principle of immutability: never change data in place, always produce new data.

1. map — transform every item

.map() takes a function and returns a new array where each item has been transformed by that function. Same length, new values.

map.jsjavascript 
const prices = [10, 20, 30];

const withTax = prices.map((p) => p * 1.2);
console.log(withTax);  // [12, 24, 36]
console.log(prices);   // [10, 20, 30] — original untouched!

// map over objects — the React list pattern:
const users = [
  { id: 1, name: "Ada" },
  { id: 2, name: "Lin" },
];
const names = users.map((user) => user.name);
console.log(names);    // ["Ada", "Lin"]

// In React you'll write almost exactly this:
// users.map((user) => <li key={user.id}>{user.name}</li>)
Why map is special: it returns a brand-new array and leaves the original alone. When you render a list in React, you map your data array into an array of UI elements. Learn map deeply and React lists become trivial.

2. filter — keep only some items

filter.jsjavascript 
const todos = [
  { title: "Email", done: true },
  { title: "Code", done: false },
  { title: "Sleep", done: false },
];

// Keep items where the function returns true:
const remaining = todos.filter((t) => !t.done);
console.log(remaining.length);   // 2

const numbers = [1, 2, 3, 4, 5, 6];
const evens = numbers.filter((n) => n % 2 === 0);
console.log(evens);   // [2, 4, 6]
map vs filter: map transforms and keeps every item (same length out). filter keeps a subset (same or shorter). They return new arrays — perfect for deriving displayed data from your source of truth.

3. reduce — boil a list down to one value

.reduce() is the most powerful (and most feared) method. It walks the array carrying an accumulator, combining items into a single result — a sum, a max, an object, anything.

reduce.jsjavascript 
const cart = [
  { item: "Book", price: 12 },
  { item: "Pen", price: 3 },
  { item: "Bag", price: 25 },
];

// Sum all prices. Start the accumulator (total) at 0.
const total = cart.reduce((runningTotal, product) => {
  return runningTotal + product.price;
}, 0);
console.log(total);   // 40

// reduce can build any shape — e.g. count by category:
const letters = ["a", "b", "a", "c", "b", "a"];
const counts = letters.reduce((acc, letter) => {
  acc[letter] = (acc[letter] ?? 0) + 1;
  return acc;
}, {});
console.log(counts);  // { a: 3, b: 2, c: 1 }
How to read reduce: the first argument is the accumulator (the result-so-far), the second is the current item, and the 0 (or {}) at the end is the starting value. Each step returns the new accumulator. Don't fear it — practice it.

4. Chaining & more methods

chaining.jsjavascript 
const products = [
  { name: "Laptop", price: 1200, inStock: true },
  { name: "Mouse", price: 25, inStock: true },
  { name: "Monitor", price: 300, inStock: false },
];

// Chain: keep in-stock, get their names, in one readable pipeline.
const availableNames = products
  .filter((p) => p.inStock)
  .map((p) => p.name);
console.log(availableNames);   // ["Laptop", "Mouse"]

// Other essentials:
console.log(products.find((p) => p.price < 100));  // first match (the mouse)
console.log(products.some((p) => p.price > 1000));  // true
console.log(products.every((p) => p.price > 0));    // true
console.log(products.map(p => p.name).join(", "));  // "Laptop, Mouse, Monitor"
Pipelines: because map/filter return arrays, you can chain them into readable data pipelines. find grabs the first match, some/every ask yes-no questions, join turns an array into a string.

5. Immutability: the golden rule

Immutability means treating data as read-only: to "change" something, you create a new version instead of editing the original. This avoids a huge category of bugs and is required for React to detect changes and re-render. map/filter/reduce and spread are your immutable toolkit.

immutable.jsjavascript 
const todos = [
  { id: 1, title: "A", done: false },
  { id: 2, title: "B", done: false },
];

// Add an item immutably (new array, original untouched):
const added = [...todos, { id: 3, title: "C", done: false }];

// Update one item immutably (map, replacing the match with a copy):
const updated = todos.map((t) =>
  t.id === 1 ? { ...t, done: true } : t
);

// Remove an item immutably:
const removed = todos.filter((t) => t.id !== 2);

console.log(todos.length);   // still 2 — never mutated
console.log(added.length, updated[0].done, removed.length); // 3 true 1
Memorise these three patterns — add ([...arr, item]), update (map + spread), remove (filter). They are exactly how you'll update lists in React state for the rest of the course. This is one of the highest-leverage things in Part 0.

Exercise · A reporting pipeline

Given an array of orders [{ id, total, paid }], compute the sum of total for orders where paid is true, using filter then reduce. Then produce a new array marking every order paid: true without mutating the original (use map + spread).

🎓 Key takeaways

  • map transforms every item into a new array (React renders lists with map).
  • filter keeps a subset; reduce combines a list into a single value.
  • These methods don't mutate — they return new arrays you can chain into pipelines.
  • Immutability: add [...arr, x], update with map+spread, remove with filter.
  • This immutable toolkit is exactly how you'll manage React state.
