How Computers & the Web Really Work

🎯 Beginner · no code yet ⏱️ ~20 min read 🧠 Mental models

Before you write a single line of code, you need the map of the territory. A principal engineer isn't just someone who types fast — it's someone who has a precise mental model of what actually happens when software runs. In this lesson we build that model from the ground up: what a computer does, what a program is, and exactly what happens between you clicking a link and a web page appearing. Everything you learn later sits on top of this foundation.

1. What a computer actually does

Strip away the screens and the apps and a computer is a machine that does one thing, billions of times per second: it follows a list of simple instructions, in order, on data stored in memory. That's it. Every app, game, website, and AI model is ultimately a very long, very clever list of tiny instructions like "add these two numbers," "compare them," "if this is bigger, jump to instruction 5,042."

There are four pieces you'll hear about constantly. Here's what each one really is:

PartPlain-English jobAnalogy
CPUThe worker that executes instructions, one after another, extremely fast.A chef following a recipe.
RAM (memory)Fast, temporary workspace holding the data and program currently in use. Cleared when power is off.The kitchen counter — roomy but wiped clean each night.
Disk (SSD)Slow, permanent storage. Your files live here even when the computer is off.The pantry and fridge.
I/OEverything the computer talks to: keyboard, screen, network, mouse.The doors and windows of the kitchen.
🧩
Concept · Code is just data that describes work

The "program" you'll write is text. Something (a compiler or an interpreter) turns that text into the simple instructions the CPU understands. When we learn TypeScript, we're learning a precise, human-friendly language for describing work that ultimately becomes those tiny CPU instructions.

2. From human language to machine language

CPUs only understand machine code — raw numbers. Writing that by hand would be torture, so we invented programming languages: readable text with rules. Two strategies turn that text into running software:

  • Compiled languages translate the whole program ahead of time into machine code (e.g. C, Rust, Go).
  • Interpreted languages are read and executed on the fly by another program called an interpreter (e.g. JavaScript, Python).

JavaScript — the language that runs in every web browser — is interpreted (and then cleverly just-in-time compiled) by an engine. TypeScript, which you'll spend this course mastering, is JavaScript with a safety layer of types bolted on. Before it runs, TypeScript is compiled down to plain JavaScript. We'll unpack all of this properly in Part 1 — for now, just hold the shape of it.

✨
What's new in 2026

The TypeScript compiler itself was historically written in TypeScript. In 2026 the team shipped a native compiler written in Go ("tsgo", TypeScript 7) that type-checks roughly 10× faster. You don't need this yet, but it's a sign of how alive this ecosystem is — and we devote a whole lesson to it in Part 3.

3. The web: clients, servers, and requests

The web is a giant conversation between two kinds of computers. A client (your browser) asks for things. A server (a computer somewhere in a data centre) answers. They speak a protocol called HTTP — a shared set of rules for asking and answering. When you type an address and hit enter, here's the journey:

  1. DNS lookup. The human-friendly name (like example.com) is translated into a numeric IP address — the actual location of the server. DNS is the web's phone book.
  2. Connection. Your browser opens a secure connection to that address (the padlock = HTTPS, encrypted).
  3. Request. The browser sends an HTTP request: "GET me the page at this path."
  4. Response. The server replies with a status code (200 = OK, 404 = not found) and the content: usually HTML, plus links to CSS and JavaScript.
  5. Render. The browser reads the HTML, downloads the CSS and JS it references, and paints pixels on your screen.
📨
Note · This round-trip is the heartbeat of everything

Later, when you build React apps that fetch data, deploy to a server, and debug a slow page, you'll be reasoning about exactly these five steps. Keep this picture in your head.

4. The three languages of the web

A web page is built from three layers, each with a single job. A useful metaphor is a human body:

LanguageJobBody metaphor
HTMLStructure & content — headings, paragraphs, buttons.The skeleton.
CSSPresentation — colours, spacing, layout, fonts.The skin & clothes.
JavaScriptBehaviour — what happens when you click, type, or scroll.The muscles & brain.

You will become fluent in all three, but JavaScript (and its safer sibling TypeScript) is where the real engineering lives — and where React, the library powering most modern apps, operates. Let's see all three together. Here is a complete, tiny web page. Read every line; the annotation underneath explains it.

hello.html html 
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>My First Page</title>
    <style>
      /* CSS: how it looks */
      body { font-family: sans-serif; text-align: center; padding: 40px; }
      h1   { color: #2563eb; }
      button { font-size: 18px; padding: 10px 20px; cursor: pointer; }
    </style>
  </head>
  <body>
    <!-- HTML: the structure and content -->
    <h1>Hello, web!</h1>
    <p id="count">You have clicked 0 times.</p>
    <button id="btn">Click me</button>

    <script>
      // JavaScript: the behaviour
      let clicks = 0;
      const button = document.getElementById("btn");
      const label  = document.getElementById("count");
      button.addEventListener("click", () => {
        clicks = clicks + 1;
        label.textContent = "You have clicked " + clicks + " times.";
      });
    </script>
  </body>
</html>
What's happening: the <style> block is CSS (presentation). The <h1>, <p>, and <button> are HTML (structure). The <script> is JavaScript (behaviour): it remembers a number, finds the button on the page, and every time you click, increases the number and updates the text. Don't worry about syntax yet — just notice the three layers cooperating.
🧪
Pro-tip · Try it yourself

That code block above is a real, editable editor — the same engine that powers VS Code, running locally in your browser. Click into it and change "Hello, web!" to your name. Use the Copy button to grab the whole file, paste it into a text editor, save it as hello.html, and double-click it. You just shipped a web page. (We'll set up a proper environment in the next lesson.)

5. Where React fits (the 30-second preview)

Writing document.getElementById and manually updating text gets painful fast — imagine doing it for a dashboard with thousands of moving parts. React is a library that lets you describe what the screen should look like for a given state of your data, and it figures out the minimal changes to the page for you. You write "the label should say You have clicked N times," and React handles the rest whenever N changes. We'll arrive there in Part 4 — and by then you'll have the TypeScript foundation to use it like a senior engineer.

6. The mindset of an engineer

One last thing, and it matters more than any syntax. The difference between a beginner and a principal engineer is rarely raw knowledge — it's how they think when something breaks. Three habits to start cultivating from lesson one:

  • Build a model, then test it. Form a belief about what the code does, then verify it. Surprises are where learning happens.
  • Read the error. Error messages are not noise — they are the computer telling you precisely what it expected. We will read thousands together.
  • Break big problems into tiny ones. Every large system is just small, understandable pieces wired together — exactly like those CPU instructions.

Exercise · Cement the mental model

Without looking back, write down (on paper or in a notes app) the five steps that happen between hitting Enter on a URL and seeing the page. Then explain, in one sentence each, the job of HTML, CSS, and JavaScript. If you can do this from memory, you're ready for the next lesson.

🎓 Key takeaways

  • A computer follows simple instructions on data in memory, very fast. Code is human-readable text that becomes those instructions.
  • The web is clients (browsers) making HTTP requests and servers sending responses — remember the five-step round-trip.
  • Web pages are three cooperating layers: HTML (structure), CSS (style), JavaScript (behaviour).
  • TypeScript is JavaScript plus a type-safety layer that's compiled to JavaScript before it runs.
  • Engineering is a mindset: build a model, read the errors, break problems down.
