1. Modules: code across files

Real projects span many files. ES Modules let each file export what it offers and import what it needs. This keeps code organised, reusable, and testable.

math.jsjavascript 
// math.js — a module that exports two helpers
export function add(a, b) {
  return a + b;
}

export const PI = 3.14159;

// A "default" export — the file's main thing
export default function multiply(a, b) {
  return a * b;
}
main.jsjavascript 
// main.js — import named + default exports
import multiply, { add, PI } from "./math.js";

console.log(add(2, 3));      // 5
console.log(multiply(4, 5)); // 20
console.log(PI);             // 3.14159
Two kinds of export: named exports (export function add) are imported in braces by name; a single default export is imported without braces under any name you choose. React components are typically default exports — you'll see this constantly.

2. The DOM: controlling the page

The DOM (Document Object Model) is the browser's live, in-memory representation of your HTML as a tree of objects. JavaScript reads and changes the DOM to make pages interactive. You'll rarely touch the DOM directly once you have React — but understanding it makes React click.

dom.js (runs in a browser)javascript 
// Find an element
const title = document.querySelector("h1");
title.textContent = "Updated by JavaScript!";

// Create and add a new element
const item = document.createElement("li");
item.textContent = "A new list item";
document.querySelector("ul").append(item);

// React to events
const button = document.querySelector("#save");
button.addEventListener("click", () => {
  console.log("Saved!");
});
The pattern: select an element (querySelector), change it (textContent, append), and respond to user actions (addEventListener). React automates all of this — you describe the result and it updates the DOM for you — but this is the machinery underneath.
🔁
Note · Why React exists, in one sentence

Manually selecting and updating dozens of DOM elements as data changes is tedious and bug-prone. React lets you write "given this data, the UI looks like this" and handles every DOM update for you. Everything you just learned is the problem React solves.

3. Project P01 — Kickoff: a task manager

Time to build. P01 is a command-line task manager. In this lesson we write its first version in plain JavaScript using everything from Part 0 — objects, arrays, functions, immutability, and modules. In Part 1, we'll rebuild it in TypeScript with full type safety and tests. Same app, leveled up — so you feel exactly what TypeScript adds.

tasks.js — P01 v0 (plain JS)javascript 
// A tiny, immutable task store. No classes yet — just functions + data.
let nextId = 1;

function createTask(tasks, title) {
  const task = { id: nextId++, title, done: false };
  return [...tasks, task];           // immutable add
}

function toggleTask(tasks, id) {
  return tasks.map((t) =>            // immutable update
    t.id === id ? { ...t, done: !t.done } : t
  );
}

function removeTask(tasks, id) {
  return tasks.filter((t) => t.id !== id); // immutable remove
}

function summary(tasks) {
  const done = tasks.filter((t) => t.done).length;
  return `${done}/${tasks.length} done`;
}

// Drive it:
let tasks = [];
tasks = createTask(tasks, "Finish Part 0");
tasks = createTask(tasks, "Start Part 1");
tasks = toggleTask(tasks, 1);
console.log(tasks);
console.log(summary(tasks)); // "1/2 done"
Look familiar? Every function here uses the immutable patterns from Lesson 10. The app's "state" is an array of task objects, and each operation returns a new array. This is exactly the model React uses for state — you're already thinking like a React developer.
