Values, Variables & Types in JavaScript

🎯 Beginner ⏱️ ~28 min 💾 Core syntax

Every program is data plus the logic that transforms it. This lesson is about the data: the kinds of values JavaScript has, how to store them in variables, and the concept of types — which is the doorway to everything TypeScript adds. Take your time here; these foundations recur in every line you'll ever write.

1. Variables: naming your data

A variable is a labelled box that holds a value. In modern JavaScript you declare them with const or let. The rule of thumb: reach for const first, and only use let when you genuinely need to reassign the value.

variables.jsjavascript 
const country = "Brazil";   // can't be reassigned
let score = 0;              // can change later
score = score + 10;         // now 10

// const protects you from accidental reassignment:
// country = "Spain";  // ❌ TypeError: Assignment to constant variable

console.log(country, score); // Brazil 10
Why const first? It signals intent ("this won't change") and prevents a whole class of bugs. let is for counters and accumulators that must change. Never use the old var — it has confusing scoping rules we've moved past.

3. Strings and template literals

Text is a string. The modern, preferred way to build strings is the template literal — backticks with ${} placeholders. It's cleaner than gluing strings with +.

strings.jsjavascript 
const name = "Marie";
const age = 30;

// Old way: concatenation
const a = "Hi, " + name + ". You are " + age + ".";

// Modern way: template literal (note the backticks ` `)
const b = `Hi, ${name}. You are ${age}.`;

console.log(b);                 // Hi, Marie. You are 30.
console.log(name.toUpperCase()); // MARIE
console.log(name.length);        // 5
console.log(`Next year: ${age + 1}`); // expressions work inside ${}
What's happening: inside backticks, anything in ${ } is evaluated and inserted. Strings also have built-in helpers like .toUpperCase() and a .length property. You'll use template literals constantly.

4. Numbers and booleans

numbers.jsjavascript 
const price = 19.99;
const quantity = 3;
const total = price * quantity;     // 59.97
const rounded = Math.round(total);  // 60

const inStock = true;
const isFree = price === 0;          // false (=== is "exactly equal")
const canBuy = inStock && !isFree;   // true  (&& = and, ! = not)

console.log(total, rounded, canBuy);
Note the operators: * / + - for math, === for equality, && (and), || (or), ! (not). We'll explore all of them in the next lesson on control flow.
⚠️
Gotcha · null vs undefined

Both mean "no value", but by convention undefined = "this was never set" (JavaScript's default), and null = "deliberately empty" (you set it). Keeping them straight matters, and TypeScript will help you handle both safely.

5. typeof and dynamic typing

JavaScript is dynamically typed: a variable can hold any type, and that type can change at runtime. This is flexible but dangerous — it's exactly the freedom that lets bugs slip in, and exactly what TypeScript tames by letting you declare and enforce types. You can inspect a value's type with typeof:

typeof.jsjavascript 
let thing = "hello";
console.log(typeof thing);  // "string"

thing = 42;                 // legal in JS! the box now holds a number
console.log(typeof thing);  // "number"

thing = true;
console.log(typeof thing);  // "boolean"

// This flexibility is powerful but error-prone.
// In Part 1, TypeScript lets us say "thing is ALWAYS a string"
// and catches mistakes before the program ever runs.
The big idea: the same variable held a string, then a number, then a boolean — and JavaScript allowed it silently. This is why large JavaScript codebases get bug-prone, and why the entire rest of this course leans on TypeScript.

🎓 Key takeaways

  • Declare variables with const by default; use let only to reassign. Never var.
  • The primitives are string, number, boolean, null, undefined, bigint, symbol.
  • Build strings with template literals: `Hi, ${name}`.
  • === checks exact equality; && || ! are logic operators.
  • JS is dynamically typed — flexible but bug-prone — which is precisely what TypeScript fixes.
