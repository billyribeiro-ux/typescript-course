Arrays, Objects, Destructuring & Spread

🎯 Core ⏱️ ~30 min 📦 Structuring data

Real programs juggle collections and structured records, not single values. Arrays hold ordered lists; objects hold labelled properties. Together with the modern destructuring and spread syntax, they are the vocabulary of every React component's props and state. This lesson is dense and essential.

1. Arrays: ordered lists

arrays.jsjavascript 
const fruits = ["apple", "banana", "cherry"];

console.log(fruits[0]);       // "apple" — indexes start at 0
console.log(fruits.length);   // 3
console.log(fruits.at(-1));   // "cherry" — negative index from the end

fruits.push("date");          // add to the end
fruits.unshift("apricot");    // add to the front
const last = fruits.pop();    // remove + return the last
console.log(fruits.includes("banana")); // true
console.log(fruits.indexOf("cherry"));  // position, or -1 if absent
Mental model: an array is a numbered shelf. Index 0 is the first slot. .push/.pop work at the end, .unshift/.shift at the front, .at(-1) reads from the back. We'll meet the transforming methods (map/filter/reduce) in the next lesson — they're the stars of the show.

2. Objects: labelled records

objects.jsjavascript 
const user = {
  name: "Aria",
  age: 28,
  isAdmin: false,
  address: { city: "Lisbon", country: "PT" }, // objects can nest
};

console.log(user.name);             // dot access → "Aria"
console.log(user["age"]);           // bracket access → 28
console.log(user.address.city);     // "Lisbon"

user.age = 29;                      // update a property
user.email = "aria@mail.com";       // add a new one
delete user.isAdmin;                // remove one

console.log(Object.keys(user));     // ["name","age","address","email"]
Objects vs arrays: use an array for a list of similar things (todos, products); use an object for one thing with named attributes (a user, a config). React props and state are objects and arrays all the way down.

3. Arrays of objects (the bread and butter)

data.jsjavascript 
const todos = [
  { id: 1, title: "Learn TypeScript", done: false },
  { id: 2, title: "Build a project", done: false },
  { id: 3, title: "Get hired", done: false },
];

console.log(todos[0].title);   // "Learn TypeScript"
console.log(todos.length);     // 3

for (const todo of todos) {
  console.log(`${todo.done ? "✓" : "○"} ${todo.title}`);
}
This shape — an array of objects — is the single most common data structure you'll handle. Lists of users, products, messages, rows: all arrays of objects. Rendering them into a UI is most of what React does.

4. Destructuring: unpacking values

Destructuring pulls properties out of objects (or items out of arrays) into named variables in one line. It's used in virtually every React component to read props.

destructuring.jsjavascript 
const user = { name: "Aria", age: 28, city: "Lisbon" };

// Instead of user.name, user.age...
const { name, age } = user;
console.log(name, age);   // Aria 28

// Rename + default while destructuring:
const { city: location, role = "member" } = user;
console.log(location, role);  // Lisbon member

// Array destructuring is positional:
const colors = ["red", "green", "blue"];
const [first, second] = colors;
console.log(first, second);   // red green

// Common in React: function greet({ name }) { ... }
function welcome({ name }) {
  return `Welcome, ${name}`;
}
console.log(welcome(user));   // Welcome, Aria
Why it's everywhere: React components receive a props object and almost always destructure it in the parameter list: function Button({ label, onClick }) { ... }. Recognising this now means React will feel familiar later.

5. Spread & rest: copying and gathering

The ... syntax does two complementary jobs: spread expands a collection, and rest gathers leftovers. Spread is the key to immutable updates — making changed copies instead of mutating originals, which is how React state must be updated.

spread-rest.jsjavascript 
// SPREAD — copy and extend
const base = { name: "Aria", age: 28 };
const updated = { ...base, age: 29 };      // copy base, override age
console.log(updated); // { name: "Aria", age: 29 } — base is untouched

const a = [1, 2];
const b = [3, 4];
const merged = [...a, ...b];               // [1, 2, 3, 4]

// REST — gather the remaining items
const [head, ...tail] = [10, 20, 30, 40];
console.log(head);  // 10
console.log(tail);  // [20, 30, 40]

function sum(...numbers) {                  // accept any number of args
  return numbers.reduce((t, n) => t + n, 0);
}
console.log(sum(1, 2, 3, 4)); // 10
The crucial idea: { ...base, age: 29 } creates a new object — it does not change base. This "copy-then-change" pattern is mandatory for updating React state correctly, so internalise it now.
⚠️
Gotcha · Objects and arrays are references

When you do const b = a with an object or array, b points to the same data — change one, you change both. To get an independent copy, spread it: const b = { ...a } or const b = [...a]. This trips up everyone once; now it won't trip up you.

🎓 Key takeaways

  • Arrays are ordered (0-indexed) lists; objects are labelled records. Arrays of objects are everywhere.
  • Destructuring unpacks values: const { name } = user — the React props pattern.
  • Spread ... copies/merges; rest gathers leftovers.
  • { ...obj, key: newValue } makes a changed copy — essential for React state.
  • Objects/arrays are references; copy with spread to avoid accidental shared mutation.
