Git & GitHub: Version Control Foundations

🎯 Beginner ⏱️ ~25 min 🌿 Collaboration

Git is the time machine and collaboration backbone of all modern software. It lets you save snapshots of your work, experiment fearlessly, undo mistakes, and work with others without chaos. GitHub is where those snapshots live online. Mastering the everyday Git workflow now will pay off in every single project for the rest of your career.

1. The problem Git solves

Without version control, saving versions looks like app-final.js, app-final-v2.js, app-final-REALLY.js — and collaboration means emailing zip files. Git replaces all of that with one elegant idea: a repository (repo) that remembers the entire history of your project as a series of commits (snapshots), each with a message describing the change.

🧩
Concept · The three areas

Git moves your changes through three places: the working directory (your actual files), the staging area (changes you've marked to include in the next snapshot), and the repository (the saved history of commits). You add files to staging, then commit them to history.

2. One-time setup

Install Git (git-scm.com, or it's likely already installed), then tell it who you are:

terminal
git --version
git version 2.4x.x
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main

3. The everyday workflow

This loop — change → add → commit — is what you'll do dozens of times a day:

terminal
git init                       # start tracking this folder (once)
git status                     # what's changed?
git add .                       # stage all changes
git commit -m "Add hello program" # save a snapshot
git log --oneline              # view history
a1b2c3d Add hello program
✍️
Pro-tip · Write commit messages like a professional

A good message completes the sentence "If applied, this commit will…": Add login form, Fix crash on empty cart. Present tense, imperative mood, specific. Future-you (and your teammates) will thank you. We'll cover Conventional Commits formally in Part 3.

4. Branches: experiment without fear

A branch is a parallel line of work. You branch off main, build a feature, and merge it back when it's ready — main stays stable the whole time. This is the heart of professional collaboration.

terminal
git switch -c feature/add-button  # create + switch to a branch
# ...make changes, add, commit...
git switch main                   # back to the main line
git merge feature/add-button     # fold the work in

5. GitHub: your code in the cloud

GitHub hosts your repos online — for backup, portfolio, and collaboration. Create a free account, make a new repository, and connect your local repo to it. You push to send commits up, and pull to bring others' commits down.

terminal
git remote add origin https://github.com/you/my-project.git
git push -u origin main          # upload + remember the link
# later, after committing more:
git push
git pull                          # download teammates' changes
🙈
Note · .gitignore

Some files shouldn't be tracked — like the huge node_modules folder or secret .env files. A .gitignore file lists patterns Git should skip. Every project you build in this course will have one (this very course repo has one too).

📝
Exercise · Your first repo

Take the hello.js project from Lesson 2. Run git init, commit it with a clear message, create a new repo on GitHub, and push it. You now have your first project online — the start of your portfolio.

🎓 Key takeaways

  • Git records your project's history as commits (snapshots) inside a repository.
  • The daily loop: change → git add → git commit -m "…".
  • Branches let you build features in isolation and merge them when ready.
  • GitHub stores repos online; push sends, pull receives.
  • Use .gitignore to keep junk and secrets out of version control.
