Setting Up Your Professional Dev Environment

🎯 Beginner ⏱️ ~25 min 🛠️ Hands-on setup

A craftsman is only as good as their workshop. In this lesson you'll install and configure the exact toolchain professional engineers use every day in 2026 — Node.js, the pnpm package manager, and Visual Studio Code — and you'll run your very first program. We set this up carefully and correctly once, so it never gets in your way again.

1. The tools, and why each one exists

ToolWhat it isWhy you need it
Node.jsA program that runs JavaScript/TypeScript outside the browser.Lets you run code, build apps, and use the whole ecosystem.
pnpmA fast, disk-efficient package manager.Installs the open-source libraries your projects depend on.
VS CodeA free, world-class code editor from Microsoft.Where you'll write code, with autocompletion and TypeScript built in.

🧩
Concept · "Runtime" and "package manager"

A runtime is the engine that actually executes your code (Node is a runtime). A package manager downloads and organises reusable code other people wrote (called packages or dependencies) so you don't reinvent everything. Modern apps stand on the shoulders of thousands of these packages.

2. Install Node.js (the right way)

Don't install Node from a one-off download — professionals use a version manager so they can switch Node versions per project. On macOS/Linux we recommend fnm (Fast Node Manager); on Windows, use fnm or the official installer. We target Node 24 LTS (the long-term-support release current in 2026).

macOS / Linux — terminal
curl -fsSL https://fnm.vercel.app/install | bash
# restart your terminal, then:
fnm install 24
fnm use 24
node --version
v24.x.x
Windows — PowerShell (with winget)
winget install Schniz.fnm
fnm install 24
fnm use 24
node --version
v24.x.x
💡
Pro-tip · What "LTS" means

LTS = Long-Term Support. Node releases a new major version often, but LTS versions get years of bug/security fixes and are what you run in production. Even-numbered majors (22, 24, …) become LTS. Always build on LTS unless you have a specific reason not to.

3. Enable pnpm

Node ships with a tool called Corepack that manages package managers for you. We'll use it to turn on pnpm — faster and more disk-efficient than the default npm, and the standard for serious projects in 2026.

terminal
corepack enable
corepack prepare pnpm@latest --activate
pnpm --version
10.x.x

4. Install VS Code + the essential extensions

Download Visual Studio Code from code.visualstudio.com. Once installed, open it and add these extensions (click the squares icon in the left bar, search, install):

  • ESLint — flags mistakes as you type.
  • Prettier — formats your code automatically.
  • Error Lens — shows errors inline, right on the line.
  • ES7+ React/Redux snippets — handy shortcuts for later.

TypeScript support is built into VS Code already — that's not a coincidence. VS Code and TypeScript are both made by Microsoft and designed to work together beautifully. You'll feel it the moment you start typing.

⌨️
Note · The integrated terminal

VS Code has a built-in terminal: press Ctrl + ` (backtick) to open it. You'll run all your commands here without leaving the editor. This is where you'll live.

5. Your first program

Let's prove the whole toolchain works. Create a folder, make a file called hello.js, paste in this code, and run it with Node. Here's the file:

hello.js javascript 
// Your very first program.
// console.log prints a message to the terminal.
const name = "future engineer";
console.log("Hello, " + name + "! Your environment works. 🎉");

// A tiny bit of logic: print today's year.
const year = new Date().getFullYear();
console.log("It is the year " + year + " and you are now coding.");
What's happening: const name = ... stores a piece of text. console.log(...) prints to the terminal. new Date().getFullYear() asks the system for the current year. You'll understand every token of this within a few lessons.
terminal
mkdir my-first-project
cd my-first-project
# create hello.js (paste the code above), then run it:
node hello.js
Hello, future engineer! Your environment works. 🎉
It is the year 2026 and you are now coding.
⚠️
Gotcha · "command not found"

If node or pnpm says "command not found", your terminal hasn't picked up the new install. Close and reopen the terminal (or restart VS Code). On macOS/Linux, make sure the fnm line was added to your shell profile (~/.zshrc or ~/.bashrc) — the installer usually does this for you.

📝
Exercise · Make it yours

Change the program to print your real name and a sentence about why you're learning to code. Run it again with node hello.js. Congratulations — you've written, saved, and executed your own software.

🎓 Key takeaways

  • Use a version manager (fnm) to install Node 24 LTS — never a one-off download.
  • Enable pnpm via Corepack; it's the fast, modern package manager.
  • VS Code + ESLint/Prettier/Error Lens is the professional editor setup; TypeScript is built in.
  • node file.js runs a program; console.log prints output.
  • When a command isn't found, restart your terminal — it likely just needs to reload.
