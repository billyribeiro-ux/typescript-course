Async JavaScript: Promises & async/await

🎯 Core ⏱️ ~30 min ⏳ Handling time

Most real work takes time: fetching data from a server, reading a file, waiting for a user. Asynchronous code lets your program kick off slow work and keep going, handling the result when it arrives. We'll go from the underlying Promise to the clean async/await syntax you'll use in every data-driven React app.

1. Why async exists

Recall from Lesson 5: JavaScript does one thing at a time. If fetching data blocked until it finished, your whole app would freeze for seconds. Instead, slow operations return immediately with a placeholder for the eventual result — a Promise — and your code says "when this is ready, do that."

🎫
Concept · A Promise is a receipt

Think of ordering food: you get a receipt immediately (the Promise), not the meal. Later the order either resolves (your food arrives) or rejects (they're out of it). A Promise is a placeholder for a value that will exist later.

2. Promises with .then / .catch

promises.jsjavascript 
// A function that returns a Promise resolving after 1 second:
function fetchUser() {
  return new Promise((resolve) => {
    setTimeout(() => resolve({ name: "Ada", id: 1 }), 1000);
  });
}

console.log("Requesting...");
fetchUser()
  .then((user) => {
    console.log("Got user:", user.name);   // runs ~1s later
  })
  .catch((error) => {
    console.log("Something went wrong:", error);
  });
console.log("This prints BEFORE the user arrives!");
What's happening: .then() registers a callback for when the Promise resolves; .catch() handles failure. Notice the last line prints first — the program didn't wait. That's async in action.

3. async / await — the modern way

Chaining .then() gets unwieldy. async/await lets you write asynchronous code that reads like ordinary top-to-bottom code. Mark a function async, then await any Promise inside it.

async-await.jsjavascript 
function fetchUser() {
  return new Promise((resolve) =>
    setTimeout(() => resolve({ name: "Ada" }), 1000)
  );
}

async function showUser() {
  console.log("Requesting...");
  const user = await fetchUser();   // pause here until it resolves
  console.log("Got user:", user.name);
  return user;
}

showUser();
// Reads like synchronous code, but doesn't block the program.
The magic of await: it pauses this function until the Promise resolves, then continues with the result — without freezing the rest of the app. An async function always returns a Promise itself.

4. Real data: fetch from an API

The browser and Node both provide fetch() for making network requests. It returns a Promise. Here's the canonical pattern you'll use to load data — including proper error handling with try/catch.

fetch.jsjavascript 
async function getPost(id) {
  try {
    const response = await fetch(
      `https://jsonplaceholder.typicode.com/posts/${id}`
    );
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`); // turn a bad status into an error
    }
    const post = await response.json();  // parse the JSON body (also a Promise)
    return post;
  } catch (error) {
    console.log("Failed to load post:", error.message);
    return null;
  }
}

// Use it:
const post = await getPost(1);
console.log(post?.title);
The standard recipe: await fetch(url) → check response.ok → await response.json(), all wrapped in try/catch for failures. You will write this shape hundreds of times. (In Part 6, TanStack Query will manage it for you — but you must understand the fundamentals first.)

5. Running things in parallel

parallel.jsjavascript 
function delay(value, ms) {
  return new Promise((resolve) => setTimeout(() => resolve(value), ms));
}

// SLOW: awaits one after another (300 + 300 = ~600ms)
async function sequential() {
  const a = await delay("A", 300);
  const b = await delay("B", 300);
  return [a, b];
}

// FAST: start both, then await together (~300ms total)
async function parallel() {
  const [a, b] = await Promise.all([delay("A", 300), delay("B", 300)]);
  return [a, b];
}
console.log(await parallel()); // ["A", "B"]
Performance lesson: if tasks don't depend on each other, start them together and await Promise.all([...]) — don't await them one-by-one. Knowing when to parallelise is a mark of an experienced engineer.
⚠️
Gotcha · Forgetting await

If you forget await, you get the Promise object itself instead of its value — leading to confusing [object Promise] bugs. When something async "isn't working", check for a missing await first. TypeScript will also warn you about many of these.

🎓 Key takeaways

  • Async code starts slow work and continues, handling results later — it never blocks the app.
  • A Promise is a placeholder that later resolves (success) or rejects (failure).
  • async/await makes async code read top-to-bottom; await pauses until a Promise settles.
  • Load data with fetch → check .ok → .json(), inside try/catch.
  • Run independent tasks together with Promise.all; never forget await.
