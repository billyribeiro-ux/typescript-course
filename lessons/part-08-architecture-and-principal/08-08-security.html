Security: XSS, CSRF, Auth & Supply Chain

🏛️ Principal · critical ⏱️ ~32 min 🔒 Don't get breached

Security is not optional, and frontend engineers own a real share of it. A single vulnerability can leak user data or take down a company. This lesson covers the threats every web engineer must understand — XSS, CSRF, injection, auth mistakes, and supply-chain risk — and the concrete defenses. Think like an attacker; build like a defender.

1. XSS — the frontend's #1 threat

xss.tsxtsx 
// XSS = attacker-controlled content runs as code in a victim's browser.

// ✅ React escapes text by default — this is SAFE even if comment is malicious:
<p>{userComment}</p>

// ❌ dangerouslySetInnerHTML bypasses escaping — XSS hole if unsanitized:
<div dangerouslySetInnerHTML={{ __html: userComment }} />

// ✅ If you MUST render HTML, sanitize it first:
import DOMPurify from "dompurify";
<div dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(userComment) }} />
React's default escaping prevents most XSS — {userInput} is rendered as text, not HTML. The danger is dangerouslySetInnerHTML (the name is a warning!): never feed it unsanitized user content. Sanitize with DOMPurify, and add a Content Security Policy (CSP) header as defense-in-depth (blocks inline scripts even if something slips through).

2. The threat checklist

3. Supply-chain security

📦
Concept · Your dependencies are your attack surface

A typical app has thousands of transitive dependencies — any one could be compromised. Defenses: commit lockfiles, run pnpm audit / Dependabot, prefer fewer, well-maintained packages, pin versions, and enable npm provenance. Be wary of typosquatted package names. A malicious dependency runs with your app's full privileges.

⚠️
Gotcha · Validate on the server, always

Client-side validation is for UX, not security — an attacker bypasses your UI entirely. Every Server Action, Route Handler, and tRPC procedure must independently validate input (Zod) and check authorization. The frontend can be lying; the server must not trust it. This is the single most important security mindset.

📝
Exercise · Find and fix a hole

Audit a small app: find any dangerouslySetInnerHTML and add sanitization; add a basic CSP header; run pnpm audit and address findings; and verify one mutation checks authorization server-side (not just hiding a button). Write a one-page threat model for the app.

🎓 Key takeaways

  • XSS is the top frontend threat — React escapes by default; sanitize any raw HTML; set a CSP.
  • Defend against CSRF (SameSite/tokens), injection (ORM/params), and broken auth (server checks).
  • Never ship secrets to the client; validate & authorize on the server for every action.
  • Supply chain: lockfiles, audits, minimal/pinned deps — your dependencies are your attack surface.
  • Client validation is UX; server validation is security — never trust the frontend.
