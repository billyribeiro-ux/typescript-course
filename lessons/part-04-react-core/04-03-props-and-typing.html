Components, Props & Typing Them

⚛️ React + TS ⏱️ ~30 min 🔌 Data in

Props are how data flows into a component — the equivalent of function arguments. This is where your TypeScript mastery pays off enormously: typed props give you autocomplete, catch wrong usage at compile time, and document your components. We'll cover typing props, default values, children, and the patterns professionals use.

1. Typing props with an interface

Button.tsxtsx 
// Define the props shape — this IS the component's public API.
interface ButtonProps {
  label: string;
  variant?: "primary" | "secondary"; // optional (note the ?)
  disabled?: boolean;
  onClick: () => void;                // a function prop (callback)
}

// Destructure props in the parameter list (the idiomatic style):
function Button({ label, variant = "primary", disabled = false, onClick }: ButtonProps) {
  return (
    <button className={`btn btn-${variant}`} disabled={disabled} onClick={onClick}>
      {label}
    </button>
  );
}

// Usage is fully type-checked:
function App() {
  return <Button label="Save" variant="primary" onClick={() => alert("saved")} />;
  // <Button />                  // ❌ missing required label + onClick
  // <Button label="X" variant="huge" .../> // ❌ "huge" not allowed
}
This is everything from Part 1 applied to React. An interface (01-04) defines the props; ? marks optional ones; a string-literal union (01-03) constrains variant; destructuring with defaults (00-09) reads them. The payoff: using <Button> wrong is a compile error, and your editor autocompletes every prop.

2. Props are read-only & flow down

🧩
Concept · One-way data flow

A component must never modify its props — they belong to the parent. Data flows one way: from parent down to child. If a child needs to communicate up, the parent passes a callback prop (like onClick) that the child calls. This unidirectional flow makes apps predictable and debuggable.

3. The children prop

Card.tsxtsx 
import type { ReactNode } from "react";

interface CardProps {
  title: string;
  children: ReactNode;   // anything renderable: elements, strings, numbers...
}

function Card({ title, children }: CardProps) {
  return (
    <section className="card">
      <h2>{title}</h2>
      <div className="card-body">{children}</div>
    </section>
  );
}

// children is whatever you nest between the tags:
function App() {
  return (
    <Card title="Welcome">
      <p>This paragraph is the children.</p>
      <button>And so is this button.</button>
    </Card>
  );
}
children is the special prop for nested content — what you put between a component's opening and closing tags. Type it as ReactNode (the type for "anything React can render"). This enables powerful composition: wrapper/layout components like Card, Modal, and Layout that don't care what's inside them.

4. Extending native element props

native-props.tsxtsx 
import type { ComponentProps } from "react";

// Accept ALL the normal <button> props (onClick, type, aria-*, ...) PLUS our own.
interface IconButtonProps extends ComponentProps<"button"> {
  icon: string;
}

function IconButton({ icon, children, ...rest }: IconButtonProps) {
  return (
    <button {...rest}>          {/* spread the native props through */}
      <span className="icon">{icon}</span>
      {children}
    </button>
  );
}

// Now consumers get full native button typing for free:
<IconButton icon="★" type="submit" onClick={() => {}} aria-label="Favourite" />;
Pro pattern: ComponentProps<"button"> gives you every prop a real <button> accepts. Extending it and spreading {...rest} means your custom component is a drop-in replacement that supports type, aria-*, event handlers, etc. — without re-typing them all. This is how design-system components are built (Part 8).

🎓 Key takeaways

  • Props are typed inputs — define them with an interface and destructure with defaults.
  • Props are read-only and flow one way (down); children communicate up via callback props.
  • children: ReactNode enables wrapper/layout composition.
  • Extend ComponentProps<"button"> + spread {...rest} to wrap native elements cleanly.
  • Typed props give compile-time safety, autocomplete, and self-documenting components.
