Memoization & the React Compiler

⚛️ React · 2026 ⏱️ ~30 min ⚡ Performance

Re-rendering is normal and usually cheap, but sometimes it's wasteful. The classic tools — useMemo, useCallback, and React.memo — let you skip unnecessary work. The huge 2026 news: the React Compiler now does this automatically, so you write simple code and get optimised output. We'll teach both: the compiler-first reality, and the manual tools you still need to understand.

1. Why re-renders happen

🧩
Concept · A component re-renders when…

…its state changes, its parent re-renders, or its context changes. Re-rendering means React re-runs the function and reconciles the result with the DOM (Part 5). This is fast by default. Memoization is only about avoiding expensive recomputation or re-rendering — a targeted optimisation, not a default habit.

2. The classic tools (what they do)

manual-memo.tsxtsx 
import { memo, useMemo, useCallback, useState } from "react";

function Dashboard({ items }: { items: number[] }) {
  const [count, setCount] = useState(0);

  // useMemo: cache an EXPENSIVE computation; recompute only if deps change.
  const total = useMemo(() => items.reduce((a, b) => a + b, 0), [items]);

  // useCallback: cache a FUNCTION identity, so memoized children don't re-render.
  const handleClick = useCallback(() => setCount((c) => c + 1), []);

  return (
    <div>
      <p>Total: {total} · Clicks: {count}</p>
      <ExpensiveChild onClick={handleClick} />
    </div>
  );
}

// React.memo: skip re-rendering if props are shallow-equal to last time.
const ExpensiveChild = memo(function ExpensiveChild({ onClick }: { onClick: () => void }) {
  return <button onClick={onClick}>Click</button>;
});
Three related tools: useMemo caches a value, useCallback caches a function's identity (so it doesn't look "new" to children), and React.memo skips a child's re-render when its props haven't changed. They work together: memo'd children need stable (useCallback'd) function props to actually skip.

3. The React Compiler changes everything

✨
2026 · Automatic memoization

The React Compiler (stable in 2026) analyses your components at build time and inserts the equivalent of useMemo/useCallback/memo for you, precisely where they help. You write plain, readable components — no manual memoization — and get optimised re-rendering automatically. It's enabled via the Babel/Vite plugin.

compiler-era.tsxtsx 
// With the React Compiler enabled, you just write this —
// no useMemo, no useCallback, no memo. The compiler optimises it.
function Dashboard({ items }: { items: number[] }) {
  const [count, setCount] = useState(0);
  const total = items.reduce((a, b) => a + b, 0); // auto-memoized if expensive
  const handleClick = () => setCount((c) => c + 1); // stable identity, automatically
  return (
    <div>
      <p>Total: {total} · Clicks: {count}</p>
      <button onClick={handleClick}>Click</button>
    </div>
  );
}
// Cleaner, and usually FASTER than hand-tuned memoization.
The guidance for 2026: enable the React Compiler and write simple components. Reserve manual useMemo/useCallback for the rare cases the compiler can't handle, or codebases that haven't adopted it. Understanding the manual tools is still essential — you'll read them in existing code and need them occasionally — but they're no longer your default.

4. The rules that make it work

  • Components must be pure: given the same props/state, render the same output, with no side effects during render. The compiler relies on this.
  • Follow the Rules of Hooks: call hooks at the top level, unconditionally. The ESLint plugin (03-04) enforces this.
  • Don't mutate props or state: the immutability you've practised all course is what makes safe memoization possible.
📝
Exercise · Measure before optimising

Build a list with an expensive derived computation (e.g. sorting + filtering 10k items). Use the React DevTools Profiler to see render times. Add useMemo and measure again. Then appreciate that the React Compiler would do this for you — and that you should always measure before reaching for manual memoization.

🎓 Key takeaways

  • Re-renders happen on state/parent/context change — cheap by default; memoization targets the expensive cases.
  • useMemo caches a value, useCallback a function identity, React.memo a child's render.
  • The React Compiler (2026) inserts these automatically — write simple components, get optimised output.
  • Reserve manual memoization for edge cases; still learn it for reading existing code.
  • Purity, Rules of Hooks, and immutability are what make automatic optimisation safe.
