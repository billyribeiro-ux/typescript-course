The architecture you now know by heart

Same discipline as P01/P02: pure core, thin edges, testable everywhere. lib/weather.ts is pure logic, lib/api.ts is the network boundary, hooks/useWeather.ts models the request as a discriminated union, and the components are small and typed. The result: every layer is independently testable.

1. The pure core

src/lib/weather.ts (excerpt)typescript 
export type Unit = "celsius" | "fahrenheit";

export function convertTemp(celsius: number, unit: Unit): number {
  return unit === "fahrenheit" ? celsius * (9 / 5) + 32 : celsius;
}
export function formatTemp(celsius: number, unit: Unit): string {
  const value = Math.round(convertTemp(celsius, unit));
  return `${value}°${unit === "fahrenheit" ? "F" : "C"}`;
}

const COMPASS = ["N", "NE", "E", "SE", "S", "SW", "W", "NW"] as const;
export function windDirection(deg: number): (typeof COMPASS)[number] {
  const normalized = ((deg % 360) + 360) % 360;
  return COMPASS[Math.round(normalized / 45) % 8]!;
}
Pure functions, zero React. Temperature conversion, formatting, compass directions, forecast summaries — all just data in, data out, using a string-literal union for Unit (01-03) and as const (02-10) for the compass. These are tested with simple expect().toBe() assertions — no DOM needed.

2. The custom hook (discriminated-union state)

src/hooks/useWeather.tstsx 
export type WeatherState =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; weather: Weather }
  | { status: "error"; message: string };

export function useWeather(point: GeoPoint | null): WeatherState {
  const [state, setState] = useState<WeatherState>({ status: "idle" });
  useEffect(() => {
    if (!point) { setState({ status: "idle" }); return; }
    const controller = new AbortController();   // race guard (04-07)
    setState({ status: "loading" });
    fetchWeather(point, controller.signal)
      .then((weather) => { if (!controller.signal.aborted) setState({ status: "success", weather }); })
      .catch((err) => { if (!controller.signal.aborted) setState({ status: "error", message: String(err) }); });
    return () => controller.abort();             // cleanup cancels stale requests
  }, [point]);
  return state;
}
This is lessons 02-07, 04-07, and 04-11 combined. The request is a discriminated union, so the component renders each state precisely (no impossible "loading + data" combos). The effect uses an AbortController to cancel stale requests when the city changes — the professional fix for the race condition from 04-07. In Part 6, TanStack Query replaces this entire hook.

3. Components render the union exhaustively

src/App.tsx (excerpt)tsx 
const state = useWeather(point);

return (
  <main>
    <SearchForm onSearch={handleSearch} unit={unit} onToggleUnit={toggleUnit} />
    {state.status === "loading" && <p>Loading weather…</p>}
    {state.status === "error" && <p role="alert">Error: {state.message}</p>}
    {state.status === "success" && (
      <>
        <WeatherCard weather={state.weather} unit={unit} />
        <ForecastList daily={state.weather.daily} unit={unit} />
      </>
    )}
  </main>
);
Conditional rendering (04-05) driven by the union's status. Inside the "success" branch, TypeScript knows state.weather exists — narrowing (01-06) at work. SearchForm is a controlled component (04-06); WeatherCard and ForecastList take typed props (04-03) and map the forecast with keys (04-05).

Three testing techniques to internalise

1) Pure unit tests for lib/ — fast, no mocks. 2) renderHook for the custom hook, with the network module mocked via vi.mock so it's deterministic. 3) Component tests with @testing-library/react + user-event: render, query by role/label (accessible queries!), interact, and assert. This is the professional React testing toolkit (formalised in Part 5).
