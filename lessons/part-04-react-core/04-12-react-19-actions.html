React 19 Actions & New Hooks

⚛️ React 19 · 2026 ⏱️ ~32 min 🆕 The latest APIs

React 19 introduced a family of features called Actions that dramatically simplify the most common hard problem in UIs: handling async submissions with pending states, errors, and optimistic updates. Plus the new use() API. These are the modern primitives for forms and mutations — you'll use them throughout the rest of the course.

1. useActionState — async submissions, simplified

useActionState.tsxtsx 
import { useActionState } from "react";

interface State { error?: string; success?: boolean; }

async function subscribe(_prev: State, formData: FormData): Promise<State> {
  const email = String(formData.get("email"));
  if (!email.includes("@")) return { error: "Invalid email" };
  await fetch("/api/subscribe", { method: "POST", body: formData });
  return { success: true };
}

function Newsletter() {
  // [currentState, formAction, isPending] — pending state for FREE:
  const [state, formAction, isPending] = useActionState(subscribe, {});

  return (
    <form action={formAction}>
      <input name="email" type="email" />
      <button disabled={isPending}>{isPending ? "Submitting..." : "Subscribe"}</button>
      {state.error && <p className="error">{state.error}</p>}
      {state.success && <p>Thanks for subscribing!</p>}
    </form>
  );
}
This replaces a pile of boilerplate. Before, you'd hand-manage isLoading, error, and the submit handler with useState + useEffect. useActionState gives you the result state, a formAction to wire to <form action>, and isPending — all handled. The action is a plain async function (prevState, formData) => newState.

2. useFormStatus — pending state for nested buttons

useFormStatus.tsxtsx 
import { useFormStatus } from "react-dom";

// A reusable submit button that knows the form's pending state —
// WITHOUT props being drilled down from the form.
function SubmitButton({ label }: { label: string }) {
  const { pending } = useFormStatus();
  return <button type="submit" disabled={pending}>
    {pending ? "Working..." : label}
  </button>;
}
// Drop <SubmitButton /> inside any <form> and it auto-disables while submitting.
useFormStatus reads the status of the nearest parent <form> — so a shared SubmitButton component can show a pending state anywhere, with no prop threading. This is how you build reusable form controls in a design system that "just work".

3. useOptimistic — instant UI feedback

useOptimistic.tsxtsx 
import { useOptimistic } from "react";

function MessageList({ messages, sendMessage }: {
  messages: string[];
  sendMessage: (text: string) => Promise<void>;
}) {
  // Show the new message IMMEDIATELY, before the server confirms:
  const [optimistic, addOptimistic] = useOptimistic(
    messages,
    (current, newText: string) => [...current, newText + " (sending...)"]
  );

  async function action(formData: FormData) {
    const text = String(formData.get("text"));
    addOptimistic(text);          // UI updates instantly
    await sendMessage(text);      // then the real request happens
  }

  return (
    <form action={action}>
      <ul>{optimistic.map((m, i) => <li key={i}>{m}</li>)}</ul>
      <input name="text" />
    </form>
  );
}
Optimistic updates make an app feel instant. useOptimistic shows the expected result immediately while the real request is in flight, then reconciles with the true state when it resolves (reverting on error). This is the polish that distinguishes professional apps — and React 19 makes it a one-liner.

4. The use() API

use-api.tsxtsx 
import { use, Suspense } from "react";

// use() unwraps a promise (or context) — read inside a Suspense boundary:
function UserName({ userPromise }: { userPromise: Promise<{ name: string }> }) {
  const user = use(userPromise); // suspends until resolved
  return <p>{user.name}</p>;
}

function App({ userPromise }: { userPromise: Promise<{ name: string }> }) {
  return (
    <Suspense fallback={<p>Loading...</p>}>
      <UserName userPromise={userPromise} />
    </Suspense>
  );
}
// Unlike hooks, use() can be called conditionally. Suspense (Part 5) shows
// the fallback while the promise is pending.
use() reads the value of a promise or context, integrating with Suspense (Part 5) to show a fallback while loading. Unlike other hooks, it can be called conditionally. It's a building block for the data-fetching patterns we explore in Part 5 and the Server Components of Part 7.
✨
2026 · Why this matters

Actions unify client and server mutations. The same action pattern works with Next.js Server Actions (Part 7), so a form's submit logic can run on the server with full type safety, pending states, and optimistic UI — all using these exact hooks. You're learning the foundation of modern full-stack React.

🎓 Key takeaways

  • useActionState handles async submissions: result state, a formAction, and isPending for free.
  • useFormStatus lets nested buttons read the parent form's pending state — no prop drilling.
  • useOptimistic shows expected results instantly, reconciling when the request resolves.
  • use() unwraps promises/context and integrates with Suspense; it can be called conditionally.
  • These Actions are the foundation for Next.js Server Actions (Part 7) — modern full-stack React.
