Lists, Keys & Conditional Rendering

⚛️ React ⏱️ ~28 min 📋 Dynamic UI

Real UIs render lists of data and show different things based on conditions. In React, both are done with plain JavaScript expressions inside JSX — .map() for lists (with the crucial key prop) and ternaries / && for conditionals. Your Part 0 array-method fluency makes this effortless.

1. Rendering lists with .map()

ProductList.tsxtsx 
interface Product { id: number; name: string; price: number; }

function ProductList({ products }: { products: Product[] }) {
  return (
    <ul>
      {products.map((product) => (
        <li key={product.id}>        {/* key is REQUIRED on list items */}
          {product.name} — ${product.price}
        </li>
      ))}
    </ul>
  );
}
// This is exactly the array.map() from lesson 00-10 — now mapping data
// to JSX elements instead of to other values. Same skill, new target.
Rendering a list IS array.map() (lesson 00-10), transforming each data item into a JSX element. The whole reason map was emphasised so heavily in Part 0 is this moment. The result is an array of elements, which React renders in order.

2. The key prop — why it matters

🔑
Concept · Keys give items a stable identity

React uses key to track which item is which across re-renders, so when the list changes (add/remove/reorder) it can update efficiently and preserve each item's state. The key must be a stable, unique ID from your data — typically item.id.

⚠️
Gotcha · Don't use the array index as key

key={index} looks tempting but causes subtle bugs when items are added, removed, or reordered — React mismatches items and their state (e.g. text typed in the wrong input). Use a stable ID from the data. Only fall back to index for a static list that never changes order.

3. Conditional rendering

conditionals.tsxtsx 
function Dashboard({ user, notifications }: { user: User | null; notifications: number }) {
  return (
    <div>
      {/* Ternary: choose between two things (lesson 00-07) */}
      {user ? <p>Welcome, {user.name}</p> : <p>Please log in</p>}

      {/* && : render something only if a condition is true */}
      {notifications > 0 && <span className="badge">{notifications}</span>}

      {/* Early return for a whole-component condition: */}
      {/* if (!user) return <LoginScreen />; — at the top of the component */}
    </div>
  );
}
interface User { name: string }
Two workhorses: the ternary cond ? a : b picks between two outputs; cond && element renders element only when cond is truthy (because false renders nothing — lesson 04-02). For whole-component branching, an early return at the top is cleanest.

4. The && number gotcha

and-gotcha.tsxtsx 
// ❌ If count is 0, this renders the NUMBER 0, not nothing!
{items.length && <List items={items} />}   // shows "0" when empty

// ✅ Make the left side a real boolean:
{items.length > 0 && <List items={items} />}
{!!items.length && <List items={items} />}
{items.length ? <List items={items} /> : null}
A classic trap: 0 && x evaluates to 0, and React renders 0 (numbers are renderable). Always make the left operand a genuine boolean (length > 0). This bug appears in real codebases constantly — now you'll spot it instantly.

Exercise · A filtered list

Given an array of tasks with a done boolean, render them with .map() and proper keys. Add a "show completed only" toggle (useState) and use .filter() before mapping. Show an empty-state message with && when the filtered list is empty (mind the number gotcha!).

🎓 Key takeaways

  • Render lists by mapping data to JSX with .map() — the Part 0 skill, new target.
  • Every list item needs a stable, unique key (use item.id, never the index).
  • Conditionals: ternary for either/or, && for show-if, early return for whole-component branches.
  • Beware 0 && ... — coerce to a real boolean (length > 0).
  • Combine filter + map to render derived/filtered views of your data.
