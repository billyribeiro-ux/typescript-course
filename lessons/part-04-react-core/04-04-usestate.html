State with useState

⚛️ React · pivotal ⏱️ ~32 min 🔁 Reactivity

State is data a component owns that can change over time — and changing it re-renders the UI. The useState hook is how function components hold state. This is the beating heart of interactivity in React. We'll cover the syntax, the all-important update rules, and the immutability patterns you already learned in Part 0 — now with a purpose.

1. The useState hook

Counter.tsxtsx 
import { useState } from "react";

function Counter() {
  // useState returns a TUPLE: [currentValue, setterFunction]  (lesson 01-03!)
  const [count, setCount] = useState(0); // 0 is the initial value; count: number

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </div>
  );
}
// Clicking calls setCount → React re-renders Counter → the new count shows.
useState returns a tuple (recall lesson 01-03) — the current value and a setter. Calling the setter does two things: it updates the stored value, and it tells React to re-render this component with the new value. TypeScript infers the type from the initial value (count is number). This is "UI = f(state)" made concrete.

2. The golden rules of state

⚠️
Gotcha · Never mutate state directly

count = 5 or todos.push(x) do nothing — React won't re-render, and it breaks. You must call the setter with a new value/object/array. This is why you learned immutability in Part 0: it's mandatory in React. Update state, don't mutate it.

updater-function.tsxtsx 
const [count, setCount] = useState(0);

// ❌ Risky when updates batch — reads a possibly-stale `count`:
setCount(count + 1);
setCount(count + 1); // both see the SAME count → only +1 total

// ✅ Use the UPDATER FUNCTION form when next state depends on previous:
setCount((prev) => prev + 1);
setCount((prev) => prev + 1); // +2 total, correctly

// React BATCHES multiple setState calls in one event into a single re-render.
Use the updater function setCount(prev => ...) whenever the next value depends on the current one. React may batch several updates, and the direct form can read a stale value. The updater form always receives the latest state. Make this a habit.

3. State with objects and arrays (immutably)

TodoList.tsxtsx 
import { useState } from "react";

interface Todo { id: number; title: string; done: boolean; }

function TodoList() {
  const [todos, setTodos] = useState<Todo[]>([]); // explicit type for empty init

  const add = (title: string) =>
    setTodos((prev) => [...prev, { id: Date.now(), title, done: false }]); // 00-10!

  const toggle = (id: number) =>
    setTodos((prev) => prev.map((t) => (t.id === id ? { ...t, done: !t.done } : t)));

  const remove = (id: number) =>
    setTodos((prev) => prev.filter((t) => t.id !== id));

  return (
    <ul>
      {todos.map((t) => (
        <li key={t.id} onClick={() => toggle(t.id)}>
          {t.done ? "✓" : "○"} {t.title}
        </li>
      ))}
    </ul>
  );
}
Look familiar? These are exactly the immutable patterns from lesson 00-10 and Project P01 — add with spread, update with map, remove with filter. React state management is just immutable data transformation. When the initial value can't be inferred (an empty array), provide the type explicitly: useState<Todo[]>([]).

4. State is per-component-instance

🧩
Concept · Each instance has its own state

Render <Counter /> three times and you get three independent counters — each call to useState creates state local to that instance (it's a closure, lesson 00-08!). State is isolated and private to each component instance, which is what makes components truly reusable.

🎓 Key takeaways

  • useState returns [value, setter]; calling the setter updates state AND re-renders.
  • Never mutate state — always pass a new value/object/array to the setter (immutability from Part 0).
  • Use the updater form setX(prev => ...) when the next state depends on the previous.
  • Update objects/arrays with spread/map/filter — the same patterns as P01.
  • State is private to each component instance, enabling true reuse.
