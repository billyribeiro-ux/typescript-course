JSX In Depth

⚛️ React ⏱️ ~28 min 📝 The syntax

JSX is the HTML-like syntax you write inside components. It looks like HTML but it's actually JavaScript in disguise — every JSX tag compiles to a function call that creates a UI element. Understanding that JSX is JavaScript is the key to using it fluently, including embedding expressions, the small but important differences from HTML, and how the compiler treats it.

1. JSX is JavaScript

jsx-is-js.tsxtsx 
// This JSX...
const element = <h1 className="title">Hello</h1>;

// ...compiles to roughly this function call:
// const element = jsx("h1", { className: "title", children: "Hello" });

// Because JSX is just expressions, it follows JS rules:
// - a component must return ONE root element (or a Fragment)
// - use parentheses for multi-line JSX for readability
function Card() {
  return (
    <div className="card">
      <h2>Title</h2>
      <p>Body</p>
    </div>
  );
}
JSX is not a template language — it's syntax sugar for function calls. Each tag becomes a jsx(type, props) call returning a plain object (a "React element") that describes UI. Because it's JavaScript, you get full type-checking on it, and you can use it anywhere an expression is allowed.

2. Embedding expressions with {}

expressions.tsxtsx 
function Greeting() {
  const name = "Ada";
  const hour = new Date().getHours();
  const items = ["a", "b", "c"];

  return (
    <div>
      {/* Any JS EXPRESSION goes inside curly braces: */}
      <h1>Hello, {name.toUpperCase()}!</h1>
      <p>The time is {hour}:00</p>
      <p>{hour < 12 ? "Good morning" : "Good afternoon"}</p>
      <p>You have {items.length} items</p>
      {/* attributes take expressions too: */}
      <img src={`/avatars/${name}.png`} alt={name} />
    </div>
  );
}
Curly braces embed any JavaScript expression (something that produces a value) — variables, math, function calls, ternaries, template literals. Note: statements (if, for) don't go inside JSX; use expressions (ternary, &&, .map()) instead — which we cover in lesson 04-05.

4. Fragments & comments

fragments.tsxtsx 
// A component must return ONE root. To return siblings without an extra
// wrapper <div>, use a Fragment — the empty <>...</> tag:
function Pair() {
  return (
    <>
      <li>First</li>
      <li>Second</li>
    </>
  );
}
// Renders two <li> with NO wrapper element — keeps your HTML clean.

// Inline styles are objects (note double braces: {{ }}):
function Badge() {
  return <span style={{ color: "white", background: "#2563eb", padding: 4 }}>New</span>;
}
// {/* This is how you write a comment inside JSX */}
Fragments (<>...</>) let you return multiple elements without polluting the DOM with wrapper divs — important for valid HTML (e.g. <li> inside a <ul>). Inline style takes a JS object with camelCased properties (the outer braces are JSX, the inner braces are the object).
⚠️
Gotcha · You can't render objects or booleans

{someObject} throws ("Objects are not valid as a React child"). React renders strings, numbers, and elements — not raw objects. And false/null/undefined render nothing (handy for conditionals, lesson 04-05). To show an object, format it first ({JSON.stringify(obj)} or access a property).

🎓 Key takeaways

  • JSX is JavaScript — each tag compiles to a function call returning a React element object.
  • Embed any expression with {}; statements (if/for) don't belong inside JSX.
  • JSX differs from HTML: className, htmlFor, camelCase events, object style, all tags close.
  • Fragments (<></>) return siblings without an extra wrapper element.
  • React renders strings/numbers/elements; false/null render nothing; raw objects error.
