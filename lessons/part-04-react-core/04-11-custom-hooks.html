Building Custom Hooks

⚛️ React · pivotal ⏱️ ~30 min ♻️ Reusable logic

Components reuse UI; custom hooks reuse stateful logic. A custom hook is just a function whose name starts with use and that calls other hooks. This is React's most elegant idea for sharing behaviour — a localStorage syncer, a debounced value, a data fetcher — without duplicating code. Mastering custom hooks is what makes your React code DRY and testable.

1. Your first custom hook

useToggle.tsxtsx 
import { useState, useCallback } from "react";

// A custom hook: a function starting with "use" that uses other hooks.
function useToggle(initial = false): [boolean, () => void] {
  const [on, setOn] = useState(initial);
  const toggle = useCallback(() => setOn((v) => !v), []);
  return [on, toggle]; // return a tuple, like useState
}

// Reuse it anywhere — each call gets its OWN independent state:
function Panel() {
  const [isOpen, toggleOpen] = useToggle();
  return (
    <div>
      <button onClick={toggleOpen}>{isOpen ? "Hide" : "Show"}</button>
      {isOpen && <p>Now you see me.</p>}
    </div>
  );
}
A custom hook is just a function that calls hooks. The use prefix is a convention React's lint rules rely on. Like useState, each component that calls useToggle gets its own isolated state (closures again — lesson 00-08). You've extracted reusable behaviour with zero ceremony.

2. A genuinely useful hook: useLocalStorage

useLocalStorage.tsxtsx 
import { useState, useEffect } from "react";

// Generic over the stored value's type (lesson 01-08!):
function useLocalStorage<T>(key: string, initial: T) {
  const [value, setValue] = useState<T>(() => {
    const raw = localStorage.getItem(key);
    return raw ? (JSON.parse(raw) as T) : initial; // lazy init
  });

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value)); // sync to storage
  }, [key, value]);

  return [value, setValue] as const; // tuple, preserving types
}

// Usage — fully typed, persists across reloads:
function Settings() {
  const [theme, setTheme] = useLocalStorage<"light" | "dark">("theme", "light");
  return <button onClick={() => setTheme(theme === "light" ? "dark" : "light")}>
    {theme}
  </button>;
}
This composes everything: generics (01-08) for the value type, lazy state initialisation (the function form of useState runs once), and an effect (04-07) to sync to localStorage. as const (02-10) keeps the return a tuple. One small hook, reused across an app — and it's exactly the kind of utility you'll write constantly.

3. Composing hooks & the rules

useDebounced.tsxtsx 
import { useState, useEffect } from "react";

// Delay a value's updates — great for search-as-you-type.
function useDebounced<T>(value: T, delayMs: number): T {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delayMs);
    return () => clearTimeout(id); // cleanup cancels the pending update
  }, [value, delayMs]);
  return debounced;
}

function Search() {
  const [query, setQuery] = useState("");
  const debouncedQuery = useDebounced(query, 300); // hooks compose freely
  // ...fetch using debouncedQuery, so we don't fire on every keystroke...
  return <input value={query} onChange={(e) => setQuery(e.target.value)} />;
}
Hooks compose: custom hooks call built-in hooks and each other. The Rules of Hooks apply: only call hooks at the top level of a component or another hook, never inside loops, conditions, or nested functions — so React can track them by call order. The ESLint plugin (03-04) enforces this; trust it.
⚡
Pro-tip · Custom hooks are unit-testable

Because a custom hook is just a function, you can test it in isolation with Testing Library's renderHook (Part 5) — no full component needed. Extracting logic into hooks doesn't just DRY your UI; it makes your logic testable, the same principle as the pure cores of P01/P02.

🎓 Key takeaways

  • A custom hook is a use-prefixed function that calls other hooks to reuse stateful logic.
  • Each call gets independent state; return a tuple (like useState) or an object.
  • Hooks compose generics, effects, refs, and other hooks (e.g. useLocalStorage, useDebounced).
  • Obey the Rules of Hooks: top-level only, never conditional — enforced by ESLint.
  • Custom hooks make logic reusable and unit-testable (renderHook).
