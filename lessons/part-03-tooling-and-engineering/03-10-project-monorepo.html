Project — Publish P02 as a Monorepo

🏗️ Build ⏱️ ~70 min 📦 Real engineering

Time to assemble everything from Part 3. We'll take the P02 schema validator and turn it into a professional monorepo: pnpm workspaces, Turborepo caching, TypeScript project references, shared ESLint/Prettier config, a consuming demo app, and a CI pipeline. This is the exact structure of a real company's frontend platform repo.

1. The target structure

repo layouttext 
validator-monorepo/
  package.json            # root: scripts + devDeps (turbo, prettier, eslint)
  pnpm-workspace.yaml     # packages: ["packages/*", "apps/*"]
  turbo.json              # build/test/lint pipeline + caching
  tsconfig.base.json      # shared strict compiler options
  tsconfig.json           # solution file: references all packages
  eslint.config.js        # shared flat config
  .github/workflows/ci.yml
  packages/
    validator/            # the P02 library (publishable)
      src/ ...
      package.json        # name: "@acme/validator", exports, build script
      tsconfig.json       # composite: true, extends base
  apps/
    demo/                 # a tiny app that USES @acme/validator
      src/main.ts
      package.json        # "@acme/validator": "workspace:*"
      tsconfig.json       # references ../../packages/validator
This is the canonical monorepo shape: shared libraries in packages/*, runnable apps in apps/*, and root-level config + tooling. The validator becomes a publishable package; the demo app consumes it locally via workspace:* — no publishing needed during development.

2. Root configuration

package.json (root)json 
{
  "name": "validator-monorepo",
  "private": true,
  "scripts": {
    "build": "turbo build",
    "test": "turbo test",
    "lint": "turbo lint",
    "check": "turbo build lint test && prettier --check ."
  },
  "devDependencies": {
    "turbo": "^2.3.0",
    "prettier": "^3.4.0",
    "typescript": "^5.9.0"
  },
  "packageManager": "pnpm@10.0.0"
}
"private": true on the root prevents accidentally publishing the whole repo. Scripts delegate to turbo, which fans out to each package's own script in dependency order with caching. One pnpm check at the root verifies the entire repo — locally and in CI.

3. The publishable package

packages/validator/package.jsonjson 
{
  "name": "@acme/validator",
  "version": "1.0.0",
  "type": "module",
  "main": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": { "types": "./dist/index.d.ts", "default": "./dist/index.js" }
  },
  "files": ["dist"],
  "scripts": {
    "build": "tsc --build",
    "test": "vitest run",
    "lint": "eslint src"
  }
}
The exports + types fields are how a package ships its API and its types (recall lesson 01-10). "files": ["dist"] means only the built output is published — not your source or tests. This is exactly the package.json shape of the real P02 project you already built, now slotted into a monorepo.

4. Wiring the demo app to the library

apps/demo/src/main.tstypescript 
// The demo imports the local workspace package by its published name.
import { v, type Infer } from "@acme/validator";

const Event = v.object({
  name: v.string().min(1),
  attendees: v.number().int().min(0),
});
type Event = Infer<typeof Event>;

const result = Event.safeParse({ name: "Launch", attendees: 120 });
console.log(result.success ? result.data : result.error.issues);
// Edit the validator's source, and `turbo build` rebuilds only what changed.
This is the payoff of the whole part. The app uses @acme/validator as if it were published from npm, but it resolves to your local source. Change the library, and Turborepo + project references rebuild only the affected packages. Editing across package boundaries feels seamless. This is daily life at a company with a shared platform.
terminal
pnpm install
pnpm check        # turbo build + lint + test across all packages, cached
pnpm --filter demo dev  # run just the demo app

🎓 Key takeaways

  • A real monorepo: packages/* (libraries) + apps/* (consumers) + root tooling.
  • pnpm workspaces link packages via workspace:*; Turborepo caches and orders tasks.
  • Project references make cross-package type-checking incremental; the root solution config ties it together.
  • The library ships via exports/types/files — the same shape as your P02 project.
