ESLint Flat Config & Prettier

🛠️ Tooling ⏱️ ~26 min ✨ Code quality

Two tools keep a codebase clean and consistent. Prettier formats your code automatically — no more arguing about spaces. ESLint catches likely bugs and enforces best practices. Together they remove an entire category of code-review nitpicks and let humans focus on what matters. We set up the modern flat config used in 2026.

1. Prettier — formatting, settled

terminal
pnpm add -D prettier
pnpm prettier --write .   # format every file
pnpm prettier --check .   # verify formatting (CI gate)
.prettierrc.jsonjson 
{
  "semi": true,
  "singleQuote": false,
  "trailingComma": "all",
  "printWidth": 100,
  "tabWidth": 2
}
The point of Prettier is to stop deciding. Pick settings once, then never think about formatting again — on save, your editor reformats. Code reviews stop containing "add a space here" and focus on logic. Configure your editor to "format on save" with the Prettier extension.

2. ESLint — catching real problems

ESLint analyses your code for bugs and anti-patterns: unused variables, missing await, incorrect React Hook usage, accidental any. In 2026 the standard is the flat config (eslint.config.js), which replaced the old .eslintrc format.

eslint.config.jsjavascript 
import js from "@eslint/js";
import tseslint from "typescript-eslint";
import react from "eslint-plugin-react-hooks";

export default tseslint.config(
  js.configs.recommended,
  ...tseslint.configs.recommendedTypeChecked, // type-aware rules!
  {
    files: ["**/*.{ts,tsx}"],
    languageOptions: {
      parserOptions: { projectService: true }, // connect to your tsconfig
    },
    plugins: { "react-hooks": react },
    rules: {
      "react-hooks/rules-of-hooks": "error",
      "react-hooks/exhaustive-deps": "warn",
      "@typescript-eslint/no-floating-promises": "error", // catch missing await
      "@typescript-eslint/no-explicit-any": "warn",
    },
  },
  { ignores: ["dist/", "node_modules/"] },
);
The flat config is just an array of config objects — each can target specific files and apply rules. The big upgrade is type-aware linting (recommendedTypeChecked): rules that use TypeScript's type information to catch subtle bugs like floating promises (a missing await — recall lesson 00-11). The React Hooks rules are non-negotiable in React projects.

3. Making them work together

ESLint and Prettier have overlapping concerns (both care about some style). The modern approach: let Prettier own all formatting, and turn off ESLint's formatting rules so they don't fight. ESLint then focuses purely on code correctness.

package.json scripts
"scripts": {
  "lint": "eslint .",
  "lint:fix": "eslint . --fix",
  "format": "prettier --write .",
  "check": "tsc --noEmit && eslint . && prettier --check ."
}
⚡
Pro-tip · The "check" script is your quality gate

A single pnpm check that runs tsc --noEmit (types), eslint (correctness), and prettier --check (formatting) is the exact command you'll run in CI (lesson 03-09). If it passes locally, it passes in CI. Three tools, one gate.

📝
Exercise · Catch a real bug

Set up ESLint with no-floating-promises. Write async function save() {} and call it without await inside another async function. Watch ESLint flag it. Add the await and watch the error clear. You just prevented a classic production race condition at lint time.

🎓 Key takeaways

  • Prettier owns formatting — configure once, format on save, never debate style again.
  • ESLint (flat config, 2026) catches bugs and enforces best practices.
  • Type-aware linting (recommendedTypeChecked) finds subtle issues like floating promises.
  • The React Hooks ESLint rules are essential for any React project.
  • One check script (tsc + eslint + prettier) is your local-and-CI quality gate.
