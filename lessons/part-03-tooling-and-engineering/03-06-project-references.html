Project References & Build Performance

🛠️ Tooling ⏱️ ~26 min ⚙️ Scaling tsc

As a TypeScript codebase grows into many packages, a single tsc run gets slow and the type relationships get murky. Project references split your build into independent, incrementally-compiled units with explicit dependencies — the official way to scale TypeScript across a monorepo. They also make your editor faster and your boundaries clearer.

1. The idea

You give each package its own tsconfig.json and declare which other packages it depends on via references. TypeScript then builds them in order, caches each one (.tsbuildinfo), and only recompiles what changed — like Turborepo, but for type-checking specifically.

packages/app/tsconfig.jsonjson 
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "composite": true,        // required for referenced projects
    "outDir": "dist",
    "rootDir": "src",
    "declaration": true,
    "declarationMap": true    // lets "go to definition" jump to SOURCE, not .d.ts
  },
  "references": [
    { "path": "../utils" }    // app depends on the utils package
  ],
  "include": ["src"]
}
Two flags do the heavy lifting: "composite": true marks a project as referenceable (enabling incremental caching), and "declarationMap": true means cmd-clicking an imported symbol jumps to its source instead of a generated .d.ts. references declares the dependency, mirroring your workspace:* package deps.

2. Building with --build

terminal
tsc --build            # builds all referenced projects in order, cached
tsc --build --watch    # incremental watch across the whole graph
tsc --build --clean    # remove all build outputs
# Only changed projects (and their dependents) recompile.

3. The root solution file

tsconfig.json (repo root)json 
{
  // A "solution" tsconfig: no files of its own, just references.
  "files": [],
  "references": [
    { "path": "packages/utils" },
    { "path": "packages/ui" },
    { "path": "apps/web" }
  ]
}
The root config ties the graph together so tsc --build at the root builds everything in dependency order. Your editor uses it to understand the whole repo, giving you fast, accurate IntelliSense across package boundaries. This is the standard layout for a typed monorepo — exactly what we assemble in lesson 03-10.
✨
2026 context · Turborepo + project references

In practice you combine both: Turborepo orchestrates and caches high-level tasks (build/test/lint across packages), while project references make the TypeScript type-checking within and across those packages fast and incremental. They're complementary layers of the same "only rebuild what changed" philosophy.

📝
Exercise · Reference one package from another

In your workspace, give utils and app each a composite tsconfig, add a reference from app to utils, and a root solution config. Run tsc --build, then touch a file in utils and rebuild — confirm only utils and app recompile.

🎓 Key takeaways

  • Project references split a large TypeScript build into incremental, explicitly-dependent units.
  • composite: true enables referencing + caching; declarationMap makes go-to-definition jump to source.
  • tsc --build compiles the graph in order and only recompiles what changed.
  • A root "solution" tsconfig with only references ties the monorepo together.
  • Pair with Turborepo: references for type-checking, Turbo for task orchestration.
