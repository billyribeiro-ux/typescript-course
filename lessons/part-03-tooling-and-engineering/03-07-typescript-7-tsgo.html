TypeScript 7 "tsgo": The Native Compiler

🛠️ Tooling · 2026 ⏱️ ~22 min 🚀 10× faster

The biggest TypeScript news of the decade: the compiler has been rewritten in Go. The original tsc was written in TypeScript itself; the new native port — nicknamed "tsgo" and shipping as TypeScript 7 — type-checks roughly 10× faster and uses far less memory. This lesson explains what changed, why it matters, and how to try it.

1. Why rewrite the compiler?

As codebases grew to millions of lines, type-checking and editor responsiveness became bottlenecks. The JavaScript-based compiler could only go so far. By porting the same algorithms to Go — a compiled language with true multithreading — the team achieved order-of-magnitude speedups without changing the language itself.

MetricTypical improvement
Full type-check time~10× faster
Editor load (large projects)~8× faster startup
Memory usageRoughly half
🧩
Concept · Same language, new engine

Crucially, the type system and syntax are unchanged. Everything you learned in Parts 1–2 — conditional types, mapped types, inference — works identically. tsgo is a faster implementation of the same compiler. Your code doesn't change; it just checks far faster.

2. Trying it

terminal
pnpm add -D @typescript/native-preview
tsgo --version
Version 7.0.0-dev (native)
tsgo --noEmit          # same flags as tsc, dramatically faster
# A check that took 12s with tsc finishes in ~1.2s with tsgo.
🧭
Note · Status as of June 2026

The native compiler ships as a preview alongside the stable TypeScript 5.9 line. The VS Code extension can opt into the native language service for huge editor responsiveness gains. As it stabilises into the full TypeScript 7 release, it becomes the default. For production today, many teams use tsc (5.9) for emit and tsgo for fast CI type-checks — and you should keep both in mind.

3. What it means for you

  • Faster feedback: CI type-checks that gated your merges in minutes now take seconds.
  • Snappier editor: autocomplete and error squiggles stay instant even in huge repos.
  • Bigger ambitions: advanced type-level programming (Part 2) that was previously too slow to compile becomes practical at scale.
  • No migration cost: because the language is identical, adopting it is just swapping the binary — your types and code are untouched.
⚡
Pro-tip · Mention this in interviews

Knowing why the compiler was rewritten (JS single-threaded performance ceiling → Go's compiled, concurrent execution) and the practical impact (CI speed, editor responsiveness, viability of heavier types) signals you track the ecosystem at a senior level. It's a great "what's new in your field?" answer.

🎓 Key takeaways

  • The TypeScript compiler was rewritten in Go ("tsgo", TypeScript 7) for ~10× faster checking and ~half the memory.
  • The language and type system are unchanged — only the implementation is faster.
  • Try it via @typescript/native-preview; tsgo takes the same flags as tsc.
  • Impact: faster CI, snappier editors, and heavier type-level programming becomes practical.
  • As of mid-2026 it's a preview alongside stable 5.9; adoption is just swapping the binary.
