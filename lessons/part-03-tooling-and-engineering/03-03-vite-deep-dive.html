Vite Deep Dive

🛠️ Tooling ⏱️ ~30 min ⚡ The dev server

Vite is the build tool that powers nearly all modern React development outside of Next.js. It gives you an instant dev server with near-zero startup, lightning-fast hot module replacement, and an optimised production build — all with almost no configuration. Understanding how it works makes you faster and unblocks you when builds misbehave.

1. Why Vite is instant

Old bundlers (Webpack) had to bundle your entire app before the dev server could start — slower as the app grew. Vite flips this: it serves your source files as native ES modules straight to the browser during development, transforming each file on demand. Startup is independent of app size.

🧩
Concept · Two modes, two engines

In dev, Vite uses native ESM + esbuild (written in Go, ~100× faster than JS bundlers) to transform files on demand — no bundling, instant HMR. In production, it bundles with Rollup for an optimised, tree-shaken, code-split output. Best of both: dev speed and prod quality.

2. Creating and running a Vite app

terminal
pnpm create vite@latest my-app --template react-ts
cd my-app && pnpm install
pnpm dev      # dev server at http://localhost:5173 (instant)
pnpm build    # optimised production bundle → dist/
pnpm preview  # serve the production build locally to verify

3. The config file

vite.config.tstypescript 
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import { resolve } from "node:path";

export default defineConfig({
  plugins: [react()],            // enables JSX, Fast Refresh, the React Compiler
  resolve: {
    alias: {
      "@": resolve(__dirname, "src"), // import "@/components/Button"
    },
  },
  server: { port: 3000 },
  build: {
    sourcemap: true,
    rollupOptions: {
      output: {
        manualChunks: { vendor: ["react", "react-dom"] }, // split big deps
      },
    },
  },
});
The two things you'll configure most: plugins (React, and later Tailwind, etc.) and path aliases (so you write @/components instead of ../../../components). Everything else has sensible defaults. The @vitejs/plugin-react also wires up the React Compiler (Part 4).

4. Env vars & static assets

env-and-assets.tstypescript 
// Env vars must be prefixed VITE_ to be exposed to client code:
//   .env →  VITE_API_URL=https://api.example.com
const apiUrl = import.meta.env.VITE_API_URL;       // typed string
const isDev = import.meta.env.DEV;                 // boolean

// Importing assets gives you a URL (handled by the bundler):
import logoUrl from "./logo.svg";   // string URL, hashed for caching

// Glob imports — load many modules at once (great for routes/pages):
const pages = import.meta.glob("./pages/*.tsx");
Security note: only VITE_-prefixed env vars reach the browser — this prevents you from accidentally leaking server secrets into client code. Type them with an ambient declaration (lesson 02-11) for full safety. We use exactly this in Project P03.
📝
Exercise · Scaffold and explore

Create a Vite React-TS app, add the @ path alias, set a VITE_GREETING env var, and render it. Run pnpm build and inspect dist/ — note the hashed filenames (for cache-busting) and the separate vendor chunk. You now understand what ships to users.

🎓 Key takeaways

  • Vite serves native ESM in dev (instant, esbuild-powered) and bundles with Rollup for production.
  • Scaffold with pnpm create vite; dev/build/preview are the core scripts.
  • You'll mostly configure plugins and path aliases — sensible defaults handle the rest.
  • Only VITE_-prefixed env vars reach the client (a safety guardrail).
  • Imports of assets become hashed URLs; glob imports load many modules at once.
