Classes & OOP in TypeScript

🎯 Core ⏱️ ~28 min 🏛️ Objects with behaviour

Classes bundle data and the behaviour that operates on it. TypeScript adds access modifiers, abstract classes, and interface implementation to make classes safe and expressive. Modern React is function-first, so you'll use classes less than in other ecosystems — but they're essential for services, domain models, and understanding the wider JS world.

1. A typed class

class.tstypescript 
class BankAccount {
  // Access modifiers: public (default), private, protected, readonly
  private balance: number;
  readonly owner: string;

  constructor(owner: string, initial: number = 0) {
    this.owner = owner;
    this.balance = initial;
  }

  deposit(amount: number): void {
    if (amount <= 0) throw new Error("Amount must be positive");
    this.balance += amount;
  }

  getBalance(): number {
    return this.balance;
  }
}

const acc = new BankAccount("Ada", 100);
acc.deposit(50);
console.log(acc.getBalance()); // 150
// acc.balance;  // ❌ private — not accessible outside the class
Access modifiers enforce encapsulation: private hides internals, readonly prevents reassignment, protected allows subclass access. balance can only change through deposit — the class controls its own invariants. This is the core value of OOP.

2. Parameter properties & #private

shorthand.tstypescript 
// Parameter properties: declare + assign fields in the constructor signature.
class Point {
  constructor(
    public readonly x: number,
    public readonly y: number
  ) {}
  distanceTo(other: Point): number {
    return Math.hypot(this.x - other.x, this.y - other.y);
  }
}
const d = new Point(0, 0).distanceTo(new Point(3, 4)); // 5

// ECMAScript #private fields — TRULY private at runtime (not just compile-time):
class Vault {
  #secret = "hidden";
  reveal(): string { return this.#secret; }
}
// new Vault().#secret  // ❌ SyntaxError — genuinely inaccessible
Two flavours of private: TypeScript's private is compile-time only (it's gone at runtime). The newer #field is enforced by the JavaScript engine itself — real, hard privacy. Prefer # when you need runtime guarantees.

3. Interfaces, implements & abstract

abstract.tstypescript 
// An interface as a contract a class must fulfil:
interface Shape {
  area(): number;
}

// An abstract base class: can't be instantiated, defines shared structure.
abstract class BaseShape implements Shape {
  abstract area(): number;            // subclasses MUST implement
  describe(): string {                // shared behaviour
    return `This shape has area ${this.area().toFixed(2)}`;
  }
}

class Circle extends BaseShape {
  constructor(private radius: number) { super(); }
  area(): number { return Math.PI * this.radius ** 2; }
}

const c = new Circle(2);
console.log(c.describe()); // "This shape has area 12.57"
// new BaseShape();        // ❌ cannot instantiate an abstract class
The pattern: an interface declares what, an abstract class provides shared how plus required holes for subclasses. implements makes the compiler verify the contract. This underpins service layers and the design patterns in Part 8.
⚛️
Note · Classes vs React

Modern React uses functions and hooks, not class components. You'll still use classes for non-UI concerns — API clients, domain models, error types (class AppError extends Error), and stores. Know them well; reach for them deliberately, not by default.

🎓 Key takeaways

  • Classes bundle data + behaviour; access modifiers (private/readonly/protected) enforce encapsulation.
  • Parameter properties declare and assign fields in the constructor signature.
  • #field gives true runtime privacy; TS private is compile-time only.
  • implements verifies an interface contract; abstract defines shared structure with required holes.
  • React is function-first — use classes for services, models, and error types.
