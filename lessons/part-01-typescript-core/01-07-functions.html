Functions: Parameters, Overloads & this

🎯 Core ⏱️ ~26 min 🔧 Typing behaviour

Functions are where types earn their keep — they document the contract between a piece of logic and everyone who calls it. We'll type parameters and returns precisely, handle optional/default/rest parameters, write function-type aliases, and meet overloads and this typing for the rare cases that need them.

1. Typing parameters and returns

basics.tstypescript 
// Param types are required; return type is usually inferred.
function multiply(a: number, b: number): number {
  return a * b;
}

// Arrow function with a function-type annotation:
const greet: (name: string) => string = (name) => `Hi, ${name}`;

// void = "returns nothing useful":
function logEvent(name: string): void {
  console.log(`event: ${name}`);
}

// A function type alias — reusable, the React event-handler shape:
type ClickHandler = (event: { x: number; y: number }) => void;
const onClick: ClickHandler = (e) => console.log(e.x, e.y);
Annotate inputs; let outputs infer — unless you want the return type as documented contract (recommended for public/exported functions, so a refactor that changes the return type surfaces as an error at the definition, not far away at the call site).

2. Optional, default & rest parameters

params.tstypescript 
// Optional (?) — may be omitted; type becomes T | undefined:
function createUser(name: string, age?: number) {
  return { name, age: age ?? 0 };
}

// Default value — used when the argument is missing:
function paginate(page: number, pageSize: number = 20) {
  return { page, pageSize };
}

// Rest — gather any number of trailing args into a typed array:
function sum(...nums: number[]): number {
  return nums.reduce((t, n) => t + n, 0);
}
sum(1, 2, 3, 4); // 10

// Object parameters (the idiomatic way to pass many options):
function request(opts: { url: string; method?: "GET" | "POST"; retries?: number }) {
  const { url, method = "GET", retries = 0 } = opts;
  return `${method} ${url} (${retries} retries)`;
}
Pro pattern: once a function needs more than ~3 parameters, switch to a single options object. It's self-documenting at the call site, makes parameters order-independent, and lets you add new options without breaking callers — the standard in modern libraries.

3. Function overloads

Overloads let one function present multiple precise call signatures. Use them sparingly — often a union or generic is cleaner — but they're invaluable when the return type depends on the argument shape in ways a union can't express.

overloads.tstypescript 
// Overload signatures (what callers see):
function parse(input: string): string[];
function parse(input: number): number[];
// Implementation signature (hidden from callers, must handle all):
function parse(input: string | number): string[] | number[] {
  if (typeof input === "string") return input.split("");
  return String(input).split("").map(Number);
}

const a = parse("abc"); // typed as string[]
const b = parse(123);   // typed as number[]
How overloads work: you list the public signatures, then one implementation that satisfies them all. Callers only see the public ones, so parse("abc") is precisely string[], not the wider union. Modern TypeScript often prefers generics/conditional types (Part 2) over overloads, but you'll meet overloads in many libraries.

4. Typing this

this-param.tstypescript 
// A fake "this" parameter (erased at runtime) types the calling context:
interface Counter { count: number; }

function increment(this: Counter, by: number) {
  this.count += by;
}

const c: Counter = { count: 0 };
increment.call(c, 5); // ✅ this is typed as Counter
console.log(c.count); // 5

// Arrow functions capture `this` lexically and CANNOT have a this param —
// which is exactly why they're preferred for callbacks in classes/React.
You'll rarely type this directly in React work (arrow functions and function components avoid it), but understanding it explains a class of legacy bugs and why arrow functions became the default for callbacks.

🎓 Key takeaways

  • Type parameters always; type returns for exported functions as a documented contract.
  • ? = optional, = value = default, ...rest: T[] = variadic.
  • Prefer an options object once you have several parameters.
  • Overloads give multiple precise call signatures over one implementation — use sparingly.
  • Arrow functions capture this lexically — the reason they're the default for callbacks.
