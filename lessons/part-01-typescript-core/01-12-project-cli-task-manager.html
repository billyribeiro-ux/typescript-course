Project P01 — The Type-Safe CLI Task Manager

🏗️ Build ⏱️ ~60 min ✅ 35 tests

Everything from Part 1 comes together here. We transform the plain-JS task store from Lesson 00-12 into a real, robust, strictly-typed and fully-tested command-line application. The complete project lives in projects/p01-ts-cli-task-manager/ — build it alongside this walkthrough, file by file.

🏛️
Architecture · pure core, thin edges

The guiding principle: keep logic pure, push side-effects to the edges. types.ts models the domain; tasks.ts and cli.ts are pure functions (no I/O) and hold all the logic; store.ts does file I/O; index.ts is the only place that touches disk and the console. Pure logic is trivially testable — which is why all 35 tests run without ever touching the filesystem or console.

1. The domain model — types.ts

src/types.tstypescript 
export type Priority = "low" | "medium" | "high";

export interface Task {
  readonly id: number;
  readonly title: string;
  readonly done: boolean;
  readonly priority: Priority;
  readonly createdAt: string;
}

export interface NewTaskInput {
  readonly title: string;
  readonly priority?: Priority;
}
Applying the lessons: a string-literal union for Priority (01-03), interface for entities (01-04), and readonly fields (01-04) to signal our immutable update style. The model is the contract everything else is checked against.

2. The pure core — tasks.ts

src/tasks.ts (excerpt)typescript 
import type { NewTaskInput, Priority, Task } from "./types.js";

const PRIORITIES: readonly Priority[] = ["low", "medium", "high"];

// A type guard (01-06) to validate untrusted strings:
export function isPriority(value: unknown): value is Priority {
  return typeof value === "string" && (PRIORITIES as readonly string[]).includes(value);
}

// Immutable add (Part 0 patterns, now typed):
export function addTask(tasks: readonly Task[], input: NewTaskInput): Task[] {
  const title = input.title.trim();
  if (title.length === 0) throw new Error("Task title must not be empty.");
  const task: Task = {
    id: tasks.reduce((max, t) => Math.max(max, t.id), 0) + 1,
    title,
    done: false,
    priority: input.priority ?? "medium",
    createdAt: new Date().toISOString(),
  };
  return [...tasks, task];
}

export function toggleTask(tasks: readonly Task[], id: number): Task[] {
  return tasks.map((t) => (t.id === id ? { ...t, done: !t.done } : t));
}
Note the signatures: every function takes readonly Task[] (01-03) and returns a new Task[] — the compiler now guarantees we never mutate the input. The full file adds removeTask, renameTask, setPriority, filterByStatus, summarize, and sortByPriority.

3. Crossing the boundary — store.ts

src/store.ts (excerpt)typescript 
import { readFile, writeFile, mkdir } from "node:fs/promises";
import type { Task } from "./types.js";
import { isPriority } from "./tasks.js";

// JSON.parse returns `unknown` (01-11) — validate before trusting it:
export function parseTasks(data: unknown): Task[] {
  if (!Array.isArray(data)) return [];
  const result: Task[] = [];
  for (const item of data) {
    if (item && typeof item === "object"
        && typeof (item as any).id === "number"
        && isPriority((item as any).priority) /* ...full checks... */) {
      result.push(item as Task);
    }
  }
  return result;
}

export async function loadTasks(filePath: string): Promise<Task[]> {
  try {
    return parseTasks(JSON.parse(await readFile(filePath, "utf8")));
  } catch (err) {
    if (err instanceof Error && "code" in err && err.code === "ENOENT") return [];
    throw err;
  }
}
This is 01-11 in action: data from disk is unknown, so we validate it with our type guard before letting it into the typed world. Malformed records are silently dropped rather than crashing the app. Robustness by design.

4. The command layer — cli.ts

runCommand is deliberately pure: given the current tasks and the parsed arguments, it returns the next tasks plus the text to print. No I/O means the entire CLI is testable in memory.

src/cli.ts (excerpt)typescript 
export interface CommandResult {
  readonly tasks: Task[];
  readonly output: string;
  readonly changed: boolean;
}

export function runCommand(tasks: readonly Task[], argv: readonly string[]): CommandResult {
  const [command, ...args] = argv;
  switch (command) {
    case "add": {
      const { priority, rest } = takePriorityFlag(args);
      const title = rest.join(" ").trim();
      if (!title) throw new Error('Provide a title, e.g. tasks add "Buy milk".');
      const next = addTask(tasks, priority === undefined ? { title } : { title, priority });
      return { tasks: next, output: `Added ${formatTask(next.at(-1)!)}`, changed: true };
    }
    case "done": { /* toggle by id, with validation */ }
    // ...list, rename, priority, rm, summary, help...
    default:
      throw new Error(`Unknown command "${command}". Run "tasks help".`);
  }
}
Spot the patterns: array destructuring with rest (Part 0), the priority === undefined ? ... : ... dance to satisfy exactOptionalPropertyTypes (01-02), and a switch that throws on unknown commands. Pure in, pure out.

5. The thin edge — index.ts

src/index.tstypescript 
import { loadTasks, saveTasks } from "./store.js";
import { runCommand } from "./cli.js";

const DATA_FILE = process.env.TASKS_FILE ?? join(homedir(), ".tasks", "tasks.json");

async function main(): Promise<void> {
  const tasks = await loadTasks(DATA_FILE);
  try {
    const result = runCommand(tasks, process.argv.slice(2));
    console.log(result.output);
    if (result.changed) await saveTasks(DATA_FILE, result.tasks);
  } catch (err) {
    console.error("✖ " + (err instanceof Error ? err.message : String(err)));
    process.exitCode = 1;
  }
}
void main();
All the I/O lives here, and nowhere else. Load → run pure command → print → save if changed. Errors are caught and turned into a clean message + a non-zero exit code (so scripts and CI can detect failure). This separation is what makes the rest of the app so easy to test.
