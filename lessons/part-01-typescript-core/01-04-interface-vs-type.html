Object Types: interface vs type

🎯 Core ⏱️ ~26 min 🏗️ Modeling data

Objects are how you model the entities in your app — users, products, requests. TypeScript gives you two tools to name object shapes: interface and type. They overlap heavily, but the differences matter. We'll cover optional and readonly properties, index signatures, extension, and a clear professional rule for which to use when.

1. Two ways to name a shape

shapes.tstypescript 
// interface — declares an object shape
interface User {
  id: number;
  name: string;
  email?: string;          // optional (may be absent)
  readonly createdAt: string; // can't be reassigned after creation
}

// type alias — names ANY type, including objects
type UserT = {
  id: number;
  name: string;
};

const u: User = { id: 1, name: "Ada", createdAt: "2026-01-01" };
// u.createdAt = "x";       // ❌ Error: readonly
const e: string | undefined = u.email; // optional → string | undefined
? makes a property optional (its type becomes T | undefined), and readonly forbids reassignment. These two modifiers express a huge amount of intent about your data.

2. The key difference: type does more

interface can only describe object/function shapes. type can alias anything — unions, intersections, primitives, tuples, mapped and conditional types. That breadth is why advanced TypeScript lives almost entirely in type.

type-power.tstypescript 
// Only `type` can do these:
type ID = string | number;             // union
type Pair = [number, number];          // tuple
type Handler = (event: string) => void; // function type
type Nullable<T> = T | null;            // generic alias

// Composition:
type Animal = { name: string };
type Dog = Animal & { breed: string }; // intersection: Animal AND extra fields
const rex: Dog = { name: "Rex", breed: "Lab" };

// `interface` extends with the `extends` keyword instead:
interface AnimalI { name: string; }
interface DogI extends AnimalI { breed: string; }
Intersection (&) merges object types — Dog needs every field of both. This is type's answer to interface extends. Because type handles unions, functions, and generics too, it's the more general tool.

3. interface's superpower: declaration merging

merging.tstypescript 
// Two interfaces with the same name MERGE into one:
interface Window {
  myAppVersion: string;
}
interface Window {
  myAppFlags: Record<string, boolean>;
}
// Now `Window` has BOTH members. This is how you safely augment
// global/library types — impossible with `type` (duplicate = error).

// `type` with a duplicate name is an error:
// type Foo = { a: number };
// type Foo = { b: number }; // ❌ Duplicate identifier 'Foo'
Declaration merging lets libraries (and you) extend existing types — e.g. adding a property to the global Window, or augmenting a third-party module. We use this deliberately in Part 2's "module augmentation" lesson. It's interface's unique value.

4. Index signatures & Record

index-signatures.tstypescript 
// When keys are dynamic, describe them with an index signature:
interface ScoreBoard {
  [playerName: string]: number;
}
const scores: ScoreBoard = { ada: 10, lin: 7 };
scores.newPlayer = 0; // any string key, number value

// The idiomatic shortcut is the built-in Record<Keys, Value>:
type Flags = Record<string, boolean>;
type RolePerms = Record<"admin" | "user", string[]>; // exact keys
const perms: RolePerms = { admin: ["read", "write"], user: ["read"] };
Record<K, V> is the cleanest way to type "an object mapping keys of type K to values of type V". With a union of literals as K, it even forces you to provide exactly those keys — very handy for lookups and config.
🧭
Pro-tip · The rule professionals actually use

Use interface for object shapes that model entities and public APIs (especially if they might be extended or augmented). Use type for everything else — unions, function types, tuples, mapped/conditional types, and any composition. Consistency matters more than the choice; this rule keeps teams sane.

🎓 Key takeaways

  • ? marks optional properties; readonly forbids reassignment.
  • type aliases anything (unions, functions, tuples, generics); interface is object/function shapes only.
  • Compose with & (intersection) or interface extends.
  • interface supports declaration merging — the key to augmenting library/global types.
  • Use Record<K, V> for key→value maps; interface for entities, type for the rest.
