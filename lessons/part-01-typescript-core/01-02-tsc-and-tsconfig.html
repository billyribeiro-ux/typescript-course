Installing TS, tsc & tsconfig.json

🎯 Core · setup ⏱️ ~26 min ⚙️ The compiler

To use TypeScript you need its compiler, tsc, and a configuration file, tsconfig.json, that tells tsc exactly how strict to be and what to produce. Configuring this well is a genuine professional skill — the right settings catch far more bugs. We'll set up a project the way a principal engineer does on day one.

1. A fresh TypeScript project

terminal
mkdir ts-playground && cd ts-playground
pnpm init                       # create package.json
pnpm add -D typescript tsx @types/node # compiler + runner + Node types
pnpm tsc --init                 # create a tsconfig.json
pnpm tsc --version
Version 5.9.x
📦
Note · Install TypeScript per-project, not globally

Always add typescript as a dev dependency of the project (-D). That pins the exact version, so your build is reproducible and teammates use the same compiler. tsx lets you run .ts files directly during development without a build step.

2. Compile and run

src/main.tstypescript 
function add(a: number, b: number): number {
  return a + b;
}

const result: number = add(2, 3);
console.log(`2 + 3 = ${result}`);

// Try breaking it: add("2", 3) — tsc will refuse to compile.
terminal
pnpm tsc                # type-check + emit JS to the outDir
node dist/main.js       # run the compiled output → 2 + 3 = 5
# ...or skip the build during dev:
pnpm tsx src/main.ts    # run the .ts directly

3. The professional tsconfig.json

The default config is too lax. Here is a strict, modern 2026 baseline. Read every line — the comments explain why each option earns its place. This is close to what we use in every project in this course.

tsconfig.jsonjson 
{
  "compilerOptions": {
    "target": "ES2022",            // JS feature level to emit
    "module": "NodeNext",          // module system (Node ESM)
    "moduleResolution": "NodeNext",
    "lib": ["ES2023"],             // built-in APIs available
    "outDir": "dist",
    "rootDir": "src",

    "strict": true,                // turns on the whole strict family ↓
    "noUncheckedIndexedAccess": true, // arr[i] is T | undefined — forces a check
    "exactOptionalPropertyTypes": true, // distinguishes missing vs undefined
    "noImplicitOverride": true,
    "noFallthroughCasesInSwitch": true,
    "verbatimModuleSyntax": true,  // explicit import type / export type

    "esModuleInterop": true,
    "skipLibCheck": true,          // skip type-checking node_modules .d.ts (faster)
    "forceConsistentCasingInFileNames": true,
    "declaration": true,           // emit .d.ts type files
    "sourceMap": true
  },
  "include": ["src"]
}
The headline option is "strict": true — never turn it off. It enables strictNullChecks (the big one), noImplicitAny, and more. The extras like noUncheckedIndexedAccess push you toward genuinely safe code. We use exactly these in Project P01.
⚡
Pro-tip · strictNullChecks is the one that matters most

With strict mode, null and undefined are not assignable to other types unless you explicitly allow them. This single setting eliminates the infamous "cannot read property of undefined" crash as a class of bug. If you ever inherit a loose codebase, turning this on is the highest-value change you can make.

4. Watch mode & the editor

You rarely run tsc by hand during development — your editor type-checks continuously, and build tools (Vite, Next.js) handle compilation. But tsc --noEmit is the gold-standard "is the whole project type-correct?" check you'll run in CI.

terminal
pnpm tsc --watch     # re-check on every save
pnpm tsc --noEmit    # type-check only, emit nothing (CI gate)
📝
Exercise · Feel strict mode bite

In a strict project, write function first(arr: string[]) { return arr[0].toUpperCase(); }. With noUncheckedIndexedAccess on, arr[0] is string | undefined and this won't compile. Fix it safely (hint: check for undefined first, or use arr.at(0) with a guard). Notice how the compiler forced you to handle the empty-array case you'd have otherwise forgotten.

🎓 Key takeaways

  • Install typescript per-project as a dev dependency; pin the version.
  • tsc type-checks and emits JS; tsx runs .ts directly in dev.
  • tsconfig.json controls everything — always set "strict": true.
  • Add noUncheckedIndexedAccess and friends for genuinely safe code.
  • tsc --noEmit is your CI "is it type-correct?" gate.
