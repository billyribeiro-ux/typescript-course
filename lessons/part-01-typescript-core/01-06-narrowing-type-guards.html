Literal Types, Narrowing & Type Guards

🎯 Core · high-value ⏱️ ~28 min 🎯 Control-flow analysis

Narrowing is how TypeScript follows your code's logic to figure out a more specific type at each point — and it's where the language feels almost magical. Master narrowing and type guards, and unions stop being obstacles and become a precise tool. This is one of the highest-value skills in the language.

1. Literal types

literals.tstypescript 
// A literal type is a single, exact value used AS a type:
type Yes = "yes";
let answer: Yes = "yes";   // only "yes" is allowed

// const infers the narrowest (literal) type; let infers the wide type:
const exact = "hello";     // type is "hello" (literal)
let loose = "hello";       // type is string (widened)

// as const freezes an entire structure to its literal types:
const config = { mode: "dark", retries: 3 } as const;
// config.mode is "dark" (not string); config is deeply readonly
Why this matters: literal types are what make string-literal unions work. The difference between const (narrow) and let (wide) inference is subtle but crucial — and as const is your tool for locking values to their exact literal types.

2. Narrowing with control flow

TypeScript performs control-flow analysis: as it reads your ifs and typeofs, it narrows the type within each branch automatically.

narrowing.tstypescript 
function describe(value: string | number | null) {
  if (value === null) {
    return "nothing";          // here value is null
  }
  if (typeof value === "string") {
    return value.toUpperCase(); // here value is string
  }
  return value.toFixed(2);      // here value is number (the only option left)
}

// Truthiness narrowing removes null/undefined:
function shout(text?: string) {
  if (!text) return "(silence)"; // text is string | undefined → narrowed away
  return text.toUpperCase();     // text is string
}

// The `in` operator narrows by property presence:
type A = { kind: "a"; a: number };
type B = { kind: "b"; b: number };
function pick(x: A | B) {
  return "a" in x ? x.a : x.b;   // narrows on which property exists
}
The tools of narrowing: typeof (for primitives), === against literals and null, truthiness (if (x)), the in operator (for properties), and instanceof (for classes). TypeScript tracks all of them through your code's branches.

3. Custom type guards (is)

When built-in narrowing isn't enough, you write your own type guard: a function whose return type is a special arg is Type predicate. It teaches the compiler how to narrow.

type-guards.tstypescript 
type Cat = { type: "cat"; meow: () => void };
type Dog = { type: "dog"; bark: () => void };
type Pet = Cat | Dog;

// A user-defined type guard — note the return type "pet is Cat":
function isCat(pet: Pet): pet is Cat {
  return pet.type === "cat";
}

function speak(pet: Pet) {
  if (isCat(pet)) {
    pet.meow();   // ✅ narrowed to Cat by our guard
  } else {
    pet.bark();   // ✅ narrowed to Dog
  }
}

// Guarding unknown data (e.g. from JSON) is a common, vital use:
function isStringArray(x: unknown): x is string[] {
  return Array.isArray(x) && x.every((i) => typeof i === "string");
}
This is exactly the isPriority guard in Project P01. Type guards are how you safely cross the boundary from untyped data (JSON, form input, unknown) into your typed world. They turn runtime checks into compile-time knowledge.
✨
2026 · Inferred type predicates (TS 5.5+)

Since TypeScript 5.5, the compiler can often infer a type predicate for you. A function like const isDefined = (x) => x !== undefined used in .filter() now narrows automatically — no explicit x is T needed in many cases. Less boilerplate, same safety.

4. The never trick for exhaustiveness

exhaustive.tstypescript 
type Status = "idle" | "loading" | "done";

function label(status: Status): string {
  switch (status) {
    case "idle": return "Ready";
    case "loading": return "Working...";
    case "done": return "Complete";
    default:
      // If a new Status is added later and not handled,
      // `status` won't be `never` here and this line errors —
      // a compile-time reminder to handle the new case!
      const _exhaustive: never = status;
      return _exhaustive;
  }
}
The exhaustiveness check is a professional staple: assign the value to a never in the default branch. If every case is handled, the value is never and it compiles; if you forget one, the compiler stops you. This makes your unions future-proof.

🎓 Key takeaways

  • Literal types are exact values used as types; const infers narrow, let wide, as const freezes.
  • Narrowing uses typeof, ===, truthiness, in, and instanceof to refine types per branch.
  • Type guards (x is T) teach the compiler to narrow — your bridge from unknown to typed.
  • TS 5.5+ can infer predicates automatically in many cases.
  • The never exhaustiveness check guarantees you handle every union case, forever.
