Server Actions & Mutations

🌐 Full-stack · pivotal ⏱️ ~32 min ✍️ Writing data

Server Actions are the killer feature of modern Next.js: server-side functions you can call directly from your components and forms — no API route, no fetch, no manual serialization. They give you fully type-safe mutations from button to database, and integrate with the React 19 Actions you learned in lesson 04-12. This is the future of full-stack React.

1. A Server Action

actions.tstsx 
"use server";   // ← marks every export as a Server Action

import { z } from "zod";
import { db } from "@/lib/db";
import { revalidatePath } from "next/cache";

const CreateTodo = z.object({ title: z.string().min(1) });

export async function createTodo(formData: FormData) {
  // Validate untrusted input with Zod (06-09 / your P02!):
  const parsed = CreateTodo.safeParse({ title: formData.get("title") });
  if (!parsed.success) return { error: "Title is required" };

  await db.todo.create({ data: parsed.data }); // runs ONLY on the server
  revalidatePath("/todos");                      // refresh the cached page
  return { success: true };
}
"use server" makes a function callable from the client but executed on the server. Next.js handles the network round-trip invisibly — you just call the function. Always validate the input with Zod (it's untrusted!), do your database work, then revalidatePath so the UI reflects the change. No API endpoint, no fetch boilerplate.

2. Calling it from a form

TodoForm.tsxtsx 
"use client";
import { useActionState } from "react";        // lesson 04-12!
import { createTodo } from "./actions.js";

export function TodoForm() {
  const [state, formAction, isPending] = useActionState(
    async (_prev: unknown, formData: FormData) => createTodo(formData),
    null
  );
  return (
    <form action={formAction}>            {/* pass the action straight to the form */}
      <input name="title" />
      <button disabled={isPending}>{isPending ? "Saving…" : "Add"}</button>
      {state && "error" in state && <p role="alert">{state.error}</p>}
    </form>
  );
}
This is React 19 Actions (04-12) wired to the server. The <form action={...}> calls the Server Action directly; useActionState gives you the result, pending state, and errors. The same hook you used for client-only forms now performs a fully type-safe server mutation — with progressive enhancement (the form even works before JS loads).

3. Why this is revolutionary

  • No API layer for mutations: call server functions directly; Next handles transport.
  • End-to-end type safety: the action's argument and return types flow to the client with no codegen.
  • Progressive enhancement: forms with action work without JavaScript.
  • Composes with optimistic UI: wrap with useOptimistic (04-12) for instant feedback.
⚠️
Gotcha · Actions are public endpoints

A Server Action is effectively a public API endpoint — anyone can call it. Always validate input (Zod) and check authorization inside the action (is this user allowed to do this?). Never trust that it's only called from your UI. Security lives in the action, not the form.

🎓 Key takeaways

  • Server Actions ("use server") are server functions callable from components/forms — no API route or fetch.
  • Wire them to <form action={...}> and React 19's useActionState (04-12) for pending/errors.
  • They give end-to-end type safety with no codegen and support progressive enhancement.
  • Always validate (Zod) and authorize inside the action — it's a public endpoint.
  • Compose with useOptimistic + revalidatePath for instant, consistent UIs.
