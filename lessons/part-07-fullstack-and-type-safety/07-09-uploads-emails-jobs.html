File Uploads, Emails & Background Jobs

🌐 Full-stack ⏱️ ~28 min 🧰 Real-world plumbing

Real SaaS apps need three pieces of plumbing beyond CRUD: uploading files, sending emails, and running work in the background. Doing these well — without blocking requests or losing data — is what makes an app production-grade. We'll cover the patterns and the 2026 tools.

1. File uploads

📤
Concept · Upload direct to storage

Don't stream large files through your server. Instead, your server issues a short-lived presigned URL, and the browser uploads directly to object storage (S3, R2, Vercel Blob). Your server just records the resulting URL. Libraries like UploadThing wrap this whole flow with typed, ready-made components. Always validate file type and size.

presigned.tstypescript 
"use server";
// 1. Server: validate + create a presigned upload URL (expires soon).
export async function getUploadUrl(input: { name: string; type: string; size: number }) {
  if (input.size > 5_000_000) throw new Error("Max 5MB");
  if (!input.type.startsWith("image/")) throw new Error("Images only");
  return createPresignedPutUrl(input.name); // from your storage SDK
}
// 2. Browser PUTs the file straight to storage using that URL.
// 3. Server stores the final URL in the DB (a separate action).

2. Transactional email

email.tstypescript 
import { Resend } from "resend";
const resend = new Resend(process.env.RESEND_API_KEY);

// React Email lets you write emails as React components!
export async function sendWelcome(to: string, name: string) {
  await resend.emails.send({
    from: "hello@app.com",
    to,
    subject: "Welcome!",
    react: <WelcomeEmail name={name} />,   // a typed React Email component
  });
}
Transactional emails (welcome, password reset, receipts) go through a provider like Resend or Postmark. React Email lets you author them as React components — the same JSX skills, rendered to email-safe HTML. Don't send email on the request path if it's slow; queue it (below).

3. Background jobs

⏳
Concept · Don't make the user wait

Slow or retry-able work (sending emails, processing images, syncing to a CRM, generating reports) should run outside the request. A job queue accepts the task and processes it reliably with retries. Modern serverless-friendly tools: Inngest, Trigger.dev, or a queue like BullMQ. The request returns instantly; the work happens in the background.

job.tstypescript 
// Define a durable, retry-able job (Inngest-style):
export const onSignup = inngest.createFunction(
  { id: "send-welcome", retries: 3 },
  { event: "user/signup" },
  async ({ event, step }) => {
    await step.run("send-email", () => sendWelcome(event.data.email, event.data.name));
    await step.sleep("wait", "1d");
    await step.run("send-tips", () => sendTips(event.data.email));
  }
);
// Your action just fires the event: inngest.send({ name: "user/signup", data });
A Server Action fires an event and returns; the job runs reliably with retries. Steps are durable — if one fails, it retries without re-running completed steps, and you can even sleep for days between steps (drip campaigns). This decoupling keeps requests fast and work resilient.

🎓 Key takeaways

  • Uploads: issue a presigned URL, upload direct to object storage, store the URL; validate type/size.
  • Email: use a provider (Resend/Postmark); author with React Email; don't block requests on it.
  • Background jobs run slow/retry-able work outside the request (Inngest/Trigger.dev/BullMQ).
  • Decoupling keeps requests fast and work reliable (retries, durable steps).
  • These three are the standard plumbing of any production SaaS.
