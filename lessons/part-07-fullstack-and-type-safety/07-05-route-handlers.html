Route Handlers & APIs

🌐 Full-stack ⏱️ ~26 min 🔌 HTTP endpoints

Server Actions cover most mutations, but you still need real HTTP API endpoints for webhooks, third-party integrations, mobile clients, and public APIs. Next.js Route Handlers (route.ts files) let you build them with the standard web Request/Response APIs you can use anywhere.

1. A Route Handler

app/api/products/route.tstsx 
import { NextResponse } from "next/server";
import { z } from "zod";
import { db } from "@/lib/db";

// GET /api/products?category=...
export async function GET(request: Request) {
  const { searchParams } = new URL(request.url);
  const category = searchParams.get("category");
  const products = await db.product.findMany({ where: category ? { category } : {} });
  return NextResponse.json(products);
}

// POST /api/products
const CreateProduct = z.object({ name: z.string().min(1), price: z.number().positive() });
export async function POST(request: Request) {
  const parsed = CreateProduct.safeParse(await request.json());
  if (!parsed.success) {
    return NextResponse.json({ error: parsed.error.issues }, { status: 400 });
  }
  const product = await db.product.create({ data: parsed.data });
  return NextResponse.json(product, { status: 201 });
}
Export a function per HTTP method (GET, POST, PATCH, DELETE). You get a standard Request and return a Response (or NextResponse for helpers). Same validation discipline: parse the body with Zod, return proper status codes (400 for bad input, 201 for created). This is a real, framework-agnostic web API.

3. Webhooks & dynamic segments

app/api/webhooks/stripe/route.tstsx 
export async function POST(request: Request) {
  const signature = request.headers.get("stripe-signature");
  const body = await request.text();           // raw body for signature check
  // verify signature, then handle the event type...
  return new Response("ok", { status: 200 });
}

// Dynamic segment: app/api/users/[id]/route.ts
export async function GET(_req: Request, { params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;                 // params is async in Next 15
  return Response.json(await db.user.findById(id));
}
Route Handlers are the standard way to receive webhooks (Stripe, GitHub, etc.) — you need the raw body and headers for signature verification. Dynamic segments ([id]) work just like pages; note that in Next 15 params is a promise you await.

🎓 Key takeaways

  • Route Handlers (route.ts) build real HTTP APIs with web Request/Response.
  • Export a function per method (GET/POST/…); validate bodies with Zod and return proper status codes.
  • Use them for webhooks, third-party/mobile clients, and public REST — not for your own UI mutations (use Actions).
  • Dynamic [id] segments work like pages; params is async in Next 15.
  • Choose the right tool: Server Components (read), Actions (UI mutations), Route Handlers (external), tRPC (typed internal API).
