Deployment & Observability

🌐 Full-stack ⏱️ ~26 min 🚀 Ship & watch

Shipping is just the start — you also need to see what your app does in production. This lesson covers deploying a Next.js app, the hosting options, and the observability essentials (logs, metrics, error tracking, analytics) that let you find and fix problems before users complain. A senior engineer owns their software in production, not just in the repo.

Concept · Preview deployments

Connect your Git repo and every push to main deploys to production; every PR gets its own preview URL with the changes live. Combined with the CI gate (03-09), nothing reaches production that didn't pass types/lint/tests. This is the modern, safe deployment flow.

2. The four pillars of observability

  • Logs: structured, searchable records of what happened (use a logger, not console.log, in production).
  • Metrics: numbers over time — request rate, latency, error rate, resource usage.
  • Traces: follow one request across services to find where time/errors go (OpenTelemetry).
  • Error tracking: capture exceptions with stack traces and context (Sentry).

3. Error tracking with Sentry

instrumentationtypescript 
import * as Sentry from "@sentry/nextjs";

Sentry.init({
  dsn: process.env.SENTRY_DSN,
  tracesSampleRate: 0.1,          // sample 10% of requests for performance traces
});

// Now uncaught errors (and the ones your error.tsx boundaries catch, 05-04)
// are reported with stack traces, the user, the request, and a session replay.
// You learn about the bug before the user emails you.
Error tracking turns "the app is broken" into an actionable report — the exact line, the input, the user, even a replay of their session. Wire it into your error boundaries (componentDidCatch, 05-04) and Server Actions. Add web analytics (Vercel Analytics, PostHog) and Core Web Vitals monitoring (Part 8) to complete the picture.

Exercise · Deploy + observe

Deploy a Next.js app to Vercel, connected to your repo so PRs get preview URLs and main auto-deploys. Add Sentry and trigger a test error to confirm it appears in the dashboard with a stack trace. Add a structured logger and a /api/health endpoint.

🎓 Key takeaways

  • Deploy via Git-connected hosts (Vercel/Netlify/Cloudflare) with preview deploys per PR, gated by CI.
  • Observability has four pillars: logs, metrics, traces, error tracking.
  • Use a real logger (not console.log) and Sentry for exceptions with full context.
  • Wire error tracking into your error boundaries (05-04) and Server Actions.
  • A senior engineer owns their app in production — sees problems before users report them.
