Databases with Drizzle ORM

🌐 Full-stack ⏱️ ~32 min 🗄️ Type-safe SQL

Real apps need a database. Drizzle is the modern TypeScript ORM: you define your schema in TypeScript, and it gives you a fully-typed query builder that reads like SQL, plus automatic migrations. Unlike heavier ORMs, Drizzle is thin, fast, and SQL-first — you always know exactly what query runs. It's the 2026 favourite for type-safe data access.

1. Define the schema in TypeScript

schema.tstypescript 
import { pgTable, serial, text, integer, boolean, timestamp } from "drizzle-orm/pg-core";

export const users = pgTable("users", {
  id: serial("id").primaryKey(),
  email: text("email").notNull().unique(),
  name: text("name").notNull(),
});

export const posts = pgTable("posts", {
  id: serial("id").primaryKey(),
  title: text("title").notNull(),
  published: boolean("published").notNull().default(false),
  authorId: integer("author_id").notNull().references(() => users.id),
  createdAt: timestamp("created_at").notNull().defaultNow(),
});

// The TYPES come from the schema — your single source of truth:
export type User = typeof users.$inferSelect;   // row shape
export type NewUser = typeof users.$inferInsert; // insert shape
Your schema IS your types. $inferSelect/$inferInsert derive the row and insert types directly from the table definition (the "derive types from implementation" principle again — 02-04). Change a column and every query that touches it is re-checked. No separate type definitions to drift.

2. Type-safe queries

queries.tstypescript 
import { drizzle } from "drizzle-orm/node-postgres";
import { eq, and, desc } from "drizzle-orm";
import { users, posts } from "./schema.js";

const db = drizzle(process.env.DATABASE_URL!);

// SELECT — fully typed result, autocompleted columns:
const published = await db
  .select()
  .from(posts)
  .where(and(eq(posts.published, true)))
  .orderBy(desc(posts.createdAt))
  .limit(10);

// INSERT — typed to NewPost, returns the created row:
const [created] = await db.insert(posts)
  .values({ title: "Hello", authorId: 1 })
  .returning();

// JOIN with relations:
const withAuthors = await db.select({ title: posts.title, author: users.name })
  .from(posts).innerJoin(users, eq(posts.authorId, users.id));
The query builder mirrors SQL but is fully typed. Columns autocomplete, where/orderBy are type-checked against your schema, and results are typed to exactly the columns you selected. You always know the SQL being generated (no hidden N+1 surprises). Drizzle also offers a relational query API for nested fetches.

3. Migrations

terminal
pnpm drizzle-kit generate   # diff schema → generate SQL migration files
pnpm drizzle-kit migrate    # apply migrations to the database
pnpm drizzle-kit studio     # a GUI to browse your data
⚡
Pro-tip · Drizzle vs Prisma

Drizzle is SQL-first, thin, fast, and edge-compatible — you write queries that look like SQL. Prisma is higher-level with its own schema language and a generated client. Both are excellent and fully typed; Drizzle has gained huge momentum in 2026 for its transparency and performance. We use Drizzle in the SaaS project (P07).

🎓 Key takeaways

  • Drizzle defines your DB schema in TypeScript; types are inferred ($inferSelect/$inferInsert).
  • The query builder mirrors SQL but is fully typed — columns autocomplete, results are precise.
  • drizzle-kit generates and applies migrations from your schema diff; Studio browses data.
  • SQL-first and thin — you always know the query that runs (no hidden N+1).
  • Drizzle (SQL-first) vs Prisma (higher-level) — both typed; we use Drizzle in P07.
