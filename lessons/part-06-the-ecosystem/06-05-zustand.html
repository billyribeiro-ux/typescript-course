Client State with Zustand

🧩 Ecosystem ⏱️ ~28 min 🐻 Simple global state

You used Zustand in Project P04; now we go deeper. It's the most popular lightweight state manager — minimal boilerplate, no providers, great TypeScript support. We'll cover selectors and performance, slices for organising larger stores, middleware (persist, devtools), and exactly when to choose it over Context or Redux.

1. Selectors & re-render performance

selectors.tsxtsx 
import { create } from "zustand";
import { useShallow } from "zustand/shallow";

interface Store { count: number; user: { name: string }; inc: () => void; }
const useStore = create<Store>((set) => ({
  count: 0,
  user: { name: "Ada" },
  inc: () => set((s) => ({ count: s.count + 1 })),
}));

// ✅ Select ONLY what you need — this component re-renders only when count changes:
const count = useStore((s) => s.count);

// ✅ Selecting multiple values? Use useShallow to avoid the new-object loop (P04!):
const { count2, name } = useStore(useShallow((s) => ({ count2: s.count, name: s.user.name })));

// Actions are stable references — select them freely:
const inc = useStore((s) => s.inc);
Selectors are how Zustand stays fast. A component subscribes only to the slice it selects and re-renders only when that slice changes. Selecting multiple values returns a new object each render — wrap it in useShallow (the fix for P04's infinite-loop pitfall). Actions never change identity, so selecting them is free.

2. Slices for larger stores

slices.tsxtsx 
import { create, type StateCreator } from "zustand";

interface CartSlice { items: string[]; addItem: (i: string) => void; }
interface UiSlice { sidebarOpen: boolean; toggleSidebar: () => void; }

const createCartSlice: StateCreator<CartSlice & UiSlice, [], [], CartSlice> = (set) => ({
  items: [],
  addItem: (i) => set((s) => ({ items: [...s.items, i] })),
});
const createUiSlice: StateCreator<CartSlice & UiSlice, [], [], UiSlice> = (set) => ({
  sidebarOpen: false,
  toggleSidebar: () => set((s) => ({ sidebarOpen: !s.sidebarOpen })),
});

const useStore = create<CartSlice & UiSlice>((...a) => ({
  ...createCartSlice(...a),
  ...createUiSlice(...a),
}));
Slices keep a growing store organised. Each feature is a typed slice; you compose them into one store with an intersection type (02-05). Components still select across the whole store, but the code is modular. This scales a single Zustand store to a large app without it becoming a mess.

3. Middleware: persist & devtools

middleware.tsxtsx 
import { create } from "zustand";
import { persist, devtools } from "zustand/middleware";

const useStore = create<Store>()(
  devtools(                          // Redux DevTools integration
    persist(                         // auto-save to localStorage
      (set) => ({
        theme: "light",
        toggle: () => set((s) => ({ theme: s.theme === "light" ? "dark" : "light" })),
      }),
      { name: "app-storage" }        // storage key
    )
  )
);
// State now survives reloads AND is inspectable in Redux DevTools.
Middleware adds superpowers with one wrapper. persist saves the store to localStorage (or any storage) and rehydrates on load; devtools connects it to the Redux DevTools time-travel debugger. This is how you'd add persistence to the P04 Kanban board in one line.
⚡
Pro-tip · When to use what

useState/useReducer for local state. Context for low-frequency global values (theme, auth). Zustand for most shared client state — simple and fast. Redux Toolkit (06-07) for large apps needing strict structure, middleware, and team conventions. TanStack Query for server state. Don't put server data in Zustand — that's Query's job.

🎓 Key takeaways

  • Selectors subscribe a component to a slice; multi-value selects need useShallow.
  • Slices + intersection types organise a large store modularly.
  • Middleware: persist (localStorage) and devtools (time-travel) add power in one wrapper.
  • Use Zustand for most shared client state; not for server state (use Query).
  • Pick the right tool: local → useState; global-low-freq → Context; shared → Zustand; big/structured → Redux.
