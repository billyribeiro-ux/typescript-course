Atomic State with Jotai

🧩 Ecosystem ⏱️ ~24 min ⚛️ Bottom-up state

Jotai takes a different philosophy from Zustand: instead of one big store, you build state from tiny atoms that compose. Atoms can derive from other atoms (like a spreadsheet), and components only re-render when an atom they use changes. It's an elegant model for fine-grained, derived state — worth knowing as the leading alternative approach.

1. Atoms

atoms.tsxtsx 
import { atom, useAtom, useAtomValue } from "jotai";

// An atom is a single piece of state — defined OUTSIDE components:
const countAtom = atom(0);
const nameAtom = atom("Ada");

function Counter() {
  // useAtom is like useState, but the state is shared via the atom:
  const [count, setCount] = useAtom(countAtom);
  return <button onClick={() => setCount((c) => c + 1)}>{count}</button>;
}

function Display() {
  const count = useAtomValue(countAtom); // read-only subscription
  return <p>Count is {count}</p>;       // re-renders only when countAtom changes
}
An atom is a unit of state any component can share. useAtom reads + writes (like useState), useAtomValue reads only. Components subscribe to specific atoms, so unrelated state changes never re-render them — fine-grained reactivity without manual selectors. No provider needed for the default store.

2. Derived atoms

derived.tsxtsx 
import { atom } from "jotai";

const priceAtom = atom(100);
const quantityAtom = atom(2);

// A derived atom computes from others — recomputes automatically:
const totalAtom = atom((get) => get(priceAtom) * get(quantityAtom)); // read-only

// A writable derived atom (read + write logic):
const discountedAtom = atom(
  (get) => get(totalAtom) * 0.9,
  (get, set, newTotal: number) => set(priceAtom, newTotal / get(quantityAtom))
);
// Change priceAtom or quantityAtom and totalAtom updates like a spreadsheet cell.
Derived atoms are the magic. atom((get) => ...) creates a value computed from other atoms; when any dependency changes, it recomputes and re-renders only its consumers. It's a reactive dependency graph — like a spreadsheet. Async atoms (returning a promise) integrate with Suspense (05-03) too.
⚡
Pro-tip · Zustand vs Jotai

Zustand is "top-down": one store, select slices. Jotai is "bottom-up": compose many atoms. Jotai shines when you have lots of independent, derived pieces of state (form fields, editor cells, granular UI) and want to avoid selector boilerplate. Both are excellent; the choice is largely stylistic. Many apps don't need either — useState + Context + Query covers a lot.

🎓 Key takeaways

  • Jotai builds state from small composable atoms (bottom-up), vs Zustand's single store (top-down).
  • useAtom (read/write) and useAtomValue (read) subscribe to specific atoms — fine-grained re-renders.
  • Derived atoms compute from other atoms and recompute automatically — a reactive graph like a spreadsheet.
  • Great for lots of independent/derived state; async atoms integrate with Suspense.
  • Zustand vs Jotai is largely stylistic — both are first-rate.
