Routing with React Router 7

🧩 Ecosystem ⏱️ ~30 min 🗺️ Navigation

A single-page app needs client-side routing: mapping URLs to components, navigating without full page reloads, and reading params. React Router 7 is the most widely used router, and it has grown into a full framework. This lesson covers the core: defining routes, links, nested layouts, URL params, and data loaders.

1. Defining routes

router.tsxtsx 
import { createBrowserRouter, RouterProvider } from "react-router";

const router = createBrowserRouter([
  {
    path: "/",
    element: <RootLayout />,        // a shared shell (nav, footer)
    children: [
      { index: true, element: <Home /> },             // "/"
      { path: "products", element: <Products /> },    // "/products"
      { path: "products/:id", element: <Product /> }, // "/products/42"
      { path: "*", element: <NotFound /> },            // catch-all 404
    ],
  },
]);

function App() {
  return <RouterProvider router={router} />;
}
Routes are a tree. Each route maps a URL path to an element. children create nested routes that render inside their parent's <Outlet />. :id is a dynamic segment (a URL param), index is the default child, and * catches unmatched URLs for a 404.

2. Layouts, Outlet & Links

layout.tsxtsx 
import { Outlet, NavLink } from "react-router";

function RootLayout() {
  return (
    <div>
      <nav>
        {/* Link/NavLink navigate WITHOUT a full page reload: */}
        <NavLink to="/" end>Home</NavLink>
        <NavLink to="/products"
          className={({ isActive }) => (isActive ? "active" : "")}>
          Products
        </NavLink>
      </nav>
      <main>
        <Outlet />   {/* child route renders here */}
      </main>
    </div>
  );
}
Use <Link>/<NavLink>, never a raw <a> for internal navigation — they update the URL and swap components without reloading the page. NavLink knows when it's active (for styling). The parent layout renders shared chrome and an <Outlet /> where the matched child appears.

3. Params, navigation & loaders

params-and-loader.tsxtsx 
import { useParams, useNavigate, useLoaderData } from "react-router";

// A loader runs BEFORE the route renders — data is ready on first paint:
async function productLoader({ params }: { params: { id?: string } }) {
  const res = await fetch(`/api/products/${params.id}`);
  return res.json();
}

function Product() {
  const { id } = useParams();              // read the :id segment
  const product = useLoaderData();          // data from the loader
  const navigate = useNavigate();           // programmatic navigation

  return (
    <div>
      <h1>Product {id}</h1>
      <button onClick={() => navigate("/products")}>Back</button>
      <button onClick={() => navigate(-1)}>History back</button>
    </div>
  );
}
Loaders fetch data before rendering — eliminating the "render, then useEffect, then spinner" waterfall (04-07). useParams reads URL segments, useNavigate moves programmatically (after a form submit, say). React Router 7 can also run in "framework mode" with file routes, SSR, and code splitting — converging with Next.js (Part 7).

2026 · React Router vs TanStack Router

React Router 7 is the established, ubiquitous choice (and the basis of Remix). TanStack Router (next lesson) is the newer challenger with best-in-class type-safe routing — fully-typed params and search params. We teach both so you can choose per project.

Exercise · A small multi-page app

Build a Vite app with a root layout (nav + Outlet), a home page, a /users list, and a /users/:id detail page that reads the param. Add a 404 catch-all and a "back" button with useNavigate. Use a loader to fetch the user list.

🎓 Key takeaways

  • Routes map URLs to components as a tree; nested children render in the parent's <Outlet />.
  • Navigate with <Link>/<NavLink> (no reload) and useNavigate programmatically.
  • :param segments are read with useParams; * catches 404s.
  • Loaders fetch data before render, avoiding effect-based waterfalls.
  • React Router 7 is ubiquitous; TanStack Router (next) adds full type-safety.
