Animation with Motion & TanStack Table

🧩 Ecosystem ⏱️ ~30 min 🎬 Polish & data grids

Two libraries that elevate a UI from functional to professional. Motion (formerly Framer Motion) adds production-grade animations with a declarative API. TanStack Table is a headless data-grid engine for sorting, filtering, and pagination — you bring the markup. Both showcase the patterns from Part 5 (declarative APIs, headless design).

1. Motion: declarative animation

motion.tsxtsx 
import { motion, AnimatePresence } from "motion/react";

function Toast({ items }: { items: { id: string; text: string }[] }) {
  return (
    <AnimatePresence>          {/* animates items entering AND leaving */}
      {items.map((item) => (
        <motion.div
          key={item.id}
          initial={{ opacity: 0, y: 20 }}     // start state
          animate={{ opacity: 1, y: 0 }}      // animate to
          exit={{ opacity: 0, x: 100 }}       // on removal
          transition={{ type: "spring", stiffness: 300 }}
        >
          {item.text}
        </motion.div>
      ))}
    </AnimatePresence>
  );
}
// motion.div is a div you can animate via props. AnimatePresence handles
// exit animations (impossible with plain CSS when an element unmounts).
Motion makes animation declarative. You describe initial/animate/ exit states and the transition; Motion handles the frames. AnimatePresence solves the hard problem of animating elements as they leave the DOM (e.g. removing a Kanban card from P04). It also does gestures, drag, layout animations, and scroll-linked effects.

2. TanStack Table: headless data grids

table.tsxtsx 
import { useReactTable, getCoreRowModel, getSortedRowModel,
         flexRender, type ColumnDef } from "@tanstack/react-table";

interface User { id: number; name: string; role: string; }
const columns: ColumnDef<User>[] = [
  { accessorKey: "name", header: "Name" },
  { accessorKey: "role", header: "Role" },
];

function UsersTable({ data }: { data: User[] }) {
  const table = useReactTable({
    data, columns,
    getCoreRowModel: getCoreRowModel(),
    getSortedRowModel: getSortedRowModel(),  // enable sorting
  });
  return (
    <table>
      <thead>{table.getHeaderGroups().map((hg) => (
        <tr key={hg.id}>{hg.headers.map((h) => (
          <th key={h.id} onClick={h.column.getToggleSortingHandler()}>
            {flexRender(h.column.columnDef.header, h.getContext())}
          </th>))}</tr>))}
      </thead>
      <tbody>{table.getRowModel().rows.map((row) => (
        <tr key={row.id}>{row.getVisibleCells().map((cell) => (
          <td key={cell.id}>{flexRender(cell.column.columnDef.cell, cell.getContext())}</td>
        ))}</tr>))}</tbody>
    </table>
  );
}
TanStack Table is the logic, not the look (05-08 headless). You define typed columns and feed data; the hook gives you sorting, filtering, pagination, grouping, and virtualization state — and you render the <table> markup however you like (styled with Tailwind/shadcn). Fully typed to your row shape, it powers admin tables and data grids of any complexity.
⚡
Pro-tip · Accessibility & reduced motion

Respect prefers-reduced-motion — Motion has a useReducedMotion() hook to tone down animations for users who request it (05-09). And keep data tables semantic (<table>/<th scope>) so they're screen-reader friendly. Polish should never cost accessibility.

🎓 Key takeaways

  • Motion animates declaratively via initial/animate/exit; AnimatePresence handles exit animations.
  • Motion also does gestures, drag, and layout animations — production-grade polish.
  • TanStack Table is a headless data-grid engine: typed columns + sorting/filtering/pagination state; you render the markup.
  • Both are fully typed and compose with Tailwind/shadcn for styling.
  • Respect prefers-reduced-motion and keep tables semantic for accessibility.
