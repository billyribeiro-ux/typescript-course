Redux Toolkit Fundamentals

🧩 Ecosystem · enterprise ⏱️ ~34 min 🏢 Structured state

Redux is the original predictable state container, and Redux Toolkit (RTK) is the modern, official way to use it — eliminating the old boilerplate. It's the standard at large companies for its strict structure, powerful middleware, and unmatched DevTools. You'll meet it constantly in enterprise codebases, so you must know it well. Everything you learned about reducers (02-07, 04-09) applies directly.

1. A slice

counterSlice.tstsx 
import { createSlice, type PayloadAction } from "@reduxjs/toolkit";

interface CounterState { value: number; }
const initialState: CounterState = { value: 0 };

const counterSlice = createSlice({
  name: "counter",
  initialState,
  reducers: {
    // RTK uses Immer — you "mutate" a draft, it produces an immutable update:
    increment: (state) => { state.value += 1; },
    decrement: (state) => { state.value -= 1; },
    addBy: (state, action: PayloadAction<number>) => { state.value += action.payload; },
  },
});

export const { increment, decrement, addBy } = counterSlice.actions;
export default counterSlice.reducer;
A slice bundles state + reducers + auto-generated actions. The magic: RTK includes Immer, so you write "mutating" code (state.value += 1) and get a correct immutable update under the hood — no spread gymnastics. Each reducer's action creator is generated for you (increment(), addBy(5)). This is the reducer pattern from 04-09, minus the boilerplate.

2. The store & typed hooks

store.tstsx 
import { configureStore } from "@reduxjs/toolkit";
import { useDispatch, useSelector } from "react-redux";
import counterReducer from "./counterSlice.js";

export const store = configureStore({
  reducer: { counter: counterReducer }, // combine slices here
});

// Infer the types FROM the store (don't hand-write them):
export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;

// Pre-typed hooks for the whole app:
export const useAppDispatch = useDispatch.withTypes<AppDispatch>();
export const useAppSelector = useSelector.withTypes<RootState>();
Types are derived from the store (lesson 02-04's "derive types from implementation") — RootState and AppDispatch come from ReturnType, so they're always accurate. The pre-typed useAppSelector/useAppDispatch give every component full type safety without re-annotating.

3. Using it in components

Counter.tsxtsx 
import { useAppDispatch, useAppSelector } from "./store.js";
import { increment, addBy } from "./counterSlice.js";

function Counter() {
  const value = useAppSelector((s) => s.counter.value); // read (typed)
  const dispatch = useAppDispatch();                     // dispatch actions
  return (
    <div>
      <p>{value}</p>
      <button onClick={() => dispatch(increment())}>+1</button>
      <button onClick={() => dispatch(addBy(5))}>+5</button>
    </div>
  );
}
// Wrap your app in <Provider store={store}> at the root.
Read with a selector, write by dispatching an action. The flow is the discriminated- union reducer pattern (02-07) at app scale: actions describe what happened, reducers compute the new state, components select what they need. Redux DevTools then gives you a full, time-travelable log of every action — invaluable for debugging complex apps.
✨
2026 · When Redux still wins

For most apps, Zustand or Context + Query is lighter. But Redux Toolkit remains the choice for large teams and complex domains: strict conventions everyone follows, powerful middleware (sagas/listeners), the best DevTools, and RTK Query (next lesson) for data fetching. Knowing it is essential for enterprise and most job interviews.

🎓 Key takeaways

  • Redux Toolkit is the modern, low-boilerplate Redux — the enterprise standard.
  • createSlice bundles state + reducers + auto actions, using Immer so you write "mutating" updates safely.
  • Derive RootState/AppDispatch from the store; use pre-typed hooks.
  • Read with useAppSelector, write by dispatching actions — the reducer pattern at scale.
  • Reducers are pure → easy to unit-test; DevTools give time-travel debugging.
