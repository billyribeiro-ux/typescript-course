Forms at Scale: React Hook Form + Zod

🧩 Ecosystem · essential ⏱️ ~32 min 📝 Real forms

Controlled forms (04-06) are fine for small cases but get verbose and re-render on every keystroke. React Hook Form (RHF) manages forms with minimal re-renders and clean APIs, and Zod (the library you built a clone of in P02!) defines your validation schema and your form's type from one source. This combo is the 2026 standard for forms.

1. A Zod schema is the single source of truth

schema.tstsx 
import { z } from "zod";

// Define validation rules once...
export const signupSchema = z.object({
  email: z.string().email("Enter a valid email"),
  password: z.string().min(8, "At least 8 characters"),
  age: z.number().int().min(18, "Must be 18+"),
  terms: z.literal(true, { message: "You must accept the terms" }),
});

// ...and derive the TypeScript type from it (just like P02's Infer!):
export type SignupForm = z.infer<typeof signupSchema>;
// { email: string; password: string; age: number; terms: true }
This is exactly your Project P02. z.infer<typeof schema> is the same "one declaration → validator + type" idea you built — z.infer is Zod's Infer. The schema validates at runtime and types your form at compile time. Change a rule, and the type updates everywhere automatically.

2. Wiring RHF + Zod

SignupForm.tsxtsx 
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { signupSchema, type SignupForm } from "./schema.js";

function Signup() {
  const { register, handleSubmit, formState: { errors, isSubmitting } } =
    useForm<SignupForm>({ resolver: zodResolver(signupSchema) });

  const onSubmit = async (data: SignupForm) => {  // data is validated + typed
    await api.signup(data);
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input type="email" {...register("email")} />
      {errors.email && <p role="alert">{errors.email.message}</p>}

      <input type="password" {...register("password")} />
      {errors.password && <p role="alert">{errors.password.message}</p>}

      <button disabled={isSubmitting}>Sign up</button>
    </form>
  );
}
register connects an input to the form with almost no code — and unlike controlled inputs, typing doesn't re-render the whole form (RHF uses refs internally). The zodResolver runs your schema on submit, populating errors with typed, per-field messages. handleSubmit only calls onSubmit with fully-validated, typed data.

3. Why this scales

  • Performance: uncontrolled inputs + ref tracking mean minimal re-renders, even on huge forms.
  • One source of truth: the Zod schema is validation + types + (often) the API contract. No drift.
  • Composability: reuse schemas (e.g. share an addressSchema), build multi-step wizards, and validate the same schema on the server (Part 7).
  • Accessibility: pair with the a11y patterns (05-09) — labelled inputs, role="alert" errors, aria-invalid.

2026 · Zod 4 & the validation landscape

Zod 4 brings big performance gains and a smaller bundle. Alternatives like Valibot (ultra-light) and ArkType exist, and the Standard Schema spec lets libraries interoperate. The concepts are exactly what you built in P02 — you understand them from the inside.

🎓 Key takeaways

  • React Hook Form manages forms with minimal re-renders via register + uncontrolled inputs.
  • Zod defines validation and the form type (z.infer) — the exact pattern from your P02 project.
  • zodResolver connects them; handleSubmit yields fully-validated, typed data.
  • Errors are typed and per-field — render them accessibly (role="alert").
  • One schema = validation + types + (often) the API contract, reusable on the server.
