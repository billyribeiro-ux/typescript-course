RTK Query for Data Fetching

🧩 Ecosystem ⏱️ ~30 min 🔌 Redux's data layer

RTK Query is Redux Toolkit's built-in data-fetching solution — its answer to TanStack Query, integrated with the Redux store. If your app already uses Redux, RTK Query gives you caching, auto-generated hooks, and cache invalidation without adding another library. You define an "API slice" and it generates fully-typed hooks for you.

1. Defining an API slice

api.tstsx 
import { createApi, fetchBaseQuery } from "@reduxjs/toolkit/query/react";

interface Product { id: number; name: string; price: number; }

export const api = createApi({
  reducerPath: "api",
  baseQuery: fetchBaseQuery({ baseUrl: "/api/" }),
  tagTypes: ["Product"],
  endpoints: (build) => ({
    getProducts: build.query<Product[], void>({
      query: () => "products",
      providesTags: ["Product"],          // this data is tagged "Product"
    }),
    addProduct: build.mutation<Product, Partial<Product>>({
      query: (body) => ({ url: "products", method: "POST", body }),
      invalidatesTags: ["Product"],       // adding invalidates the list → auto refetch
    }),
  }),
});

// RTK Query GENERATES typed hooks from your endpoints:
export const { useGetProductsQuery, useAddProductMutation } = api;
You describe endpoints; RTK Query generates the hooks. getProducts becomes useGetProductsQuery(), fully typed to return Product[]. The tagTypes/providesTags/invalidatesTags system is declarative cache invalidation: a mutation tagged to invalidate "Product" automatically refetches every query that provides it. No manual invalidateQueries calls.

2. Using the generated hooks

Products.tsxtsx 
import { useGetProductsQuery, useAddProductMutation } from "./api.js";

function Products() {
  const { data, isLoading, isError } = useGetProductsQuery();
  const [addProduct, { isLoading: isAdding }] = useAddProductMutation();

  if (isLoading) return <Spinner />;
  if (isError) return <p>Failed to load</p>;
  return (
    <>
      <ul>{data!.map((p) => <li key={p.id}>{p.name}</li>)}</ul>
      <button disabled={isAdding}
        onClick={() => addProduct({ name: "New", price: 9.99 })}>
        Add (list auto-refetches)
      </button>
    </>
  );
}
The hooks look just like TanStack Query's — data/isLoading/ isError for queries, a trigger + status for mutations. The difference: RTK Query lives in your Redux store (visible in DevTools, integrated with other slices). Add the API's reducer + middleware to configureStore and you're done.
⚡
Pro-tip · RTK Query vs TanStack Query

Already using Redux? RTK Query is the natural, integrated choice — one store, one DevTools, the tag-based invalidation. Not using Redux? TanStack Query is lighter and framework-agnostic. Both are excellent caches for server state; don't use both. The concepts (cache keys/tags, invalidation, generated/wrapped hooks) transfer between them.

Exercise · A tagged CRUD API

Build an API slice for "todos" with getTodos, addTodo, toggleTodo, deleteTodo. Use a "Todo" tag so mutations automatically refetch the list. Wire the generated hooks into a component and watch the list update after each mutation with zero manual cache code.

🎓 Key takeaways

  • RTK Query is Redux Toolkit's integrated data layer — caching + generated typed hooks.
  • Define an API slice with endpoints; it generates useXxxQuery/useXxxMutation hooks.
  • Tags (providesTags/invalidatesTags) give declarative, automatic cache invalidation.
  • Choose RTK Query if you're on Redux; TanStack Query otherwise — don't use both.
  • The caching concepts transfer between the two.
