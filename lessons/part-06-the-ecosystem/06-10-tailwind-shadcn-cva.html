Styling: Tailwind v4, shadcn/ui & CVA

🧩 Ecosystem ⏱️ ~32 min 🎨 Modern styling

The dominant 2026 styling stack: Tailwind CSS v4 (utility classes), shadcn/ui (copy-paste accessible components built on Radix), and CVA (type-safe style variants). Together they let you build beautiful, consistent, accessible UIs fast — and you own all the code. This is how modern product teams ship polished interfaces.

1. Tailwind: utility-first CSS

tailwind.tsxtsx 
// Style with utility classes directly in JSX — no separate CSS files:
function Card() {
  return (
    <div className="rounded-xl border border-gray-200 bg-white p-6 shadow-sm
                    hover:shadow-md transition-shadow">
      <h2 className="text-xl font-bold text-gray-900">Title</h2>
      <p className="mt-2 text-gray-600">Body text</p>
      <button className="mt-4 rounded-lg bg-blue-600 px-4 py-2 text-white
                         hover:bg-blue-700 focus-visible:ring-2">
        Action
      </button>
    </div>
  );
}
// Responsive (md:), state (hover:/focus:), dark mode (dark:) — all inline.
Utility classes keep styles colocated with markup — no naming things, no switching files, no dead CSS. Prefixes handle responsive (md:), states (hover:), and dark mode (dark:). Tailwind v4 is configured in CSS (@theme) and is far faster. It feels verbose at first, then becomes the quickest way to build UI you'll ever use.

2. CVA: type-safe variants

button-variants.tsxtsx 
import { cva, type VariantProps } from "class-variance-authority";

// Define a button's style variants in a type-safe way:
const button = cva("rounded-lg font-medium transition-colors", {
  variants: {
    intent: {
      primary: "bg-blue-600 text-white hover:bg-blue-700",
      ghost: "bg-transparent text-blue-600 hover:bg-blue-50",
    },
    size: { sm: "px-3 py-1 text-sm", md: "px-4 py-2", lg: "px-6 py-3 text-lg" },
  },
  defaultVariants: { intent: "primary", size: "md" },
});

type ButtonProps = VariantProps<typeof button> & { children: React.ReactNode };
function Button({ intent, size, children }: ButtonProps) {
  return <button className={button({ intent, size })}>{children}</button>;
}
// <Button intent="ghost" size="lg"> — autocompleted & type-checked variants!
CVA turns Tailwind classes into typed component variants. VariantProps extracts the variant names as a type (your Part 2 utility-type skills!), so <Button intent="ghost"> is autocompleted and a typo is a compile error. This is how you build a consistent, type-safe design system on top of Tailwind.

3. shadcn/ui: components you own

🧩
Concept · Copy-paste, not a dependency

shadcn/ui isn't an installed component library — you run a CLI that copies accessible, Tailwind-styled components (built on Radix primitives + CVA) into your codebase. You own and can edit every line. No version lock-in, no fighting a library's API — just great defaults you customise. It's the most popular way to build React UIs in 2026.

terminal
pnpm dlx shadcn@latest init          # set up Tailwind + config
pnpm dlx shadcn@latest add button dialog # copy components into src/components/ui
# Now import { Button } from "@/components/ui/button" — and edit it freely.
⚡
Pro-tip · The cn() helper

Combine clsx (conditional classes) + tailwind-merge (resolves conflicting utilities) into a cn() helper — shadcn includes it. cn("p-2", isActive && "bg-blue-600", className) merges cleanly and lets consumers override. It's the glue for flexible, composable styled components.

🎓 Key takeaways

  • Tailwind v4: utility classes colocated with markup; prefixes for responsive/state/dark mode.
  • CVA turns Tailwind into type-safe variants; VariantProps types your component (Part 2 skills).
  • shadcn/ui copies accessible Radix+Tailwind components into your repo — you own and edit them.
  • The cn() helper (clsx + tailwind-merge) composes and overrides classes cleanly.
  • This stack is the fastest path to polished, consistent, accessible UIs in 2026.
