Server State with TanStack Query

🧩 Ecosystem · pivotal ⏱️ ~34 min 🔄 The data layer

Recall the painful useEffect fetching from lesson 04-07 — loading flags, error handling, race conditions, no caching. TanStack Query solves all of it. It's the single most important library in the React ecosystem: it manages server state (data that lives on a server) with caching, background refetching, and deduplication built in. Master this and your data layer becomes effortless.

1. The key insight: server state is different

🧩
Concept · Server state ≠ client state

Client state (form inputs, toggles, the Kanban board) is owned by your app — use useState/Zustand. Server state is a cache of data that actually lives elsewhere: it can be stale, shared across components, and needs refetching. TanStack Query is built specifically for server state — don't manage it with useState.

2. useQuery

useQuery.tsxtsx 
import { useQuery } from "@tanstack/react-query";

function Products() {
  const { data, isPending, isError, error } = useQuery({
    queryKey: ["products"],                 // unique cache key
    queryFn: async () => {                  // how to fetch
      const res = await fetch("/api/products");
      if (!res.ok) throw new Error("Failed to load");
      return res.json() as Promise<Product[]>;
    },
    staleTime: 60_000,                       // data is "fresh" for 60s
  });

  if (isPending) return <Spinner />;
  if (isError) return <p>Error: {error.message}</p>;
  return <ul>{data.map((p) => <li key={p.id}>{p.name}</li>)}</ul>;
}
Compare this to the 04-07 effect mess. One useQuery gives you data, isPending, isError, automatic caching by queryKey, deduplication (10 components, one request), background refetching, and retries — all for free. The queryKey is the identity of this data in the cache.

3. What you get automatically

  • Caching: the same queryKey shares one cached result across the app.
  • Deduplication: simultaneous requests for the same key are collapsed into one.
  • Background refetch: stale data refetches on window focus, reconnect, or interval — your UI silently stays fresh.
  • Retries: failed requests retry with backoff.
  • Garbage collection: unused cache entries are cleaned up.

4. Setup & query keys

setup.tsxtsx 
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";

const queryClient = new QueryClient();

function App() {
  return (
    <QueryClientProvider client={queryClient}>
      <YourApp />
    </QueryClientProvider>
  );
}

// Query keys are arrays — include every input the query depends on:
useQuery({ queryKey: ["product", id], queryFn: () => fetchProduct(id) });
useQuery({ queryKey: ["products", { category, page }], queryFn: ... });
// When a key value changes (e.g. id), Query fetches + caches separately.
Query keys are the heart of the cache. Treat them like a dependency array: include every variable the query depends on. ["product", id] caches each product separately and refetches automatically when id changes — no useEffect needed. A consistent key convention (e.g. a "query key factory") keeps a large app organised.

Exercise · Replace your effect-fetch

Take the weather dashboard (P03) and replace the hand-rolled useWeather hook with a useQuery keyed by the city. Notice how loading/error/caching come for free, how switching cities back and forth is instant (cached), and how much code disappears.

🎓 Key takeaways

  • Server state (a cache of remote data) is different from client state — use TanStack Query for it.
  • useQuery gives data + loading/error states + caching, dedup, background refetch, retries — automatically.
  • Query keys are arrays identifying cached data; include every input the query depends on.
  • Wrap your app in a QueryClientProvider; tune freshness with staleTime.
  • It replaces the entire useEffect-fetch pattern (04-07) — far less code, far more robust.
