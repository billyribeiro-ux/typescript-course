Portals, Refs & Imperative Handles

🚀 Advanced ⏱️ ~26 min 🚪 Breaking out

Two escape hatches for the cases where the normal tree isn't enough. Portals render children into a different DOM location (for modals, tooltips, toasts) while keeping them in the React tree. useImperativeHandle lets a parent call methods on a child via a ref. Used sparingly, these solve real UI problems cleanly.

1. Portals — render elsewhere in the DOM

Modal.tsxtsx 
import { createPortal } from "react-dom";
import type { ReactNode } from "react";

function Modal({ children, onClose }: { children: ReactNode; onClose: () => void }) {
  // Render into document.body, ESCAPING any parent overflow:hidden / z-index trap:
  return createPortal(
    <div className="overlay" onClick={onClose}>
      <div className="dialog" role="dialog" aria-modal="true"
           onClick={(e) => e.stopPropagation()}>
        {children}
      </div>
    </div>,
    document.body
  );
}
// Even though <Modal> lives deep in the tree, its DOM appears at the top of
// <body> — so it overlays everything and isn't clipped by ancestors.
Portals solve the "modal trapped inside a clipped container" problem. The component stays in the React tree (so context, state, and events still work — events even bubble through the React tree, not the DOM tree!), but its DOM renders wherever you choose. Essential for modals, dropdowns, tooltips, and toasts that must visually escape their parent.

2. useImperativeHandle — expose methods

imperative.tsxtsx 
import { useImperativeHandle, useRef, type Ref } from "react";

interface VideoHandle { play: () => void; pause: () => void; }

// React 19: ref is just a prop (no forwardRef needed).
function Video({ ref, src }: { ref: Ref<VideoHandle>; src: string }) {
  const el = useRef<HTMLVideoElement>(null);
  useImperativeHandle(ref, () => ({
    play: () => el.current?.play(),
    pause: () => el.current?.pause(),
  }), []);
  return <video ref={el} src={src} />;
}

function Player() {
  const videoRef = useRef<VideoHandle>(null);
  return (
    <>
      <Video ref={videoRef} src="/clip.mp4" />
      <button onClick={() => videoRef.current?.play()}>Play</button>
    </>
  );
}
This exposes a small, intentional imperative API. Instead of leaking the raw DOM node, useImperativeHandle lets the child publish just the methods it chooses (play/pause). Use it for genuinely imperative things — media playback, focus, scroll, animations — that don't fit the declarative model. Keep the surface tiny.
⚠️
Gotcha · Reach for these last

Imperative handles are an escape hatch — most parent→child communication should be props, not method calls. If you find yourself adding many imperative methods, reconsider whether the state should live in the parent instead. Portals, by contrast, are the standard, expected solution for overlays.

🎓 Key takeaways

  • Portals (createPortal) render children into a different DOM node while staying in the React tree.
  • Use portals for modals, tooltips, dropdowns, toasts — anything that must escape parent clipping/z-index.
  • Events still bubble through the React tree from a portal, and context/state work normally.
  • useImperativeHandle exposes a small, intentional method API to a parent via ref (React 19: ref is a prop).
  • Both are escape hatches — prefer props/state; use these for genuinely imperative needs.
