Testing React: Testing Library & Playwright

🚀 Advanced · essential ⏱️ ~34 min ✅ Confidence at scale

You tested components in Project P03; now we cover React testing properly. The philosophy: test behaviour the way a user experiences it, not implementation details. We'll use React Testing Library (component/integration tests) and Playwright (end-to-end browser tests) — the standard 2026 stack — and the accessible-query approach that ties testing to the a11y you just learned.

1. The Testing Library philosophy

🧩
Concept · Query by accessibility, not by class

Testing Library makes you find elements the way a user (or screen reader) would: by role, label, and text — not by CSS classes or component internals. This means your tests survive refactors (you can rewrite the implementation freely) and double as accessibility checks (if you can't query by role, neither can assistive tech).

2. A component test

Counter.test.tsxtsx 
import { describe, it, expect } from "vitest";
import { render, screen } from "@testing-library/react";
import userEvent from "@testing-library/user-event";
import { Counter } from "./Counter.js";

describe("<Counter>", () => {
  it("increments when the button is clicked", async () => {
    const user = userEvent.setup();
    render(<Counter />);

    // Query by accessible role + name (like a user would):
    const button = screen.getByRole("button", { name: /increment/i });
    expect(screen.getByText("Count: 0")).toBeInTheDocument();

    await user.click(button);                 // simulate a real click
    expect(screen.getByText("Count: 1")).toBeInTheDocument();
  });
});
// getByRole / getByLabelText / getByText / findBy* (async) are your tools.
// userEvent simulates real user interactions (typing, clicking, tabbing).
This is exactly the pattern from Project P03. render mounts the component in jsdom, screen.getByRole finds elements accessibly, and userEvent simulates real interactions. Assert on what the user sees (text, roles), never on internal state or props. Use findBy* (async) when content appears after a delay/fetch.

3. Querying cheat-sheet

QueryUse for
getByRole("button", {name})Buttons, links, headings, inputs (preferred)
getByLabelTextForm fields by their label
getByTextVisible text content
findByRoleAsync — waits for an element to appear
queryByRoleAssert something is absent (returns null)

4. End-to-end tests with Playwright

e2e/signup.spec.tstypescript 
import { test, expect } from "@playwright/test";

test("a user can sign up", async ({ page }) => {
  await page.goto("/signup");
  await page.getByLabel("Email").fill("ada@example.com");
  await page.getByLabel("Password").fill("hunter2!");
  await page.getByRole("button", { name: "Create account" }).click();
  await expect(page.getByText("Welcome, ada")).toBeVisible();
});
// Playwright drives a REAL browser (Chromium/Firefox/WebKit), testing the
// whole app end-to-end: routing, network, the actual rendered DOM.
Playwright tests the real thing. It launches an actual browser and exercises full user journeys across pages, network, and real rendering — catching integration bugs unit tests can't. Note it uses the same accessible queries (getByLabel, getByRole) as Testing Library, so the skill transfers directly.
🧪
Pro-tip · The testing trophy

Modern guidance favours mostly integration tests (a component + its real children, behaviour tested via RTL), a solid base of unit tests for pure logic (P01/P02 style), a few high-value E2E tests (Playwright) for critical journeys, and static checks (TypeScript + ESLint) as the foundation. Test behaviour and contracts, not implementation.

📝
Exercise · Test a form three ways

For a login form: 1) unit-test the validation function; 2) RTL-test that submitting empty shows an error and submitting valid calls onSubmit (use accessible queries + userEvent); 3) write a Playwright E2E that logs in against a running dev server. Notice how the same accessible queries appear at every level.

🎓 Key takeaways

  • Test behaviour as users experience it, not implementation details — refactor-proof tests.
  • React Testing Library: query by role/label/text, interact with userEvent, assert on visible output.
  • Use findBy* for async UI and queryBy* to assert absence.
  • Playwright drives a real browser for end-to-end journeys, using the same accessible queries.
  • Balance the layers: static → unit → integration → a few E2E. Accessible UIs are easier to test.
