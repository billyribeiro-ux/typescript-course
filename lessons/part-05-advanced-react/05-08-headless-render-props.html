Headless Components & Render Props

🚀 Advanced ⏱️ ~28 min 🎭 Logic vs presentation

The most reusable components separate behaviour from appearance. Headless components provide all the logic, state, and accessibility but no styling — you supply the markup. This is the philosophy behind the most popular 2026 libraries (Radix, TanStack, Headless UI). We'll cover the headless hook approach and the classic render-prop pattern that preceded it.

1. The headless hook approach (modern)

useDisclosure.tsxtsx 
import { useId, useState } from "react";

// All the LOGIC + a11y wiring, ZERO markup/styles. The caller renders.
function useDisclosure(initial = false) {
  const [open, setOpen] = useState(initial);
  const panelId = useId();
  return {
    open,
    toggle: () => setOpen((o) => !o),
    close: () => setOpen(false),
    // "Prop getters" return the props to spread onto your elements:
    triggerProps: {
      "aria-expanded": open,
      "aria-controls": panelId,
      onClick: () => setOpen((o) => !o),
    },
    panelProps: { id: panelId, hidden: !open },
  } as const;
}

// You own 100% of the markup and styling:
function FAQ() {
  const d = useDisclosure();
  return (
    <div>
      <button {...d.triggerProps} className="my-button">What is headless?</button>
      <div {...d.panelProps} className="my-panel">Logic without looks.</div>
    </div>
  );
}
Headless = behaviour as a hook, presentation as your problem. The hook owns state, accessibility (aria-expanded, linked ids via useId), and keyboard handling; you bring the markup and styles via "prop getters" you spread onto elements. This is why TanStack Table and Query, Radix, and React Aria are so flexible — they never dictate how things look.

2. Render props (the classic pattern)

render-props.tsxtsx 
import { useState } from "react";

// A component whose `children` is a FUNCTION that receives state:
function MousePosition({ children }: {
  children: (pos: { x: number; y: number }) => React.ReactNode;
}) {
  const [pos, setPos] = useState({ x: 0, y: 0 });
  return (
    <div onMouseMove={(e) => setPos({ x: e.clientX, y: e.clientY })}>
      {children(pos)}   {/* hand the state to the caller's render function */}
    </div>
  );
}

// The consumer decides what to render with the shared state:
<MousePosition>
  {({ x, y }) => <p>Mouse at {x}, {y}</p>}
</MousePosition>;
Render props share logic by passing a render function as children. It was the dominant reuse pattern before hooks. You'll still encounter it (e.g. some chart and virtualization libraries), and it's occasionally the cleanest fit — but for most "reuse stateful logic" needs, a custom hook (04-11) is simpler. Knowing both lets you read any codebase.
✨
2026 · The headless ecosystem

The dominant pattern today is headless: Radix UI and React Aria for accessible primitives, TanStack Table/Query/Virtual for headless data UIs, and shadcn/ui (Part 6) which gives you styled-but-editable components built on Radix. You'll consume these constantly — understanding the headless philosophy is essential.

🎓 Key takeaways

  • Headless components/hooks provide behaviour + accessibility but no styling — you own the markup.
  • Prop getters (e.g. triggerProps) bundle the props/handlers/ARIA to spread onto elements.
  • Render props share logic by passing a render function as children — the pre-hooks pattern.
  • Prefer custom hooks for logic reuse today; know render props for reading older/library code.
  • The 2026 ecosystem (Radix, React Aria, TanStack, shadcn) is built on the headless philosophy.
