Project P04 — The Kanban Board

🏗️ Build ⏱️ ~90 min ✅ 15 tests

A Kanban board built with React 19 and Zustand — your first dedicated state-management library. We model the board as normalized state, expose immutable actions, and test the whole store without rendering anything. The complete project is in projects/p04-kanban-board/ with 15 passing tests.

1. Why Zustand, and normalized state

🐻
Concept · A store outside the component tree

useState/useReducer live inside components; Zustand holds state in an external store any component can read via a hook — no providers, no boilerplate. We store data normalized (cards keyed by id, columns holding ordered id lists), the same shape Redux uses (Part 6). Moves and lookups become trivial, and the store is pure data + functions — easy to test.

2. The store

src/store/board.ts (excerpt)typescript 
import { create } from "zustand";

export interface Card { readonly id: string; readonly title: string; }
export interface Column { readonly id: string; readonly title: string; readonly cardIds: readonly string[]; }

export const useBoard = create<BoardState>((set) => ({
  ...initialBoard,
  addCard: (columnId, title) =>
    set((state) => {
      const clean = title.trim();
      if (!clean) return state;                       // ignore empty
      const id = nextId();
      return {
        cards: { ...state.cards, [id]: { id, title: clean } },        // immutable add
        columns: state.columns.map((c) =>
          c.id === columnId ? { ...c, cardIds: [...c.cardIds, id] } : c),
      };
    }),
  moveCard: (cardId, toColumnId, toIndex) =>
    set((state) => {
      const without = removeFromColumns(state.columns, cardId);       // pull out
      return { columns: without.map((c) => c.id === toColumnId
        ? { ...c, cardIds: insertAt(c.cardIds, cardId, toIndex) }     // re-insert
        : c) };
    }),
}));
Every action is an immutable update (spread/map/filter — the Part 0 patterns, again). Components read slices with a selector: useBoard((s) => s.columns). Zustand re-renders only the components whose selected slice changed. No context, no provider — just a hook.

3. The Zustand v5 trap (a real bug we hit)

⚠️
Gotcha · Don't return new arrays/objects from a selector

Building this project, the test suite hit an infinite render loop. The cause: useBoard((s) => column.cardIds.map((id) => s.cards[id])) returns a new array every call, so useSyncExternalStore always sees a "changed" snapshot → re-render → new array → loop. The fix: select a stable reference (the cards record) and derive the array in render, or use useShallow. This is the #1 Zustand v5 pitfall — now you'll never hit it.

src/components/Column.tsx (the fix)tsx 
// ❌ new array each call → infinite loop:
// const cards = useBoard((s) => column.cardIds.map((id) => s.cards[id]));

// ✅ select a stable reference, derive in render:
const cardsById = useBoard((s) => s.cards);
const cards = column.cardIds.map((id) => cardsById[id]).filter((c) => c != null);

4. Testing the store + components

tests (excerpt)tsx 
// Store logic — no rendering, just call actions and assert (resetBoard each test):
get().moveCard("a1", "done");
expect(columnById("done").cardIds).toEqual(["a3", "a1"]);

// Component — accessible queries + userEvent (05-10):
await user.click(screen.getByRole("button", { name: /move "design the schema" right/i }));
expect(useBoard.getState().columns.find(c => c.id === "doing")!.cardIds).toContain("a1");
The store tests are pure and instant — call actions, assert on getState(). The component tests use accessible role/label queries (05-10) and userEvent, resetting the store before each test. Because state is normalized data + pure actions, testing is as easy as P01/P02.

🎓 Key takeaways

  • Zustand holds state outside the tree; components read slices via a selector hook — no providers.
  • Model state normalized (entities by id + ordered id lists) for O(1) moves/lookups and easy testing.
  • Actions are immutable updates — the same spread/map/filter patterns from Part 0.
  • Never return a new array/object from a selector (infinite loop) — select stable refs or use useShallow.
