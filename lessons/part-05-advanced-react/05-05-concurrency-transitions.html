Concurrent Features & Transitions

🚀 Advanced ⏱️ ~28 min ⚡ Responsive UIs

React's concurrent capabilities let it interrupt and prioritise rendering so the UI stays responsive during heavy updates. The practical tools are useTransition and useDeferredValue — they mark some updates as low-priority so urgent ones (like typing) never get blocked. This is how you keep an app buttery-smooth under load.

1. The problem: urgent vs non-urgent updates

When you type in a search box that filters a huge list, two updates happen: the input value (urgent — must feel instant) and the filtered list (non-urgent — can lag a frame). Without prioritisation, the expensive list re-render blocks the keystroke, and typing feels laggy.

2. useTransition

useTransition.tsxtsx 
import { useState, useTransition } from "react";

function Search({ allItems }: { allItems: string[] }) {
  const [query, setQuery] = useState("");
  const [results, setResults] = useState<string[]>(allItems);
  const [isPending, startTransition] = useTransition();

  function handleChange(e: React.ChangeEvent<HTMLInputElement>) {
    const next = e.target.value;
    setQuery(next);                       // URGENT: update the input immediately
    startTransition(() => {               // NON-URGENT: can be interrupted
      setResults(allItems.filter((i) => i.includes(next)));
    });
  }

  return (
    <>
      <input value={query} onChange={handleChange} />
      {isPending && <span>Filtering…</span>}
      <List items={results} />
    </>
  );
}
startTransition marks an update as low-priority. React keeps the input responsive (urgent) and renders the expensive list in the background, interrupting it if you keep typing. isPending lets you show a subtle "updating" indicator. The keystrokes never feel blocked, even with a massive list.

3. useDeferredValue

useDeferredValue.tsxtsx 
import { useState, useDeferredValue, useMemo } from "react";

function Search({ allItems }: { allItems: string[] }) {
  const [query, setQuery] = useState("");
  const deferredQuery = useDeferredValue(query); // "lags behind" during fast typing

  // Expensive work keyed off the DEFERRED value, so typing stays snappy:
  const results = useMemo(
    () => allItems.filter((i) => i.includes(deferredQuery)),
    [allItems, deferredQuery]
  );

  return (
    <>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />
      <List items={results} />
    </>
  );
}
useDeferredValue is the value-based sibling of useTransition. Instead of wrapping a state update, you defer a value: the input uses query (live), while the expensive list uses deferredQuery (which trails during rapid input). Use it when you receive a value (e.g. a prop) you can't wrap in a transition.
✨
2026 · It also powers Suspense transitions

Wrapping a navigation in startTransition lets React keep showing the old screen (instead of a Suspense fallback) while the next one loads — no jarring flash of a spinner. Routers (Part 6) and Server Components (Part 7) use transitions to make navigation feel instant.

Render a list of 20,000 items and a search box. First implement it naively and feel the lag. Then fix it two ways — once with useTransition, once with useDeferredValue — and compare. Show an isPending indicator in the transition version.

🎓 Key takeaways

  • Concurrent React can interrupt and prioritise renders so urgent updates aren't blocked.
  • useTransition marks a state update as low-priority and gives you isPending.
  • useDeferredValue defers a value for expensive downstream work, keeping input snappy.
  • Transitions also avoid jarring Suspense fallbacks during navigation.
  • Reach for these when an expensive render makes urgent interactions (typing, clicking) feel laggy.
