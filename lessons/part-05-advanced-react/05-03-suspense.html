Suspense & Data Fetching Patterns

🚀 Advanced ⏱️ ~30 min ⏳ Declarative loading

Suspense lets you declare loading UI declaratively: wrap part of your tree in a boundary, and React shows a fallback while anything inside is "suspending" (waiting on data or code). It replaces scattered isLoading flags with a clean, composable pattern, and it's the foundation for code splitting, the use() hook, and Server Components (Part 7).

1. The Suspense boundary

suspense.tsxtsx 
import { Suspense } from "react";

function App() {
  return (
    <Suspense fallback={<Spinner />}>
      <Profile />        {/* if Profile suspends, the Spinner shows */}
      <Timeline />       {/* both must be ready before the boundary reveals */}
    </Suspense>
  );
}

// Boundaries compose and nest — granular loading states:
function Page() {
  return (
    <Suspense fallback={<PageSkeleton />}>
      <Header />
      <Suspense fallback={<FeedSkeleton />}>
        <Feed />        {/* its own independent loading region */}
      </Suspense>
    </Suspense>
  );
}
Suspense moves loading state out of components and into the tree. A component "suspends" by throwing a promise (libraries and use() do this for you); the nearest <Suspense> ancestor catches it and shows the fallback until it resolves. Nest boundaries for granular skeletons — the header can show while the feed still loads.

2. Suspense with the use() hook

use-suspense.tsxtsx 
import { use, Suspense } from "react";

function Comments({ commentsPromise }: { commentsPromise: Promise<string[]> }) {
  const comments = use(commentsPromise); // suspends until resolved (04-12)
  return <ul>{comments.map((c, i) => <li key={i}>{c}</li>)}</ul>;
}

function Post({ commentsPromise }: { commentsPromise: Promise<string[]> }) {
  return (
    <article>
      <h2>My Post</h2>
      <Suspense fallback={<p>Loading comments…</p>}>
        <Comments commentsPromise={commentsPromise} />
      </Suspense>
    </article>
  );
}
// The post renders instantly; comments stream in when ready.
use(promise) + Suspense is the modern data pattern. The component reads the promise's value directly (no useState/useEffect loading dance), and Suspense handles the pending UI. Pair it with an Error Boundary (next lesson) for failures. In practice, TanStack Query (Part 6) and Server Components (Part 7) provide the promises and caching.

3. The patterns that matter

  • Render-as-you-fetch: start fetching before/while rendering (not in an effect after), so data and UI load in parallel. Suspense reveals content as it arrives.
  • Streaming: with Server Components, the server sends HTML progressively, filling Suspense fallbacks as data resolves — fast first paint, no waterfall.
  • Avoid waterfalls: sequential awaits (or effect-triggered fetches) make requests wait on each other. Kick off independent requests together (lesson 00-11's Promise.all).

Exercise · Granular skeletons

Build a profile page with two independent data sources (user + posts), each read with use() inside its own nested <Suspense>. Give each a distinct skeleton. Confirm the user section appears before the slower posts section, rather than the whole page waiting.

🎓 Key takeaways

  • Suspense declares loading UI in the tree: a boundary shows a fallback while descendants suspend.
  • Boundaries nest for granular, independent loading regions.
  • use(promise) + Suspense is the modern fetch pattern — no manual loading state.
  • Prefer render-as-you-fetch and avoid request waterfalls.
  • TanStack Query (Part 6) and Server Components (Part 7) build on this foundation.
