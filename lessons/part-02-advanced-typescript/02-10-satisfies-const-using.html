satisfies, const Type Params & using

🧠 Advanced · modern ⏱️ ~32 min ✨ TS 5.x features

The newest tools in the language, from TypeScript 5.0 through 5.9. satisfies validates without widening, const type parameters preserve literal types through functions, and using (explicit resource management) brings deterministic cleanup to JavaScript. These are the features that mark code as current in 2026.

1. satisfies — validate without widening

satisfies.tstypescript 
type Config = Record<string, string | number>;

// ❌ Annotation widens — you lose the specific keys/value types:
const a: Config = { host: "localhost", port: 8080 };
a.host.toUpperCase(); // ERROR: host is string | number, not string

// ✅ `satisfies` CHECKS against Config but KEEPS the precise inferred type:
const b = { host: "localhost", port: 8080 } satisfies Config;
b.host.toUpperCase(); // ✅ host is string
b.port.toFixed(0);    // ✅ port is number
// b.missing;         // ✅ still errors — unknown key caught

// The classic use: a typed palette that keeps literal keys for autocomplete.
const palette = {
  primary: "#2563eb",
  danger: "#b42318",
} satisfies Record<string, `#${string}`>;
type ColorName = keyof typeof palette; // "primary" | "danger" (not string!)
The best of both worlds: satisfies verifies your value matches a type without replacing the precise inferred type with the broader one. You get the constraint check AND keep literal keys/values for autocomplete and narrowing. Use it for config objects, route maps, and design tokens. This is one of the most-loved modern features.

2. const type parameters

const-params.tstypescript 
// Without `const`: literals widen when captured by a generic.
function loose<T>(value: T): T { return value; }
const x = loose(["a", "b"]); // string[]  (widened)

// With a `const` type parameter: literals are preserved, as if `as const`.
function exact<const T>(value: T): T { return value; }
const y = exact(["a", "b"]); // readonly ["a", "b"]  (narrow!)

// Real use — a router/builder that keeps your literal paths:
function defineRoutes<const T extends readonly string[]>(routes: T): T {
  return routes;
}
const routes = defineRoutes(["/home", "/about"]);
type Route = (typeof routes)[number]; // "/home" | "/about"
// The CALLER didn't need `as const` — the library demanded narrowness for them.
This is what made your P02 v.literal() infer "admin" not string. A const type parameter tells the compiler "infer the narrowest literal type here", sparing your users from sprinkling as const at every call site. It's how modern libraries deliver precise inference ergonomically.

3. using — explicit resource management

using.tstypescript 
// A resource that knows how to clean itself up via Symbol.dispose:
function openConnection(name: string) {
  console.log(`open ${name}`);
  return {
    query: (sql: string) => console.log(`query: ${sql}`),
    [Symbol.dispose]() { console.log(`close ${name}`); },
  };
}

function run() {
  using db = openConnection("primary"); // disposed automatically...
  db.query("SELECT 1");
} // ...HERE, at end of scope — even if an error was thrown. No try/finally!

run();
// open primary / query: SELECT 1 / close primary

// `await using` does the same for async cleanup (Symbol.asyncDispose).
using brings deterministic cleanup to JavaScript (like C#'s using or Python's with). When the variable goes out of scope, its [Symbol.dispose]() runs automatically — guaranteeing files, connections, locks, and subscriptions are released even on errors. It replaces error-prone try/finally ladders. Shipped in TS 5.2 and standardized in ECMAScript.

  • using/await using give deterministic, error-safe cleanup via Symbol.dispose.
  • These power ergonomic library APIs — exactly what made your P02 validator's literals narrow.
