Recursive Types & Type-Level Programming

🧠 Expert ⏱️ ~40 min 🌀 Turing-complete types

TypeScript's type system is Turing-complete — a programming language in its own right. With recursion, you can model self-similar data (JSON, trees), and even perform computation on tuples as if they were lists. This is the deepest end of the pool. You won't write this every day, but understanding it gives you total command of types — and explains how the most magical libraries work.

1. Recursive data types

recursive-data.tstypescript 
// Model JSON precisely — a type that references itself:
type Json =
  | string
  | number
  | boolean
  | null
  | Json[]
  | { [key: string]: Json };

const data: Json = {
  name: "Ada",
  scores: [10, 20, { bonus: true }],
  meta: null,
};
// const bad: Json = { fn: () => {} }; // ❌ functions aren't valid JSON

// A tree structure:
interface TreeNode<T> {
  value: T;
  children: TreeNode<T>[];
}
Self-referential types model self-similar data. The Json type is the correct type for anything that came from JSON.parse — far better than any. Recursive interfaces model trees, file systems, comment threads, and org charts.

2. Type-level recursion = computation

tuple-recursion.tstypescript 
// Reverse a tuple by recursively peeling off the head:
type Reverse<T extends unknown[]> =
  T extends [infer Head, ...infer Tail] ? [...Reverse<Tail>, Head] : [];
type R = Reverse<[1, 2, 3]>; // [3, 2, 1]

// Compute a tuple's length as a literal number:
type Length<T extends readonly unknown[]> = T["length"];
type L = Length<["a", "b", "c"]>; // 3

// Build a tuple of N elements (type-level counting):
type BuildTuple<N extends number, Acc extends unknown[] = []> =
  Acc["length"] extends N ? Acc : BuildTuple<N, [...Acc, unknown]>;
type Five = BuildTuple<5>["length"]; // 5

// ...which enables type-level ADDITION:
type Add<A extends number, B extends number> =
  [...BuildTuple<A>, ...BuildTuple<B>]["length"];
type Sum = Add<3, 4>; // 7  — arithmetic, in the type system!
Yes, that's addition performed by the type checker. Recursion + variadic tuples (next lesson) turn tuples into lists you can compute on. You'll rarely do type-level math in app code, but this is the engine behind libraries that, say, type a chunk(arr, 3) function's exact output shape. It proves the type system is a real programming language.

3. Practical recursion: Paths of an object

object-paths.tstypescript 
// Generate all dot-paths into a nested object — used by form libraries,
// i18n, and config tools to give you autocompleted, type-checked key paths.
type Paths<T> = T extends object
  ? {
      [K in keyof T & string]: T[K] extends object
        ? `${K}` | `${K}.${Paths<T[K]>}`
        : `${K}`;
    }[keyof T & string]
  : never;

interface Config {
  server: { host: string; port: number };
  features: { auth: { enabled: boolean } };
}
type ConfigPath = Paths<Config>;
// "server" | "server.host" | "server.port"
//   | "features" | "features.auth" | "features.auth.enabled"
This is a real, valuable utility. React Hook Form uses paths exactly like this so setValue("features.auth.enabled", true) is autocompleted and type-checked. Combining recursion, mapped types, template literals, and indexed access, you generate every valid nested key path automatically. That's the full Part 2 toolkit firing at once.
⚠️
Gotcha · The recursion depth limit

TypeScript caps recursive instantiation (historically ~50, deeper for tail-recursive types using the ...rest accumulator pattern). Very deep or unbounded recursion produces "Type instantiation is excessively deep". Design with an accumulator and a base case, and keep depth bounded. Power with limits.

🎓 Key takeaways

  • Recursive data types model JSON, trees, and other self-similar structures precisely.
  • TypeScript's types are Turing-complete: recursion + tuples enable real computation (even arithmetic).
  • The [infer Head, ...infer Tail] pattern walks tuples like a list.
  • Object paths (recursion + templates + mapped types) power typed form/config/i18n keys.
  • Mind the recursion depth limit — use accumulators and base cases, keep it bounded.
