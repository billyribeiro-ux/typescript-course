The Utility Type Catalog

🧠 Advanced ⏱️ ~34 min 🧰 The standard library

TypeScript ships a toolbox of built-in utility types — pre-made transformations you'll use every single day. Having just learned how mapped and conditional types work, you'll understand each one from the inside rather than memorising magic. This lesson is your reference; bookmark it.

1. Object-shaping utilities

object-utils.tstypescript 
interface User {
  id: number;
  name: string;
  email: string;
  password: string;
}

type T1 = Partial<User>;            // all keys optional
type T2 = Required<Partial<User>>;  // all keys required again
type T3 = Readonly<User>;           // all keys readonly

// Pick a subset of keys:
type PublicUser = Pick<User, "id" | "name" | "email">;
// Omit (remove) keys — perfect for stripping sensitive fields:
type SafeUser = Omit<User, "password">;  // { id; name; email }

// Record builds a key→value map:
type RolePermissions = Record<"admin" | "user", string[]>;
const perms: RolePermissions = { admin: ["*"], user: ["read"] };
The four you'll use most: Partial (forms/patches), Pick and Omit (deriving DTOs from entities), and Record (lookup maps). Omit<User, "password"> is the canonical "never leak the password field" pattern.

2. Union-filtering utilities

union-utils.tstypescript 
type Status = "idle" | "loading" | "success" | "error";

// Exclude removes union members (uses conditional distribution, 02-01):
type Settled = Exclude<Status, "idle" | "loading">; // "success" | "error"
// Extract keeps only matching members:
type Pending = Extract<Status, "idle" | "loading">; // "idle" | "loading"

// NonNullable strips null and undefined:
type T = NonNullable<string | null | undefined>; // string

// Combine with keyof for "keys whose value is a function":
type Handlers = Record<string, unknown> & { onClick: () => void; id: number };
type FnKeys = {
  [K in keyof Handlers]: Handlers[K] extends Function ? K : never;
}[keyof Handlers];
Exclude/Extract/NonNullable operate on unions via the distribution rule from 02-01. NonNullable is especially handy after a filter or guard. They look trivial now — because you understand the conditional-type machine underneath.

3. Function-related utilities

fn-utils.tstypescript 
function createUser(name: string, age: number) {
  return { id: 1, name, age, createdAt: new Date() };
}

type Args = Parameters<typeof createUser>;     // [name: string, age: number]
type Result = ReturnType<typeof createUser>;   // { id; name; age; createdAt }
type FirstArg = Parameters<typeof createUser>[0]; // string

async function loadData() { return { ok: true }; }
type Data = Awaited<ReturnType<typeof loadData>>; // { ok: boolean }

// InstanceType — the instance shape of a class constructor:
class Service { run() {} }
type S = InstanceType<typeof Service>; // Service

// These let you derive types FROM implementations — single source of truth.
The "derive from implementation" superpower: rather than writing a type and a function separately (and letting them drift), you write the function and extract types from it with Parameters, ReturnType, and Awaited. This is how you keep types and code in lockstep — a core L7++ habit.

Pro-tip · Compose them

The real power is composition: Readonly<Pick<User, "id" | "name">>, Partial<Omit<Post, "id">>, Record<Status, ReturnType<typeof reducer>>. Chaining utilities expresses precise intent without writing a single new mapped type.

Exercise · DTOs from one entity

Given interface Article { id: number; title: string; body: string; authorId: number; secret: string }, derive: CreateArticle (everything except id and secret, all required), UpdateArticle (same fields but all optional), and PublicArticle (no secret). Use only built-in utilities composed together.

🎓 Key takeaways

  • Object utilities: Partial, Required, Readonly, Pick, Omit, Record.
  • Union utilities: Exclude, Extract, NonNullable (built on conditional distribution).
  • Function utilities: Parameters, ReturnType, Awaited, InstanceType (built on infer).
  • Derive types from implementations to keep them in sync — a key habit.
  • Compose utilities to express precise DTOs without new mapped types.
