Decorators, Module Augmentation & Ambient Types

🧠 Advanced ⏱️ ~34 min 🔌 Extending the world

The final core skills of advanced TypeScript: standard decorators (TS 5.0+, now an ECMAScript feature) for declarative metaprogramming, and module augmentation + ambient declarations for safely extending types you don't own — third-party libraries, globals, and the environment. These are what let you integrate cleanly with any codebase.

1. Standard decorators

decorators.tstypescript 
// A method decorator that logs calls. The 2023 standard signature:
//   (originalMethod, context) => replacementMethod
function logged<This, Args extends unknown[], Return>(
  target: (this: This, ...args: Args) => Return,
  context: ClassMethodDecoratorContext<This>
) {
  const name = String(context.name);
  return function (this: This, ...args: Args): Return {
    console.log(`→ ${name}(${args.join(", ")})`);
    const result = target.call(this, ...args);
    console.log(`← ${name} returned ${result}`);
    return result;
  };
}

class Calculator {
  @logged
  add(a: number, b: number): number {
    return a + b;
  }
}
new Calculator().add(2, 3);
// → add(2, 3) / ← add returned 5
The modern decorator receives the thing it decorates plus a typed context object (its name, kind, and helpers) and returns a replacement. Unlike the old experimental decorators, these are the standardized ECMAScript form — no reflect-metadata, no experimentalDecorators flag. Frameworks like NestJS and some ORMs use them heavily for declarative routing, validation, and DI.

2. Module augmentation

augmentation.tstypescript 
// Add a property to an existing third-party module's interface.
// (This is how you tell TS about a plugin that mutates a library's types.)
import "some-router";

declare module "some-router" {
  interface RouteMeta {
    requiresAuth?: boolean;   // a field we add for our app
    roles?: string[];
  }
}

// Now, everywhere RouteMeta is used, our fields are typed too.

// Augment the GLOBAL scope (e.g. a value you attach to window):
declare global {
  interface Window {
    __APP_VERSION__: string;
  }
}
window.__APP_VERSION__ = "1.0.0"; // ✅ typed
export {}; // ensures this file is a module
Module augmentation uses interface declaration merging (from lesson 01-04) to extend types you don't own — without forking the library. This is how you add requiresAuth to a router's route metadata, register a Redux store's type, or teach TypeScript about import.meta.env variables. Indispensable for real integration work.

3. Ambient declarations & typed env

ambient.tstypescript 
// Declare things that exist at runtime but TS doesn't know about.

// A non-code import (handled by a bundler like Vite):
declare module "*.svg" {
  const src: string;
  export default src;
}

// Type your environment variables strictly (huge for safety):
declare namespace NodeJS {
  interface ProcessEnv {
    readonly DATABASE_URL: string;
    readonly NODE_ENV: "development" | "production" | "test";
  }
}
// Now process.env.NODE_ENV is the union, and typos are caught:
const env = process.env.NODE_ENV; // "development" | "production" | "test"
Ambient declarations describe the runtime to the compiler. Typing process.env (or Vite's import.meta.env) means a misspelled env var is a compile error, and values carry their real union types. Declaring *.svg modules lets you import assets with types. This is foundational setup in every production app you'll build from Part 3 on.
⚠️
Gotcha · Augmentation must target a module

declare global and declare module only work inside a file that is itself a module (has an import or export). If TypeScript treats your file as a global script, add export {} to make it a module — otherwise the augmentation silently does nothing.

🎓 Key takeaways

  • Standard decorators (TS 5.0+, ECMAScript) take (target, context) and return a replacement — declarative metaprogramming with no special flags.
  • Module augmentation (declare module) extends third-party types via declaration merging — no forking.
  • Ambient declarations (declare global/namespace/module "*.x") describe runtime things to the compiler.
  • Strictly typing process.env/import.meta.env turns env typos into compile errors.
  • Augmentations require the file to be a module — add export {} if needed.
