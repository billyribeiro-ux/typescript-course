Variadic Tuples & Function Composition

🧠 Expert ⏱️ ~34 min 🧮 Typing the untypeable

Variadic tuple types let you spread and manipulate tuples in type positions — the feature that finally made it possible to fully type notoriously hard functions like compose, curry, and bind. This is how libraries give you perfect inference through chains of operations. It's the engine behind type-safe pipelines.

1. Spreading tuples in type positions

variadic.tstypescript 
// A tuple spread (...) inside another tuple type:
type Pair = [string, number];
type Triple = [...Pair, boolean]; // [string, number, boolean]

// Generic head/tail manipulation:
type Push<T extends unknown[], V> = [...T, V];
type Unshift<T extends unknown[], V> = [V, ...T];
type Concat<A extends unknown[], B extends unknown[]> = [...A, ...B];

type P = Push<[1, 2], 3>;        // [1, 2, 3]
type C = Concat<[1, 2], [3, 4]>; // [1, 2, 3, 4]

// Extract head and tail with infer + spread:
type Head<T extends unknown[]> = T extends [infer H, ...unknown[]] ? H : never;
type Tail<T extends unknown[]> = T extends [unknown, ...infer R] ? R : [];
type H = Head<[1, 2, 3]>; // 1
type R = Tail<[1, 2, 3]>; // [2, 3]
Tuples become first-class lists you can compute on. The [...T, V] and [infer H, ...infer T] patterns are the primitives. They power the recursive type-level algorithms from lesson 02-06 and the function typing below.

2. Typing function arguments precisely

args.tstypescript 
// Type a function that takes the SAME args as another, plus a leading one.
// This is exactly how a typed "withLogging" wrapper or DI container works.
function wrap<Args extends unknown[], R>(
  fn: (...args: Args) => R
): (label: string, ...args: Args) => R {
  return (label, ...args) => {
    console.log(`calling ${label}`);
    return fn(...args);
  };
}

const add = (a: number, b: number) => a + b;
const loggedAdd = wrap(add);
loggedAdd("sum", 2, 3); // ✅ args after label are typed as (number, number)
// loggedAdd("sum", 2, "x"); // ❌ second arg must be a number

// Tuples with labels read nicely in tooltips:
type Range = [start: number, end: number];
Capturing a function's argument list as a tuple Args and re-spreading it is how you write perfectly-typed higher-order functions — wrappers, decorators, middleware, currying. Before variadic tuples, these required dozens of hand-written overloads.

3. Fully-typed compose & pipe

pipe.tstypescript 
// A type-safe `pipe`: each function's output must match the next's input,
// and the final return type is inferred. (Simplified 2-3 step version.)
function pipe<A, B>(a: A, ab: (a: A) => B): B;
function pipe<A, B, C>(a: A, ab: (a: A) => B, bc: (b: B) => C): C;
function pipe<A, B, C, D>(a: A, ab: (a: A) => B, bc: (b: B) => C, cd: (c: C) => D): D;
function pipe(value: unknown, ...fns: Array<(x: unknown) => unknown>): unknown {
  return fns.reduce((acc, fn) => fn(acc), value);
}

const result = pipe(
  "  Hello World  ",
  (s) => s.trim(),          // string => string
  (s) => s.toLowerCase(),   // string => string
  (s) => s.split(" ")       // string => string[]
);
// result is typed as string[]  — each step's type flows to the next.
This is the holy grail of functional typing. Each step's output type must be assignable to the next step's input, and the final type is inferred end-to-end. Libraries like Effect, fp-ts, and Remeda use advanced variadic-tuple machinery to type pipe for any number of steps. You're seeing the technique that makes type-safe data pipelines possible.

🎓 Key takeaways

  • Variadic tuples allow [...T, V] spreads and [infer H, ...infer T] destructuring in type positions.
  • They let you capture and re-spread a function's argument list as a tuple Args.
  • This is how perfectly-typed higher-order functions (wrappers, middleware, currying) are written.
  • Fully-typed pipe/compose chains flow each step's output type into the next.
  • The same primitives drive the recursive type-level algorithms of lesson 02-06.
