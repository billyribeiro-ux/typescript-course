Template Literal Types

🧠 Advanced ⏱️ ~36 min 🔤 String types as data

Template literal types let you compute string types the way template literals compute string values. You can concatenate, pattern-match, and even parse strings entirely at the type level. This unlocks astonishing things: type-safe routes, event names, CSS units, and APIs that validate string formats before your code runs.

1. Building string types

building.tstypescript 
type World = "world";
type Greeting = `hello ${World}`; // "hello world"

// Cross-multiply unions — every combination is generated:
type Color = "red" | "blue";
type Shade = "light" | "dark";
type Swatch = `${Shade}-${Color}`;
// "light-red" | "light-blue" | "dark-red" | "dark-blue"

// Type-safe CSS-ish values:
type Px = `${number}px`;
const margin: Px = "16px";  // ✅
// const bad: Px = "16em";  // ❌ not assignable

// Built-in intrinsic string manipulators:
type A = Uppercase<"hello">;     // "HELLO"
type B = Capitalize<"hello">;    // "Hello"
type C = Lowercase<"HELLO">;     // "hello"
type D = Uncapitalize<"Hello">;  // "hello"
Unions multiply. When you interpolate a union into a template literal type, TypeScript generates every combination. This is how a handful of literals can describe a precise, finite set of valid strings — and why you get autocomplete for things like "dark-blue".

2. Pattern matching strings with infer

Combine template literals with infer and you can parse strings at the type level — extracting parts of a structured string into types.

parsing.tstypescript 
// Extract the part after a prefix:
type RemovePrefix<S, P extends string> =
  S extends `${P}${infer Rest}` ? Rest : S;
type Event = RemovePrefix<"on:click", "on:">; // "click"

// Split a string on a delimiter into a tuple (recursive — lesson 02-06):
type Split<S extends string, D extends string> =
  S extends `${infer Head}${D}${infer Tail}`
    ? [Head, ...Split<Tail, D>]
    : [S];
type Parts = Split<"a.b.c", ".">; // ["a", "b", "c"]

// Parse a route's params into a typed object:
type Params<Path extends string> =
  Path extends `${infer _Start}:${infer Param}/${infer Rest}`
    ? { [K in Param | keyof Params<`/${Rest}`>]: string }
    : Path extends `${infer _Start}:${infer Param}`
    ? { [K in Param]: string }
    : {};
type RouteParams = Params<"/users/:userId/posts/:postId">;
// { userId: string; postId: string }
This is genuinely advanced — and genuinely used. Type-safe routers (TanStack Router, and patterns in Next.js typed routes) parse your path strings exactly like this to give you a typed params object with autocomplete and no manual types. You write "/users/:userId" and the framework knows there's a userId: string param.

3. Key remapping × template literals

event-map.tstypescript 
// A type-safe event emitter signature, generated from an events map.
type Events = {
  click: { x: number; y: number };
  focus: { id: string };
};

type Listeners<E> = {
  [K in keyof E as `on${Capitalize<string & K>}`]: (payload: E[K]) => void;
};
type AppListeners = Listeners<Events>;
// { onClick: (p: { x: number; y: number }) => void;
//   onFocus: (p: { id: string }) => void }

// This is essentially how typed component props for events are derived.
Combining the last three lessons: a mapped type (02-02) renames keys via the as clause using a template literal (02-03) and Capitalize. From a small events object you generate a fully-typed listener interface. This compositional power is what "5× beyond the basics" looks like.
⚠️
Gotcha · Combinatorial explosion

Template literals over large unions multiply: two 100-member unions produce a 10,000-member type and can slow the compiler to a crawl or hit its limit. Use them on small, bounded unions. Power tools demand respect — measure compile time on big ones.

🎓 Key takeaways

  • Template literal types compute string types; interpolating unions generates every combination.
  • Built-ins Uppercase/Capitalize/Lowercase/Uncapitalize transform string types.
  • With infer, you can parse strings at the type level — the basis of type-safe routers.
  • Combined with key remapping, you generate whole interfaces (event listeners, getters/setters) from data.
  • Beware combinatorial blow-up on large unions — keep them bounded.
