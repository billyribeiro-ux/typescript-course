Mapped Types & Key Remapping

🧠 Advanced ⏱️ ~38 min 🗺️ Transforming shapes

If conditional types are the if of type-level programming, mapped types are the for loop — they iterate over the keys of a type and build a new type. Add key remapping (the as clause) and you can rename, filter, and reshape keys at will. This is how Partial, Readonly, and P02's optional-key splitting actually work.

1. The mapped type loop

mapped.tstypescript 
type User = { id: number; name: string; age: number };

// "For each key K in User, keep it, but make its value type the same":
type Clone<T> = { [K in keyof T]: T[K] };
type C = Clone<User>; // identical to User

// Transform every value to boolean (e.g. a "which fields changed?" map):
type Flags<T> = { [K in keyof T]: boolean };
type UserFlags = Flags<User>; // { id: boolean; name: boolean; age: boolean }

// keyof gets the union of keys; T[K] is the value type at key K.
type UserKeys = keyof User;     // "id" | "name" | "age"
type AgeType = User["age"];     // number
Read { [K in keyof T]: ... } as a loop: "for each key K in the union keyof T, produce a property whose value type is the right-hand side." Inside, T[K] is the original value type. Everything else in this lesson is variations on this one construct.

2. Modifiers: adding and removing ? and readonly

modifiers.tstypescript 
type User = { id: number; name: string };

// Add modifiers — these ARE the built-in Partial and Readonly:
type MyPartial<T>  = { [K in keyof T]?: T[K] };           // all optional
type MyReadonly<T> = { readonly [K in keyof T]: T[K] };   // all readonly

// REMOVE modifiers with the "-" prefix (the built-in Required):
type MyRequired<T> = { [K in keyof T]-?: T[K] };          // strip optionality
type Mutable<T>    = { -readonly [K in keyof T]: T[K] };  // strip readonly

type P = MyPartial<User>;   // { id?: number; name?: string }
type M = Mutable<{ readonly id: number }>; // { id: number }
The +/- modifier prefixes add or remove ? and readonly during the mapping. -? makes optional properties required; -readonly makes them mutable. The standard library's Partial, Required, and Readonly are literally these one-liners. You now understand them from the inside.

3. Key remapping with as

The as clause lets you rename or filter keys as you map. Combined with template literal types (next lesson) and never (to drop keys), this is breathtakingly expressive.

remapping.tstypescript 
type User = { id: number; name: string; age: number };

// Rename keys: generate getter method names with a template literal.
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};
type UserGetters = Getters<User>;
// { getId: () => number; getName: () => string; getAge: () => number }

// FILTER keys: map a key to `never` to drop it. Keep only string-valued props:
type StringProps<T> = {
  [K in keyof T as T[K] extends string ? K : never]: T[K];
};
type S = StringProps<User>; // { name: string }  (id and age dropped)
This is the exact technique P02 uses. Remember InferObject splitting required vs optional keys? It maps the keys, using as ... ? K : never to route each key into the "required" group or the "optional" group. Mapping a key to never removes it entirely — your tool for filtering object types.

4. Real-world mapped utilities

utilities.tstypescript 
// Deep readonly — recurse into nested objects (uses recursion, lesson 02-06):
type DeepReadonly<T> = {
  readonly [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K];
};
type Config = DeepReadonly<{ server: { port: number }; debug: boolean }>;
// every level is readonly

// Pick only the function-valued properties of a type:
type Methods<T> = {
  [K in keyof T as T[K] extends (...args: any[]) => any ? K : never]: T[K];
};

// Make specific keys optional (a genuinely useful custom utility):
type PartialBy<T, K extends keyof T> = Omit<T, K> & Partial<Pick<T, K>>;
type Draft = PartialBy<{ id: number; title: string; body: string }, "id">;
// { title: string; body: string; id?: number }
These are production-grade utilities. PartialBy in particular — "make just these keys optional" — is something you'll reach for constantly (e.g. a create-form type where the server assigns the id). Notice how mapped types compose with Omit, Pick, and Partial (the utility catalog, lesson 02-04).
✨
Pattern · The "stamp" over a literal union

You can map over any union of keys, not just keyof T: type Routes = { [K in "home" | "about"]: `/${K}` } → { home: "/home"; about: "/about" }. Mapping over string-literal unions is how type-safe routers and event systems generate their types.

🎓 Key takeaways

  • Mapped types { [K in keyof T]: ... } iterate keys to build a new type — the type-level for loop.
  • Modifiers ?/readonly can be added or removed with +/- — the basis of Partial/Required/Readonly.
  • Key remapping (as) renames keys (with template literals) or filters them (map to never to drop).
  • This is exactly how P02 splits required vs optional object keys.
  • Compose with Pick/Omit/Partial to build utilities like PartialBy.
