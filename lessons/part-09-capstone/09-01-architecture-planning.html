ProjectHub: Architecture & Planning

🎓 Capstone ⏱️ ~40 min 🏗️ Plan before you build

This is it — the graduation project. ProjectHub is a production-grade, multi-tenant team-collaboration SaaS (think a focused Linear/Asana). Over the next six lessons we architect and build it end-to-end, weaving together everything from the entire course. We start the way a principal engineer always does: not with code, but with a plan.

1. What we're building

ProjectHub lets organizations manage projects and tasks with their team: create an org, invite members with roles, organize work on boards, collaborate in real time, and manage billing. The features deliberately exercise the whole curriculum.

2. The architecture

monorepo layouttext 
projecthub/                  # pnpm + Turborepo monorepo (Part 3)
  apps/
    web/                     # Next.js 15 App Router (Part 7)
  packages/
    ui/                      # the design system (P08 + shadcn)
    db/                      # Drizzle schema + queries (07-06)
    api/                     # tRPC routers + Zod inputs (07-07, P02)
    auth/                    # session + RBAC core (P05/P07, 07-08)
    config/                  # shared tsconfig, eslint, env schema (07-10)
// Clear module boundaries (08-01): each package has one responsibility,
// the app composes them. Pure logic in packages, framework glue in app/web.
The structure embodies the course's principles. A Turborepo monorepo (Part 3) with a design-system package (P08), a typed data layer (Drizzle), a typed API (tRPC), and an auth/RBAC core (P05/P07). Each package has a single responsibility (08-01); the Next.js app composes them. Pure, testable logic lives in packages; thin framework glue lives in the app.

3. The plan (an RFC in miniature)

  • Requirements: multi-tenant (org isolation), real-time, role-based access, billed by seat, accessible, fast (Core Web Vitals).
  • Data model: orgs → members (with roles) → projects → tasks; plus sessions and subscriptions.
  • Rendering: Server Components for initial loads (07-02), client islands for interactivity, streaming for the dashboard (07-03).
  • State: server state via tRPC + TanStack Query; local board UI via Zustand (P04 patterns); forms via RHF + Zod (06-09).
  • Non-functionals: tests at every layer, CI gate, observability, performance budget.
