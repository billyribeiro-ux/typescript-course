The Application Core & Design System

🎓 Capstone ⏱️ ~55 min 🎨 Build the product

With data and auth in place, we build the product itself: the typed API layer, the UI built on our design system, and the project boards. This is where every front-end skill from the course comes together into a polished, real application.

1. The typed API (tRPC + Zod)

packages/api/routers/project.tstypescript 
export const projectRouter = router({
  list: protectedProcedure.query(({ ctx }) =>
    db.select().from(projects).where(eq(projects.orgId, ctx.member.orgId))), // scoped

  create: protectedProcedure
    .input(z.object({ name: z.string().min(1).max(80) }))     // Zod validation (P02)
    .mutation(({ ctx, input }) => {
      authorize(ctx.member.role, "project:create");            // RBAC (P05/P07)
      return db.insert(projects)
        .values({ name: input.name, orgId: ctx.member.orgId }) // org-scoped insert
        .returning();
    }),
});
Each procedure is auth-gated, validated, authorized, and org-scoped — the four guarantees from Project P07, now backed by a real database. The client gets these procedures fully typed with zero codegen (07-07), built on TanStack Query for caching. This is end-to-end type safety from the database to the button.

2. The UI on the design system

apps/web/app/projects/page.tsxtsx 
import { Button, Card } from "@projecthub/ui";  // the design system (P08 + shadcn)

// Server Component: fetch on the server, render fast (07-02)
export default async function ProjectsPage() {
  const projects = await api.project.list();    // tRPC server caller
  return (
    <main>
      <div className="flex items-center justify-between">
        <h1 className="text-2xl font-bold">Projects</h1>
        <NewProjectButton />                     {/* client island */}
      </div>
      <div className="grid gap-4 md:grid-cols-3">
        {projects.map((p) => (
          <Card key={p.id}><h2>{p.name}</h2></Card>   {/* design-system component */}
        ))}
      </div>
    </main>
  );
}
Server shell + client islands + design system. The page is a Server Component (07-02) that fetches via tRPC and renders our @projecthub/ui components (P08 + shadcn, Tailwind 06-10). Interactive bits like NewProjectButton are small client islands using useMutation + a RHF/Zod dialog (06-09). Consistent, accessible, fast.

3. The task board

Each project has a board — and we already built this in Project P04! The Kanban store (Zustand, normalized state, immutable moves) drops straight in, now backed by tRPC mutations for persistence and Motion (06-11) for card animations. The local board state is client state (Zustand); the tasks themselves are server state (TanStack Query via tRPC). We reuse, not reinvent.

⚡
Pro-tip · The capstone is composition, not novelty

Notice you're not learning new concepts here — you're composing P02 (validation), P04 (boards), P05/P07 (RBAC/API), P08 (design system), and Part 7 (Next.js). That's the lesson: a large app is well-understood pieces, assembled with judgement. You already know how to build every piece.

Exercise · Build a feature end-to-end

Implement "create task": a tRPC task.create procedure (auth + Zod + RBAC + org-scoped insert), a design-system dialog with a RHF/Zod form (06-09), a useMutation with optimistic update + cache invalidation (06-04), and the new task appearing on the board. One vertical slice touching every layer.

🎓 Key takeaways

  • The typed API (tRPC + Zod + Drizzle) gives each procedure auth + validation + RBAC + org-scoping.
  • UI = Server Component shells + client islands, built on the design system (P08/shadcn/Tailwind).
  • The task board reuses Project P04 (Zustand) — client board state + server task state.
  • A feature is a vertical slice through every layer: schema → procedure → hook → component.
  • The capstone is composition of known pieces, not new concepts.
